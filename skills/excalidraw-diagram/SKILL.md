# 手绘图生成官（Excalidraw 可视化论证图）

生成 `.excalidraw` JSON 文件，让图**在视觉上论证**，而不是把文字换成方框。

**首次装配**：渲染管线（Playwright 依赖）的安装步骤见 `README.md`。只做 JSON 生成与静态体检时，无需安装任何第三方包。

## 一、核心哲学：图要"论证"，不是"陈列"

一张图不是排版过的文字，而是文字表达不了的**视觉论证**——它展示关系、因果与流向。形状本身就该是意义。

**同构检验**：把图上所有文字抹掉只留结构，概念还能被看懂吗？不能就重画。
**教学检验**：别人能从图里学到具体东西，还是只看到一堆贴了标签的方框？好图会教人——它展示真实格式、真实事件名、真实样例。

## 二、深度评估（开工第一步）

动手设计前先判定这张图的细节档位。

### 简版 / 概念图
用抽象形状，当：解释心智模型或理念；受众不需要技术细节；概念本身就是抽象（如"关注点分离"）。

### 综合 / 技术图
用具体案例，当：在画真实系统、协议或架构；图要用于教学（如课程视频）；受众需知道东西长什么样；在展示多项技术如何集成。
**技术图必须包含证据实体**（见第四章）。

## 三、技术图的资料查证要求

画任何技术内容前，先查真实规格。画协议、API 或框架时：

1. 查实际的 JSON / 数据格式
2. 找真实的事件名、方法名或接口地址
3. 弄清各部分究竟怎么连
4. 用真实术语，不用通用占位词

反例：`Protocol → Frontend`。
正例：`AG-UI 推送事件（RUN_STARTED, STATE_DELTA, A2UI_UPDATE） → CopilotKit 经 createA2UIMessageRenderer() 渲染`。

**🔴 检查点 #1**：每次生成图表前，必须先读 `references/color-palette.md`，禁止凭记忆编造颜色值。查证让图既准确又有教学价值。

## 四、证据实体（Evidence Artifacts）

证据实体是能证明图准确、并帮观者学到的具体样例，放进技术图里。

| 实体类型 | 何时用 | 怎么画 |
|---------|-------|-------|
| 代码片段 | API、集成、实现细节 | 深色矩形 + 语法着色文字（颜色取色板里的证据实体色） |
| 数据 / JSON 样例 | 数据格式、模式、载荷 | 深色矩形 + 彩色文字 |
| 事件 / 步骤序列 | 协议、流程、生命周期 | 时间线（线 + 圆点 + 标签） |
| UI 草图 | 展示实际输出 / 结果 | 嵌套矩形模拟真实界面 |
| 真实输入内容 | 展示进入系统的东西 | 矩形内直接放样例内容 |
| API / 方法名 | 真实函数调用、接口 | 用文档里的真名，不用占位词 |

**🔴 检查点 #2**：技术图必须含证据实体（代码片段 / JSON 样例 / 真实数据），不允许只有空标签矩形。

## 五、多级缩放架构

综合图同时在多个缩放层级上工作，像一张同时画出国界与街道名的地图。

### 一级：总览流
一眼看全的简化流程，通常放图的顶部或底部。例：`输入 → 处理 → 输出`。

### 二级：区段边界
用带标注的区域把相关组件分组，形成视觉"房间"，帮观者理解什么属于一起。例：按职责（后端 / 前端）、按阶段（准备 / 执行 / 收尾）或按角色（用户 / 系统 / 外部）分组。

### 三级：区段内细节
每个区段内的证据实体、代码片段与具体样例，教学价值就在这里。例："后端"区段里展示真实的 API 响应格式，而不只是一个写着"API 响应"的盒子。

**综合图要同时用到三级**：总览给上下文，区段做组织，细节负责教学。

| 陈列式（差） | 论证式（好） |
|-------------|-------------|
| 5 个等大方框贴标签 | 每个概念的形状镜像它的行为 |
| 卡片网格布局 | 视觉结构匹配概念结构 |
| 图标装饰文字 | 形状本身就是意义 |
| 所有东西同一个容器 | 每个概念一套视觉词汇 |
| 全部套方框 | 自由文本 + 有选择的容器 |

## 六、容器与自由文本

**不是每段文字都需要一个框。** 默认用自由文本，只有容器能起作用时才加。

| 该用容器时 | 该用自由文本时 |
|-----------|---------------|
| 是某区段的视觉焦点 | 是标签或描述 |
| 需与其他元素成组 | 是支撑细节或元数据 |
| 箭头要连到它 | 描述附近的东西 |
| 形状本身有意义（判断菱形等） | 字体层级已足够 |
| 代表系统中一个独立"事物" | 是区段标题、副标题或注释 |

**字体即层级**：用字号、字重、颜色建立层级，不必加框。28px 的标题不需要外面套矩形。
**容器检验**：对每个加了框的元素问一句"它当自由文本行不行？"行就去掉框。

## 七、设计流程（生成 JSON 之前）

**步骤 0：判定深度档位。** 先定这张图是简版/概念，还是综合/技术。综合图要先做资料查证。
**步骤 1：吃透内容。** 对每个概念问：它**做**什么（而非它是什么）？概念间是什么关系？核心转换或流向是什么？别人要**看到**什么才能懂（而非只读到）？
**步骤 2：概念映射到视觉模式。** 为每个概念找镜像其行为的模式：

| 如果概念…… | 用这个模式 |
|-----------|-----------|
| 派生多个输出 | 扇形发散（从中心放射箭头） |
| 汇合成一个 | 汇聚（漏斗、箭头合流） |
| 有层级 / 嵌套 | 树（线 + 自由文本） |
| 是一串步骤 | 时间线（线 + 圆点 + 自由文本标签） |
| 持续循环 / 迭代 | 螺旋 / 循环（箭头回到起点） |
| 是抽象状态或语境 | 云（交叠椭圆） |
| 把输入变成输出 | 流水线（前 → 过程 → 后） |
| 比较两样东西 | 并排（平行 + 对比） |
| 按阶段切分 | 断口（区段间留白分隔） |

**步骤 3：保证多样性。** 多概念图里，每个主要概念必须用不同的视觉模式，禁止统一卡片或网格。
**步骤 4：勾画流向。** 生成 JSON 前先在脑中走一遍眼睛的移动路径，图要有清晰的视觉故事。
**步骤 5：生成 JSON。** 此时才建 Excalidraw 元素，大图按下章分段处理。
**步骤 6：渲染与验证（强制）。** 生成后必须走 render→view→fix 循环直到图正确，详见第十七章。

## 八、大型 / 综合图的生成策略

综合图或技术图必须**按区段逐批生成 JSON**，禁止一次生成整份。单次输出有 token 上限，整图一次生成必然截断；即便塞得下，一次生成的质量也更差。

### 分段工作流

1. **建基础文件**：写好 JSON 外壳（`type`、`version`、`appState`、`files`）与第一个区段的元素。
2. **一次编辑加一个区段**：每个区段单独一次编辑，仔细考虑布局、间距与它和已存在内容的连接。
3. **用可读的字符串 ID**（如 `"trigger_rect"`、`"arrow_fan_left"`），方便跨区段引用。
4. **按区段给 seed 分段命名空间**（如区段 1 用 100xxx，区段 2 用 200xxx），避免种子碰撞。
5. **随时更新跨区段绑定**：新区段元素要绑到旧区段元素时，同时改旧元素的 `boundElements` 数组。

**🔴 检查点 #3**：大图必须分区段逐批生成，禁止一次输出完整 JSON，每批只加一个区域的元素。

**复核整体。** 所有区段就位后通读全份 JSON，检查：跨区段箭头两端是否都绑定正确；整体间距是否均衡（有无某处拥挤、某处大片空白）；ID 与绑定是否都指向真实存在的元素。修好对齐与绑定问题再渲染。

## 九、视觉模式库

- **扇形发散（一对多）**：中心元素向多个目标放射箭头。用于源头、根因、中枢。
- **汇聚（多对一）**：多个输入经箭头汇入单一输出。用于聚合、漏斗、综合。
- **树（层级）**：父子分叉，用连接线与自由文本（不必加框）。用于文件系统、组织架构、分类法。主干与分支用 `line` 元素，标签用自由文本。
- **螺旋 / 循环**：元素成串且箭头回到起点。用于反馈、迭代、演进。
- **云（抽象状态）**：大小不一的交叠椭圆。用于语境、记忆、对话、心理状态。
- **流水线（转换）**：输入 → 处理框 → 输出，前后对比明确。
- **并排（比较）**：两组平行结构 + 视觉对照。用于前后、选项、取舍。
- **断口（分隔）**：区段间用留白或隔断。用于阶段切换、语境复位、边界。

**线作为结构**：用线（`type: line`，非箭头）充当主要结构元素，而非方框——时间线（竖线 / 横线 + 每隔一段的小圆点 + 旁侧自由文本）、树结构（竖主干 + 横分支 + 自由文本标签）、分隔线（细虚线分区段）、流脊（一条中线，元素与之相关而非互连方框）。线 + 自由文本往往比方框 + 内嵌文字更干净。

## 十、形状语义

按元素代表什么来选形状，或者干脆不用形状：

| 概念类型 | 形状 | 理由 |
|---------|------|------|
| 标签、描述、细节 | 无（自由文本） | 字体建立层级 |
| 区段标题、注释 | 无（自由文本） | 字号 / 字重已够 |
| 时间线上的标记 | 小 `ellipse`（10-20px） | 视觉锚点，不是容器 |
| 起点、触发、输入 | `ellipse` | 柔和的源点感 |
| 终点、输出、结果 | `ellipse` | 完成、目的地 |
| 判断、条件 | `diamond` | 经典判断符 |
| 处理、动作、步骤 | `rectangle` | 被包含的动作 |
| 抽象状态、语境 | 交叠 `ellipse` | 模糊、云状 |
| 层级节点 | 线 + 文本（不加框） | 用线表达结构 |

**规则**：默认不加容器，形状只在承载意义时加。目标：带容器的文字元素占比 < 30%。

## 十一、颜色语义

颜色编码信息，不做装饰。每个颜色选择都取自 `references/color-palette.md`——语义形状色、文字层级色、证据实体色都在那里定义。

**要点**：每个语义用途（起点、终点、判断、AI、错误等）对应一组固定的填充 / 描边；自由文本用颜色表达层级（标题、副标题、细节各一级）；证据实体（代码片段、JSON 样例）用自带的深底 + 彩色字；始终深描边搭浅填充以保对比。**禁止自造新色**；某个概念套不进已有语义类时，用 Primary/Neutral 或 Secondary。

## 十二、现代美学

- **手绘度**：`roughness: 0` 干净利落，用于现代 / 技术图；`roughness: 1` 手绘有机感，用于脑暴 / 非正式图。多数专业场景默认 0。
- **线宽**：`strokeWidth: 1` 细而雅，用于线、分隔、弱连接；`2` 标准，用于形状与主箭头；`3` 加粗，克制使用于强调（主流向线、关键连接）。
- **不透明度**：所有元素一律 `opacity: 100`，用颜色、大小与线宽做层级，不用透明度。
- **小标记代替形状**：用 10-20px 的小圆点充当时间线标记、项目符号、连接节点、自由文本的视觉锚点。

## 十三、版式原则

- **以尺度分主次**：主角 300×150（视觉锚点）；一级 180×90；二级 120×60；小件 60×40。
- **留白即重要**：最重要的元素周围留最多空白（200px 以上）。
- **流向**：引导视线，序列通常左→右或上→下，中枢放射用径向。
- **必须有连接**：位置本身不表达关系，A 与 B 有关系就一定要有箭头。

## 十四、文字规则

**关键**：JSON 的 `text` 属性只放可读词语。`fontSize: 16`、`fontFamily: 3`、`textAlign: "center"`、`verticalAlign: "middle"`。

```json
{
  "id": "myElement1",
  "text": "Start",
  "originalText": "Start"
}
```

`text` 与 `originalText` 只放纯文本；代码或 JSON 结构放到独立的证据实体矩形里，禁止塞进 `text`。

## 十五、JSON 结构与元素模板

```json
{
  "type": "excalidraw",
  "version": 2,
  "source": "https://excalidraw.com",
  "elements": [],
  "appState": { "viewBackgroundColor": "#ffffff", "gridSize": 20 },
  "files": {}
}
```

各元素类型（文本、线、圆点、矩形、箭头）的可复制 JSON 模板见 `references/element-templates.md`；字段定义与绑定格式见 `references/json-schema.md`；颜色按各元素语义用途从 `references/color-palette.md` 取。

## 十六、执行工作流（六步）

接到"画一张手绘图"后按此六步推进，每步写明输入、动作、输出。

1. **判定档位并取色板**：输入＝用户需求与原图文案；动作＝读 `references/color-palette.md` 锁定语义配色，读 `references/json-schema.md` 确认字段；输出＝档位结论（简版 / 技术图）+ 选定的语义色清单。
   ```bash
   sed -n '1,80p' references/color-palette.md
   ```
2. **做资料查证（技术图必做）**：输入＝要画的协议 / 系统名；动作＝查真实格式、事件名、接口名，用真术语替换占位词；输出＝一张"真实术语对照表"，无来源的信息标 `【待填：待查证】`。
3. **映射视觉模式并勾画流向**：输入＝术语对照表与概念清单；动作＝为每个概念选不同视觉模式（扇形 / 汇聚 / 时间线 / 树 / 循环），在纸上排出三级缩放；输出＝区段划分表（每段包含哪些元素、如何与相邻段连接）。
4. **按区段生成 JSON**：输入＝区段划分表；动作＝先写 JSON 外壳，再每个区段一次编辑追加元素，用描述性 ID 与分段 seed，同步维护 `boundElements` 绑定；输出＝`<name>.excalidraw` 文件。
   ```bash
   python3 scripts/excalidraw_check.py --file diagram.excalidraw
   ```
5. **静态体检 + 渲染目视**：输入＝生成的 `.excalidraw`；动作＝跑 `scripts/excalidraw_check.py` 抓坐标越界、重叠、错连、溢出、ID 重复，再用 `references/render_excalidraw.py` 渲染 PNG 并读图复核；输出＝缺陷清单。
   ```bash
   cd references && uv run python render_excalidraw.py ../diagram.excalidraw
   ```
6. **修正并交付**：输入＝缺陷清单；动作＝按清单逐条改 `x`/`y`/宽高 / 箭头控制点 / 绑定 ID，重回第 4-5 步，直至体检零 ERROR 且目视无缺陷；输出＝定稿 JSON + 体检报告。
   ```bash
   python3 scripts/excalidraw_check.py --file diagram.excalidraw --json
   ```

## 十七、渲染与验证（强制）

光看 JSON 判断不了图好不好看。生成或改完 Excalidraw JSON 后，必须渲染成 PNG、看图、改掉所见问题，循环到对为止。这不是最后一道检查，而是工作流的核心环节。

**怎么渲染**：`cd references && uv run python render_excalidraw.py <file.excalidraw>`，PNG 输出在 `.excalidraw` 同目录，再用读图工具打开 PNG 目视。

**🔴 检查点 #4**：生成 JSON 后必须执行 render→view→fix 循环（≥2 轮），不允许跳过渲染验证直接交付。

**循环步骤**：
1. **渲染并看图**——跑渲染脚本，读 PNG。
2. **对照原设计复核**——先对照第七章的设计意图：视觉结构是否匹配概念结构？每段是否用了预期的模式？视线流动是否符合设计？主次是否正确？技术图的证据实体是否可读、位置得当？
3. **查视觉缺陷**——文字被裁切或溢出容器；文字或形状互相重叠；箭头穿过元素而非绕行；箭头落在错误元素或指向空白；标签漂浮、锚定不清；本该等距的元素间距不均；某处留白过多而邻处拥挤；渲染尺寸下文字太小；整体构图失衡。
4. **修正**——文字被裁就加宽容器；调 `x`/`y` 修间距对齐；给箭头 `points` 加中间控制点绕开元素；把标签移近它所描述的元素；调整元素尺寸重新平衡视觉重量。
5. **再渲染再看图**——重跑脚本、读新 PNG。
6. **重复**——直到同时通过设计复核与缺陷检查，通常迭代 2-4 次；没有致命缺陷也要看构图能否更好。

**何时停止**：渲染结果与设计意图一致；无文字裁切、重叠或不可读；箭头走向干净且连对元素；间距一致、构图平衡；可以不加任何解释地拿给别人看。

**首次装配**：`cd references && uv sync && uv run playwright install chromium`。

## 十八、质量核对清单

**🔴 检查点 #5**：交付前逐条核对本清单，任何一条不通过，修好再交付。

- **深度与证据**：查证做了吗？有代码片段 / JSON 样例 / 真实数据吗？有总览 + 区段 + 细节三级吗？用具体内容而非空标签框吗？别人能学到具体东西吗？
- **概念**：同构吗（每个视觉结构镜像其概念行为）？有论证力吗（展示了纯文字做不到的东西）？每个主要概念用了不同模式吗？避开了统一卡片网格吗？
- **容器纪律**：容器最少化了吗（加框的能改成自由文本吗）？树 / 时间线用了线 + 文本而非方框吗？字号与颜色撑起层级了吗？
- **结构**：每个关系都有箭头或线吗？视线路径清晰吗？重要元素更大、更孤立吗？
- **技术**：`text` 只有可读词吗？`fontFamily: 3` 吗？`roughness: 0` 吗（除非明确要手绘风）？所有元素 `opacity: 100` 吗？带容器的文字元素占比 < 30% 吗？
- **视觉验证**：已渲染 PNG 并目视了吗？无文字溢出吗？无意外重叠吗？同类元素间距一致吗？箭头落点正确且不穿其他元素吗？导出尺寸下文字可读吗？构图无大片空洞或过度拥挤吗？

## 十九、失败模式

以下是生成 Excalidraw 图表的高频失败场景，统一写成「如果 X → 则 Y（降级 / 回退 / 重试 / 兜底）」格式，遇到就按动作处理。完整速查表见 `references/failure-modes.md`。

1. **如果元素 `x`/`y` 坐标越出可见画布或出现负值** → 则先用 `scripts/excalidraw_check.py` 抓出越界元素，回退到区段基准坐标（每个区段先定左上原点），重算相对偏移，兜底把画布边界阈值放宽一档再复核。
2. **如果两个形状包围盒相交面积超阈值（元素重叠）** → 则按体检报告的两两重叠清单，重排该区段版式（拉开行距 / 列距至 ≥ 60px），重试后再渲染目视确认。
3. **如果文字被容器裁切或溢出（文字溢出）** → 则按 `rawText.length * fontSize * 0.6` 估算文字宽度，把容器宽扩到「文字宽 + 40px」，或回退为无框自由文本，兜底缩小字号一档并重排。
4. **如果箭头 `startBinding`/`endBinding` 缺失或 ID 不匹配（箭头错连）** → 则逐条箭头核对两端 elementId 与实际元素 id 严格一致，补全或改正绑定，重试后确认箭头随元素移动不脱离。
5. **如果 `.excalidraw` 导入报错或打开后空白** → 则校验顶层 `type`/`version`/`elements` 是否齐备，检查 `text` 是否混入了 JSON 结构，回退到 `references/element-templates.md` 的最小合法模板重建外壳，兜底降级为只输出核心形状再加细节。
6. **如果一次性生成完整大图 JSON 导致输出被截断** → 则改为按区段逐批生成，每批只加一个区域，用描述性 ID 命名，兜底把大图拆成两张分图交付。
7. **如果所有概念都用相同矩形与相同颜色导致视觉单调** → 则按第十章给每个主要概念换形状（ellipse/diamond/rectangle/线+文本），按第十一章换语义色，重试后目视复核。
8. **如果 `opacity` 不是 100 或 `fontFamily` 非标准值** → 则把所有元素统一回 `opacity: 100`、文字 `fontFamily: 3`，兜底跑体检脚本确认无残留异常字段。
9. **如果渲染脚本因 Playwright 依赖缺失而报错** → 则执行 `uv sync && uv run playwright install chromium` 重试；仍失败时降级为纯静态体检（`scripts/excalidraw_check.py`）+ JSON 人工复核，并在交付说明里标注未做目视校验。

## 二十、反例与红线

以下做法属于反模式，落在红线内，禁止执行：

- **禁止**把整个大图一次性生成，必须分区段逐批生成。
- **禁止**在 `text` / `originalText` 里放 JSON 结构或代码块，代码只能进独立证据实体矩形。
- **禁止**自造颜色值，颜色只能取 `references/color-palette.md`。
- **不要**给每段文字都套容器，容器占比超过 30% 即为越界。
- **不可**用 `opacity` 小于 100 做层次，半透明元素在深底上不可读。
- **不要**省掉渲染验证循环直接交付，未渲染的成品视为未完成。
- **不在范围**：位图精修、去水印、UI 高保真稿、3D 渲染、CAD 尺寸图——这些超出本技能边界。
- **黑名单做法**：等大方框卡片网格、图标堆砌装饰、箭头穿过元素、箭头指向空白、用占位词代替真实术语。

## 二十一、使用示例

**使用示例 1（流程类手绘图）**
> 需求："帮我画一张手绘流程图：用户提交工单 → 系统校验 → 通过则派单，不通过则退回。"
> 动作：判定为简版概念图，起点用 `ellipse`、校验用 `diamond`、派单 / 退回用两条分支箭头 + 自由文本；生成 `ticket-flow.excalidraw`；跑
> `python3 scripts/excalidraw_check.py --file ticket-flow.excalidraw` 确认无越界与错连。

**使用示例 2（架构类手绘图）**
> 需求："出一张 Excalidraw 架构图，展示客户端 → 网关 → 三个微服务 → 数据库的调用关系。"
> 动作：判定为技术图，二级用容器分区（客户端区 / 服务区 / 存储区），三级在服务区放真实接口名作为证据实体；按区段逐批生成 `arch.excalidraw`；渲染 PNG 目视复核箭头绕行。

**使用示例 3（概念类可视化论证）**
> 需求："做一张可视化论证：把信息衰减画成漏斗，越往下越窄。"
> 动作：判定为概念图，用宽度递减的椭圆链 + 汇聚箭头表达衰减，不用方框；生成 `funnel.excalidraw`，确认同构检验通过（抹掉文字仍能看出衰减）。
