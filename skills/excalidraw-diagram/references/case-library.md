# excalidraw-diagram 实战案例库

本案例库记录「手绘图生成官」的典型生成与纠偏过程，供复现与复盘。案例来源：技能实际生成记录（P0 一手产物）与设计方法论推导（P2）。

## 案例一：工单流转流程手绘图（简版概念图）

- 背景：需要一张"提交工单 → 系统校验 → 通过派单 / 不通过退回"的手绘流程图。
- 做法：判定为简版概念图；起点用 `ellipse`、校验用 `diamond`、两条分支用箭头 + 自由文本；不套卡片网格；生成 `ticket-flow.excalidraw` 后跑 `python3 scripts/excalidraw_check.py --file ticket-flow.excalidraw` 确认无越界与错连。
- 结果：结构一次性通过体检，同构检验通过（抹掉文字仍能看出"分流"结构）。

## 案例二：微服务调用架构手绘图（综合技术图）

- 背景：出一张 Excalidraw 架构图，展示客户端 → 网关 → 三个微服务 → 数据库。
- 做法：判定为技术图，二级用容器分区（客户端区/服务区/存储区），三级在服务区放真实接口名与真实响应 JSON 样例作为证据实体；按区段逐批生成 `arch.excalidraw`（避免单次生成被截断）；渲染 PNG 目视复核箭头绕行与文字溢出。
- 结果：首轮渲染发现一处箭头穿过元素、一处文字溢出，回退调整 `points` 控制点并把容器加宽 40px；第二轮通过，容器占比 26%（< 30%）。

## 案例三：信息衰减漏斗（概念可视化论证）

- 背景：把"信息衰减"画成漏斗，越往下越窄。
- 做法：判定为概念图，用宽度递减的椭圆链 + 汇聚箭头表达衰减，不用方框；生成 `funnel.excalidraw`。
- 结果：同构检验通过；无形状重叠；交付时附一句"抹掉文字仍能看出衰减"的设计自证。

## 案例四：渲染依赖缺失的降级交付

- 背景：环境未安装 Playwright/Chromium，渲染脚本报错。
- 做法：先 `uv sync && uv run playwright install chromium` 重试；仍失败则降级为纯静态体检（`excalidraw_check.py` + `excalidraw_deliver_check.py`）+ 人工复核 JSON，并在交付说明明确标注"未做目视校验"。
- 结果：结构性问题被静态体检全部拦截；交付说明如实标注未目视，避免误判为已完整验证。
