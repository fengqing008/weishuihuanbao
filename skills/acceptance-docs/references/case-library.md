> 移植自 WorkBuddy 专家包 acceptance-docs（pkg/agents/acceptance-docs.md「核心方法论/工作流」＋ pkg/skills/references/case-library.md），并按 ima 环境完成再沙箱化：原包在"脚本生成 Word 文档"环节改写为脱离工具的手工操作指引，本次移植已全部还原为本技能脚本 `scripts/acceptance_tools.py` 对应子命令调用——43 项核对清单、检验批/隐蔽/分项/分部四联模板、竣工验收报告、会议四件套、九大分部划分表均由脚本一键生成 Word，用户只做【待填】字段填写、打印、签字、盖章。

> 与既有文件的关系：本技能原无 references/ 目录；`scripts/acceptance_tools.py`（checklist/records/report/meeting/divisions 五个子命令）是资料生成的唯一权威实现，本库只解决"先查场景、再选对子命令、按对要点"的策略问题，两者配合使用，不替代脚本。模板字段口径详见 `writing-templates.md`。

## 场景 1：验收前资料自查与缺项补正

【场景】单位工程竣工预验收或正式验收前，需要判断资料是否齐套、缺什么、谁负责补。

【策略】按五类资料清单逐项核对：一、施工管理资料（开工报告及报审表、施工组织设计及专项方案、图纸会审/设计变更/洽商记录、测量放线复核、施工日志、技术交底、质量事故处理报告、见证取样送检台账、施工现场质量管理检查记录〔GB 50300-2013 附录 A〕）；二、质量控制资料（材料合格证及复试、混凝土/砂浆配合比与试块强度、钢筋连接工艺评定、防水材料及蓄水淋水试验、隐蔽验收记录、检验批/分项/分部记录、满水试验、管道水压闭水闭气试验、设备单机试运转、绝缘/接地电阻测试、沉降观测）；三、安全和功能检验资料（通水通球、照明全负荷试运行、消防联动调试检测、污水厂联动试运行及 72 小时满负荷试运行、环保验收监测、防雷接地检测、特种设备检验）；四、观感质量检查资料（按附录 H 由验收组现场填写）；五、竣工验收文件（验收报告、备案表、各参建单位质量检查报告、保修书、竣工图、竣工结算、会议纪要及意见书、质量监督报告、移交清单、PPP 绩效资料）。

【要点】①每项标注份数要求与责任单位，勾选"已备/未备"；②缺项列清单限期补正，资料齐全后施工单位成册、监理审核签认；③清单为通用版，按施工合同与地方质监站要求增删。

【示例骨架＋工具调用】表格：序号｜资料名称｜份数要求｜责任单位｜完成情况（□已备 □未备）。脚本 CHECKLIST 常量已内置五大类 43 项与核对说明 5 条，直接生成：

```bash
python scripts/acceptance_tools.py checklist -o ./output --project-name "<工程名称>"
```

## 场景 2：检验批质量验收记录填写

【场景】施工过程中检验批验收，或竣工前补齐检验批记录。

【策略】按 GB 50300-2013 附录 B、D 结构填表：表头（工程名称、检验批部位/区段、施工单位、监理单位、验收依据）；主控项目检查表＋一般项目检查表（含允许偏差），均设"施工单位检查评定记录"与"监理（建设）单位验收记录"两栏。

【要点】①主控项目必须全部合格，一般项目按规范允许偏差抽查；②结论栏分别由项目专业质量检查员、专业监理工程师签署"合格/不合格"并签字注明日期。

【示例骨架＋工具调用】主控项目表：序号｜检验项目｜规范要求｜施工单位检查评定记录｜监理（建设）单位验收记录；结论两行：施工单位检查结果／监理（建设）单位验收结论（源自脚本 cmd_records·检验批质量验收记录）。四联记录包一并生成：

```bash
python scripts/acceptance_tools.py records -o ./output --project-name "<工程名称>"
```

## 场景 3：隐蔽工程验收记录办理

【场景】土方、钢筋、防水、管道、基础等隐蔽部位覆盖前必须先办验收。

【策略】填隐蔽部位（桩号/构筑物名称）、隐蔽日期、施工图号、隐蔽内容（材质、规格、数量、做法），检查方法按观察/量测/试验填写，结论勾选合格/不合格。

【要点】①先办隐蔽验收记录再进入下道工序；②附隐蔽部位示意图或照片并注明拍摄位置与日期；③施工、监理、建设三方均须签字。

【示例骨架＋工具调用】信息表＋"附图（示意图、照片粘贴处）"栏＋三方"验收意见及签字/日期"表（源自脚本 cmd_records·隐蔽工程验收记录），由 `records` 子命令一并生成（命令见场景 2）。

## 场景 4：分项、分部工程质量验收

【场景】检验批全部完成后逐级汇总验收。

【策略】分项记录（附录 E）：列各检验批部位区段的合格性判定，由项目专业技术负责人与监理工程师签署结论。分部记录（附录 F）：汇总各分项数量，核查质量控制资料（完整/基本完整/不完整）、安全和功能检验报告（齐全/基本齐全/缺项）、观感质量（好/一般/差），形成验收结论。

【要点】①分部验收签字单位为施工、勘察、设计、监理、建设五方；②勘察单位仅在地基与基础分部验收时参加；③满水试验、闭水试验、单机试运转等功能性检验记录作为分部验收必备附件。

【示例骨架＋工具调用】分项表：序号｜检验批部位区段｜施工单位评定｜监理验收结论；分部表：序号｜分项工程名称｜检验批数量｜双方结论＋三项核查栏＋五方签字栏（源自脚本 cmd_records·分项/分部工程质量验收记录），由 `records` 子命令一并生成（命令见场景 2）。

## 场景 5：竣工验收报告编制

【场景】建设单位在正式验收前编制竣工验收报告。

【策略】按七部分框架：一、工程概况（名称、地点、建设规模、结构类型、层数/构筑物数量、造价、开竣工日期、合同编号、质量目标）；二、勘察/设计/施工/监理单位情况（含资质等级、项目负责人，附质量监督机构）；三、验收范围及内容；四、验收依据（六项法规标准合同）；五、工程质量评定（分部质量、质量控制资料核查、安全和功能检验、观感质量、综合评定五小节）；六、验收意见；七、参加验收人员签字栏。

【要点】①验收前填写完整；②报告一式 4 份；③不合格时写明问题及"整改后重新组织验收"。

【示例骨架＋工具调用】七部分框架（源自脚本 cmd_report·竣工验收报告框架），地点、造价可随命令注入：

```bash
python scripts/acceptance_tools.py report -o ./output --project-name "<工程名称>" \
    --location "<工程地点>" --cost "<工程造价>"
```

## 场景 6：竣工验收会议组织

【场景】建设单位牵头组织竣工验收会议并形成全套文件。

【策略】四件套配套产出：①会议议程（8 项：宣布开始介绍验收组→建设单位介绍建设及验收准备→施工单位汇报施工与自评→监理汇报与质量评估→勘察设计发表质量意见→现场实体检查与资料核查→讨论形成验收意见→宣布结论签署意见书）；②验收组组成名单（组长、副组长、成员，含单位/职务职称/专业/电话/签字）；③会议签到表；④验收意见书（概况→组织情况→依据及程序→结论勾选→验收组签字）。

【要点】①验收组由建设单位牵头，成员含勘察、设计、施工、监理单位项目负责人及聘请专家；②与会人员提前 15 分钟签到；③验收按"听取汇报、现场检查、资料核查、讨论评议"程序；④意见书一式多份，建设单位、施工、监理、实施机构/质监机构各执。

【示例骨架＋工具调用】四件套（源自脚本 cmd_meeting·会议议程/验收组名单/签到表/意见书），会议三要素随命令注入：

```bash
python scripts/acceptance_tools.py meeting -o ./output --project-name "<工程名称>" \
    --meeting-date "<会议时间>" --meeting-place "<会议地点>" --host "<主持人>"
```

## 场景 7：污水厂工程分部分项划分

【场景】市政污水处理厂项目开工或验收前，需明确分部—分项—检验批划分。

【策略】按 9 大分部列典型分项（检验批）：地基与基础（土方、垫层、钢筋、模板、混凝土、地基处理）；主体结构—构筑物（池体底板/池壁/顶板、预埋件、防水混凝土、满水试验）；主体结构—建筑物（砌体、框架、屋面、装饰装修、门窗）；建筑给排水及供暖；建筑电气（桥架、配管配线、照明、防雷接地、通电试运行）；工艺设备安装（格栅、泵、鼓风机、刮泥机、加药、消毒、污泥脱水、单机试运转）；工艺管道（进出水管、加药/污泥管、水压闭水试验、冲洗消毒）；自动化仪表与监控（仪表、PLC 柜、监控系统、自控联调）；室外附属（道路、围墙大门、绿化、室外照明）。

【要点】①划分原则：单位工程按独立施工条件或使用功能，分部按专业性质与建筑部位，分项按工种/材料/工艺/设备类别，检验批按工程量/楼层/施工段；②划分结果须经监理工程师确认，验收批数施工单位填写、监理复核；③实际项目按施工图纸、合同范围及当地质监站要求调整。

【示例骨架＋工具调用】表：序号｜分部工程｜分项工程（检验批）｜验收批数｜备注；划分原则与使用说明已内置于脚本 DIVISIONS 常量与 cmd_divisions：

```bash
python scripts/acceptance_tools.py divisions -o ./output --project-name "<工程名称>"
```

## 场景 8：PPP 项目验收专项资料

【场景】污水处理厂 PPP 项目竣工验收，涉及绩效评价与可用性付费。

【策略】在竣工验收文件类中附 PPP 项目绩效评价、可用性付费相关资料；同时备齐环保验收监测报告（水质、废气、噪声、污泥）与 72 小时满负荷试运行报告。

【要点】①按 PPP 合同及实施机构要求确定资料深度，责任单位为项目公司/实施机构；②验收绩效占年度考核比重的项目，验收资料口径应与考核指标一致。

【示例骨架＋工具调用】脚本 CHECKLIST 第五类末项已内置该行（PPP 项目绩效评价/可用性付费相关资料｜1 份｜项目公司/实施机构｜□已备 □未备），`checklist` 直接带出；配套报告与会议文件用 `report`/`meeting` 子命令生成（见场景 5、6）。项目资料索取前先 search_knowledge 检索 ima 知识库（如某市三库之竣工资料库），仍缺再向用户索取。
