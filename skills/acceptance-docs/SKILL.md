# acceptance-docs —— 工程验收全套资料生成技能

## 使用说明

1. **用途**：工程验收全套资料生成。
2. **典型问法**：“验收资料”、“验收清单”、“检验批”、“隐蔽工程验收”。
3. **调用方式**：在 ima 对话中直接描述需求或上传相关文件，本技能按触发词自动匹配调用。

> v2.0.0 专家级（2026-09-07）：本次升级头部插入专家级路由与触发条件，尾部补齐输出规范、边界与反模式、实战范例、版本与变更记录；原五类子命令、文档模板流程、【待填：...】占位与法规依据全部保留

## 触发条件

满足任一即响应；均不满足时说明本技能不适用并建议改用对应技能：
- 用户提到"验收资料、验收清单、检验批、隐蔽工程验收、分项分部验收、分部分项划分、竣工验收报告、验收会议、某市PPP项目竣工验收"等关键词；
- 用户要求生成 Word 验收记录、报告、会议文件，或将验收资料转 PDF 归档；
- 用户询问某项验收资料是否必备、份数多少、由哪个单位提供（L1 快答）；
- 用户要为竣工验收会议准备议程、验收组名单、签到表、意见书。

## 一、功能概述

本技能面向市政工程（含污水处理厂 PPP 项目）竣工验收场景，依据《建设工程质量管理条例》（国务院令第279号）、《房屋建筑工程和市政基础设施工程竣工验收暂行规定》（建质〔2000〕142号）与 GB 50300-2013《建筑工程施工质量验收统一标准》，通过一个 Python 脚本（argparse 子命令）批量生成五类 Word 验收资料：

| 子命令 | 产出 | 说明 |
| --- | --- | --- |
| `checklist` | 工程竣工验收资料核对清单 | 按 5 大类（施工管理资料 / 质量控制资料 / 安全和功能检验资料 / 观感质量 / 竣工验收文件）逐项列出文件名称、份数要求、责任单位、勾选列，用于验收前资料自查 |
| `records` | 检验批/隐蔽/分项/分部验收记录模板包 | 检验批质量验收记录、隐蔽工程验收记录、分项工程质量验收记录、分部工程质量验收记录 4 个 Word 模板 |
| `report` | 竣工验收报告框架 | 工程概况、参建单位、验收范围及内容、验收依据、工程质量评定、验收意见、参加验收人员签字栏 |
| `meeting` | 竣工验收会议全套文件 | 会议议程、验收组组成名单、会议签到表、验收意见书框架 4 个 Word |
| `divisions` | 污水厂工程分部分项划分表（v1.1.0 新增） | 按 9 大分部（地基基础/构筑物主体/建筑物主体/给排水/电气/工艺设备/工艺管道/自控仪表/室外附属）列出典型分项检验批，含划分原则与使用说明 |

所有模板字段以【待填：...】占位，可直接在 Word/WPS 中填写、打印、签字归档。

## 二、适用场景

- 市政污水处理厂 PPP 项目竣工验收资料准备（如某市 PPP 项目，验收绩效占年度考核 30%）
- 单位工程竣工预验收、正式验收前的资料自查与补缺
- 施工/监理单位按检验批、分项、分部工程同步整理验收记录
- 组织竣工验收会议并形成会议全套文件（议程、名单、签到、意见书）

## Phase 0｜资料生成前校验（未过不进主流程）

| 检查项 | 通过标准 | 未过动作 |
|---|---|---|
| 验收阶段 | 明确为检验批/分项/分部/单位工程/竣工验收 | 阶段不明先确认 |
| 项目类型 | 市政污水/房屋建筑等类型明确（影响分部分项划分） | 确认类型后再建表 |
| 依据标准 | 所引验收标准为现行版本（GB 50300-2013、GB 50268-2008 等） | 核实版本后引用 |
| 工程信息 | 工程名称、部位、施工单位、监理单位等字段口径齐备 | 补齐后再生成 |
| 项目划分 | 分部分项与检验批划分表已确定 | 划分确定后再批量出表 |

🔴 检查点：任一检查项未过，先补齐再进入工作流程。

## 三、工作流程

1. 确认项目名称、工程地点、造价、参建单位等基本信息；
2. 运行 `checklist` 生成资料核对清单，逐项核对、列出缺项并限期补正；
3. 运行 `records` 生成检验批/隐蔽/分项/分部记录模板，随施工进度同步填写；
4. 运行 `report` 生成竣工验收报告框架，验收前填写完整；
5. 运行 `meeting` 生成会议全套文件，组织竣工验收会议并签署意见书；
6. 产出 Word 均可用 Office/WPS/LibreOffice 打开，可用 soffice 转 PDF 归档备查。

## 四、命令用法

```bash
# 依赖安装
pip install python-docx

# 1. 验收资料核对清单（输出：验收资料核对清单.docx）
python scripts/acceptance_tools.py checklist \
    -o ./output --project-name "某市区污水处理厂PPP项目"

# 2. 检验批/隐蔽/分项/分部验收记录模板包（输出 4 个模板）
python scripts/acceptance_tools.py records \
    -o ./output --project-name "某市区污水处理厂PPP项目"

# 3. 竣工验收报告框架
python scripts/acceptance_tools.py report \
    -o ./output --project-name "某市区污水处理厂PPP项目" \
    --location "西安市某市区" --cost "2.86亿元"

# 4. 竣工验收会议全套文件（输出 4 个文件）
python scripts/acceptance_tools.py meeting \
    -o ./output --project-name "某市区污水处理厂PPP项目" \
    --meeting-date "2026年3月X日" --meeting-place "项目公司会议室" \
    --host "项目公司副总经理"

# 5.（可选）批量转 PDF 核验文档无损坏
soffice --headless --convert-to pdf --outdir ./output/pdf ./output/*.docx
```

## 七、注意事项

- 模板中所有【待填：...】字段务必逐项填写完整后再签字盖章；
- 清单内容依据国家法规/标准整理，具体项目应按施工合同、地方质监站要求适当增删；
- 市政污水工程特有资料已包含：构筑物满水试验、设备单机试运转与联动试运行、环保验收监测（水质/废气/噪声/污泥）等；
- PPP 项目涉及绩效评价、可用性付费的，应在竣工验收文件类中附绩效评价相关资料；
- 观感质量检查记录按 GB 50300-2013 附录 H 执行，由验收组现场填写。

## 八、输出规范（v2.0.0 新增）

- **结论先行**：首次响应先给齐套性结论、缺项清单或模板骨架，再展开细节，不做背景铺垫；
- **占位符统一**：所有未定字段一律用【待填：...】占位并写明待填内容（如【待填：工程名称】【待填：验收日期】），不得留空、不得编造具体数值；
- **文件命名与目录**：产出文件按脚本默认名（验收资料核对清单.docx、检验批质量验收记录.docx 等），统一输出到 `-o` 指定目录；每次交付列明"已生成文件清单"；
- **条目要素**：核对清单逐项标注文件名称、份数、责任单位、勾选列；验收记录须含验收部位与验收结论栏；报告须含工程概况、验收依据、验收程序、验收意见、签字栏；会议四件套须各自独立可打印；
- **份数口径**：建质〔2000〕142号未统一规定份数的，按施工合同、城建档案馆与当地质监站要求填【待填：份数】，不得擅自代定；
- **格式验证**：交付前用 soffice 转 PDF 抽验，确认文档可正常打开、表格无错位。

## 九、边界与反模式（v2.0.0 新增）

**明确不做**：
- 不代签：施工/监理/建设/设计各签字栏一律留【待填：...】，不生成任何人名、签章、日期；
- 不下结论：工程质量是否合格、能否通过验收由验收组现场判定，本技能只提供记录与意见书框架；
- 不替检测：环保验收监测、满水试验、桩基与设备检测数据须由有资质机构出具，本技能仅提供记录表格；
- 不改条文：《建设工程质量管理条例》、建质〔2000〕142号、GB 50300-2013 原文只引用不改写，地方细则由用户按属地补充；
- 不越程序：竣工验收备案、规划/消防/节能/环保专项验收按属地程序执行，本技能不模拟政府审批流程。

**反模式（出现即纠正）**：
- 框架当结论：把生成模板直接当作"验收已合格"的资料提交——模板只解决"格式齐"，不解决"合格否"；
- 编造数据：在【待填：...】处填入未经实测的数值、日期或签名人；
- 倒序补资料：跳过检验批直接填分部记录——GB 50300-2013 要求检验批→分项→分部逐级验收，须按序补齐；
- 漏专项：污水厂项目漏掉满水试验、设备单机试运转与联动试运行、环保验收监测资料；
- 跳过核对：未跑 `checklist` 齐套核对就先出记录与报告，把缺项风险后置。

## 九、验收资料高频退回情形（失败模式，2026-09-18 增补）

下列六类为市政污水工程验收资料自查中反复出现的退回与整改原因，逐条列出检查动作，交付前须逐条核对。

一是日期逻辑倒挂。检验批、分项、分部、单位工程四级验收记录的日期须依次递进，隐蔽工程验收日期不得晚于覆盖日期。检查动作：抽取任一分部内最早与最晚的检验批日期，与对应分项、分部记录比对，出现倒挂即整联返工。

二是隐蔽工程未验先覆。钢筋、防水、管道基础等隐蔽部位在覆盖前须完成验收并双方签字，事后补签记录在质监站核查中不予认可。检查动作：对照施工日志与隐蔽验收记录日期，逐项确认验收在覆盖之前。

三是签字主体错位。检验批由施工项目专业质量检查员与监理工程师签认，分项、分部由施工项目技术负责人与总监理工程师签认，建设单位在单位工程验收记录上签认。检查动作：按记录类型核对签字人身份，施工方代签监理栏的须重签。

四是试验与试运行记录缺附件。满水试验、单机试运转、联动试运行记录须附对应监测或调试报告，仅有记录表而无附件的按缺项处理。检查动作：逐项检查试验记录与归档附件编号是否对应。

五是竣工图不规范。竣工图须按 GB/T 50328-2014 加盖竣工图章，涉及设计变更的部位须标注变更依据文号，未标注的不得作为竣工图归档。检查动作：抽查变更部位图纸，核对竣工图章与变更标注。

六是PPP项目资料脱节。涉及可用性付费与运营绩效的验收，须同步归集绩效评价资料与付费依据，仅备齐工程验收资料会在后续付费环节形成缺环。检查动作：对照 PPP 合同付费条款，逐项确认验收资料与付费资料的衔接。

## 十、交付前关键检查点（2026-09-18 增补）

🔴 五类资料份数与责任单位已按合同与质监站要求标注，无空缺；
🔴 全部【待填：...】字段已逐项填写，无遗留占位直接打印；
🔴 四级验收记录日期序列经核对无倒挂；
🔴 隐蔽工程验收日期全部早于覆盖日期；
🔴 竣工图已加盖竣工图章并标注设计变更依据。

## 输出质量规范

- **数据溯源与来源分级**：逐项挂来源并标级——P0 设计图纸、施工记录与试验报告｜P1 验收标准（GB 50300-2013 等）与地方规定｜P2 同类项目范本；无来源者标【待核：需补来源】。
- **缺口显性化**：未填字段一律保留【待填：具体项】占位，不留空白、不臆造数据。
- **事实与判断分离**：实测值与检验结论属事实段直陈；合格与否的判定以「判断：」起头并附条款。
- **能力边界提示**：本输出为资料模板与核对清单；验收结论须由建设、监理、施工等单位签认后生效。

## 交付附加与迭代

交付时按需追加：关联提示、要点归纳（3—5 条，如资料缺口、高频退回情形、签署要求）、下一步动作（可执行项）。

多轮迭代：交付后说明可调整维度（阶段／项目类型／表式版本），指定后直接改。

## 交付自检表

| 检查项 | 标准 | 不达标动作 |
|---|---|---|
| 表式版本 | 与现行标准表式一致 | 更换表式 |
| 字段齐备 | 必填字段无空白（占位已标注） | 补占位 |
| 划分一致 | 分部分项与划分表相符 | 修正 |
| 依据现行 | 所引标准为现行版本 | 更新后引用 |
| 签署位 | 各方签署栏位齐备 | 补栏位 |
