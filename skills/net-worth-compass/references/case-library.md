# 身价罗盘案例库（case-library）

本案例库（案例集）为净值归集与分位定位的标准化处置参照，每则按「场景 / 处理 / 结论 / 要点」四段呈现。
套用时须按实际情况复核，不得直接复制数值与结论；代理值、未核实值一律标【估】【待核】。

---

## 案例一　资产清单缺项下的估值降级

- **场景**：用户口述"家里大概有套房、几十万存款、一辆车"，要求直接给分位结论；无精确金额、无小区名、无 region_code。
- **处理**：触发失败模式（输入不足）；不进入主流程，改跑 `scripts/nwc_check.py --input assets.json`——缺 name / value 时返回退出码 2；降级为"采集模板 + 缺项清单"，先由用户补齐房产小区名、面积、房龄与各账户金额，再行估值。禁止按 0 资产静默计算（会输出"前 99%"的危险假结论）。
- **结论**：交付采集模板与缺项清单两件，明确"金额补齐后回归估值"，不与用户争辩数据缺失。
- **要点**：①缺项先列清单再补数据；②`nwc_check.py` 退出码 2 即输入不足信号；③显式报错优于静默降级。

## 案例二　region_code 未命中基准库

- **场景**：用户提供的行政区划代码在本机 `assets/baseline.json`（3,421 个地区）中未命中，仍要求出"县区分位"。
- **处理**：按质量门禁第 4 条，`region_code` 未命中时**只出全国口径并提示**；不得编造该级基准。用 `nwc_check.py --expect-region <代码>` 校验位数与一致性，返回告警后回退到省级或全国口径，并在报告注明"该级无基准，暂只出全国口径"。
- **结论**：输出全国口径分位 + 取数路径提示（说明基准库扩展方式）。
- **要点**：①无基准数据不得输出该级分位；②扩展地区走 `scripts/build_regions.py`；③口径降级须显式说明。

## 案例三　公积金与存款重复计入

- **场景**：用户清单同时列出"住房公积金"与"银行存款（含公积金账户）"，两笔金额部分重合。
- **处理**：`nwc_check.py` 检测到「公积金」与「现金存款」类目并存时给出提示，触发人工复核；按第 2 步分类归集表的去重提醒，二者只能择一计入，复核后删除重复项再估值。
- **结论**：去重后总资产下调，净资产与分位同步修正，并在报告中记录复核轨迹。
- **要点**：①公积金既是账户也可能被算进存款，属高频重复项；②归集后逐类复核；③修正须留痕。

## 案例四　小区名匹配歧义

- **场景**：用户输入"万科金域东郡"，`assets/housing.json` 中同时存在"万科金域东郡"与"万科金域东郡三期"，单价不同。
- **处理**：按匹配顺序执行——**精确同名 → 包含匹配（取最短名）→ 所选地区区县均价 → 手动填单价**；命中"三期"属包含匹配歧义，回退到精确同名优先，仍不唯一时用区县均价兜底并要求用户手动确认单价。
- **结论**：给出估值区间与所用单价依据，标注"挂牌参考、非成交价"。
- **要点**：①精确同名优先；②歧义时降级到区县均价；③房产估值必须带"非成交价"免责。

## 案例五　高端净值外推失真

- **场景**：某用户净资产超过 1 亿元，模型仍按中位数锚点外推分位，给出"约前 0.01%"。
- **处理**：触发失败模式"高端外推失真"；不改模型数学，改为在报告中标注"仅作量级参考"，并说明高净值段样本稀疏、代理误差放大；同时披露精度分层（全国较可靠 / 省级中等 / 地级市与县区粗估）。
- **结论**：输出量级区间而非精确分位，附精度分层披露表。
- **要点**：①高净值段仅作量级参考；②精度分层必须如实披露；③不得把统计分位说成真实排名。

## 案例六　双端算法漂移自检

- **场景**：修改 `nwc_calc.py` 的计算逻辑后，互动版 HTML 内嵌 JS 未同步，同一输入得出不同分位。
- **处理**：按质量门禁第 8 条"双端一致"，改算法后跑同值校验：同一份 `result.json` 分别走 `nwc_calc.py` 与互动版 JS，比对净资产与分位是否一致；不一致即回退修复，两处算法对齐后才交付。
- **结论**：双端同值通过后交付，并在版本沿革中记录本次算法变更。
- **要点**：①互动版 JS 与脚本算法必须一致；②改后必跑同值校验；③算法变更进 CHANGELOG。
