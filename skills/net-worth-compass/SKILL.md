# 身价罗盘（Net Worth Compass）

把零散资产变成一份能直接打开、能随手改的净值报告，并在全国 / 省 / 市 / 县四级上回答：**这个数字，排在前百分之几。**

## 一、它解决什么

1. **归集**：资产条目可手动增删改，自动归入标准大类，算出净资产
2. **估价**：房产输入小区名 → 自动匹配参考单价 × 面积 = 估值，一键填入
3. **定位**：全国 3,421 个地区任选，算四级分位
4. **出图**：自包含 HTML，改数即刷新，可转发、可打印

## 二、适用边界

**适用**
- 个人 / 家庭资产盘点与净资产估值
- "我的财富在大盘里大概处在什么位置"、"同样的钱在西安和在深圳分别排多少"
- 房产快速估值（按小区名匹配参考单价）
- 输入形式：结构化 JSON、Excel/CSV 清单、手写清单、银行 App 资产截图

**不适用**
- 真实个人财富排名查询（个人财富属隐私，无个人级榜单）
- 企业估值、并购定价（用投资类技能）
- 投资建议、税务筹划、法律意见

| 用户说 | 走哪条路径 |
|---|---|
| 我身价多少、家底多少 → 净资产归集路径 |

## Phase 0｜估值前校验（未过不进主流程）

| 检查项 | 通过标准 | 未过动作 |
|---|---|---|
| 资产清单 | 房产/车辆/存款/理财/公积金/股权/应收款逐项列明 | 补齐后估值 |
| 负债清单 | 房贷/车贷/消费贷/信用负债逐项列明 | 补齐后算净值 |
| 口径基准 | 按市价还是成本价估值明确 | 明确后统一口径 |
| 房产信息 | 小区名称、面积、房龄明确 | 补齐后估价 |
| 分位口径 | 全国/省/市/县区定位层级明确 | 明确层级 |

🔴 检查点：任一检查项未过，先补齐再估值。

## 确认门

资产清单与估值口径确认后暂停，将归集表提交用户确认，确认后再出具分位定位报告。

## 三、工作流

### 第 1 步 · 采集
读取资产来源，逐项登记「名称 + 金额 +（可选）类别」。截图类输入先逐项转写金额，**逐条复核数字位数**（如 1,096,100 不要读成 109,610）。
互动版中用户可直接在页面上增删改资产，无需回到脚本。

### 第 2 步 · 分类归集
按八大类归集，负债单列：

| 大类 | 归入项 |
|---|---|
| 房产 | 住宅、商铺、车位、写字楼 |
| 车辆 | 汽车、摩托车 |
| 现金存款 | 银行存款、活期/定期、支付宝、微信零钱 |
| 理财投资 | 理财、基金、股票、债券、保险、黄金 |
| 公积金 | 住房公积金账户 |
| 股权出资 | 公司股权、出资额 |
| 应收借出 | 借出款、应收款 |
| 其他资产 | 无法归类的 |

**去重提醒**：公积金既是"账户"也可能被算进"存款"，二者只能择一。

### 第 3 步 · 房产估价（可选）
输入小区名 → 匹配 `assets/housing.json` → 得参考单价 → × 建筑面积 = 估值 → 填入资产表。
匹配顺序：**精确同名 → 包含匹配（取最短名）→ 用所选地区的区县均价 → 手动填单价**。

### 第 4 步 · 计算
```
净资产 = 总资产 − 总负债
```

### 第 5 步 · 定位与出图
调用计算引擎得四级分位；生成 HTML（静态版 / 互动版）。

## 四、指令

```bash
# 1. 计算（内置测试数据）
python3 scripts/nwc_calc.py --demo --out result.json

# 2. 计算（真实清单）
python3 scripts/nwc_calc.py --input assets.json --out result.json --region 610115

# 3. 生成 HTML（静态版）
python3 scripts/nwc_html.py --input result.json --out report.html

# 4. 生成 HTML（互动版：可改资产、可小区估价、可换地区）
python3 scripts/nwc_html.py --input result.json --out report_interactive.html --interactive

# 5. 地区基准批量导入 / 全国重构
python3 scripts/build_regions.py --csv regions.csv --merge
python3 scripts/gen_national.py
```

**输入 JSON 模板**：

```json
{
  "owner": "某某",
  "region_code": "610115",
  "scope": "家庭",
  "assets": [
    {"name": "某某小区房产", "value": 1096100},
    {"name": "公积金", "value": 302000},
    {"name": "某银行储蓄", "value": 120000}
  ],
  "liabilities": [
    {"name": "房贷", "value": 0}
  ]
}
```

## 五、基准库

| 文件 | 内容 |
|---|---|
| `assets/baseline.json` | 3,421 个地区（31 省 + 334 地级市 + 3,056 县区），含收入比 / 密度比 / coef / 户数 |
| `assets/housing.json` | 房价参考库：小区库 + 60 个地区均价（元/㎡，2025—2026 挂牌参考） |
| `scripts/data/pca-code.json` | 全国行政区划骨架 |

- 收入统一采用**居民人均可支配收入**（全国基准 43,377 元）
- 地区系数 `coef = √(收入比 × 密度比)`
- 房产估价单位：元/㎡，数据可自行扩充 `housing.json`

**精度分层**（必须在报告中如实说明）：

| 层级 | 数据基础 | 精度 |
|---|---|---|
| 全国 | 胡润锚点 + 央行中位数 | 较可靠 |
| 陕西省 / 西安 / 某市等 25 条 | 胡润实测密度 + 统计局真实收入 | 较可靠 |
| 其余 30 省 | 统计局 2025 真实居民收入【估密度】 | 中等 |
| 其余地级市 / 县区 | 省级收入 × 城市等级系数代理【估】 | 粗估，仅供量级参考 |
| 房价 | 挂牌参考价（会随行情变动） | 参考，非成交价 |

## 六、质量门禁

🔴 **1 数据溯源**：每一笔金额注明来源（截图 / 清单 / 用户口述）。
🔴 **2 口径声明**：报告必须写明「个人 or 家庭」「含 or 不含负债」。
🔴 **3 免责声明**：HTML 必须保留"统计近似、非真实排名"声明。
🔴 **4 地区校验**：`region_code` 未命中基准库时只出全国口径并提示。
🔴 **5 数字格式**：金额千分位；分位两位小数；单位统一为元。
🔴 **6 待核标注**：代理值、未核实值一律标【估】【待核】。
🔴 **7 房价免责**：房产估值为挂牌参考，须提示"非成交价、以实际为准"。
🔴 **8 双端一致**：互动版 JS 与 `nwc_calc.py` 算法必须一致，改后跑同值校验。
🔴 **9 精度分层披露**：涉及地级市 / 县区分位时，提示"该级为代理估算"。

## 七、失败模式

1. **把统计分位说成真实排名** → 必须带免责声明，统一用"约前 X%"
2. **分母用错**（人口 vs 家庭户）→ 分位偏差数倍 → 固定用家庭户数
3. **代理值当实测值** → 省市县代理层必须标【估】
4. **资产重复计入**（公积金/存款重复）→ 归集后逐类复核
5. **负债漏计** → 主动询问房贷、车贷、消费贷、信用卡
6. **小区名匹配错**（"万科金域东郡"命中"三期"）→ 精确同名优先，其次取最短匹配
7. **房价当成交价** → 标注"挂牌参考，非成交价"
8. **高端外推失真**（净资产 > 1 亿元）→ 标注"仅作量级参考"
9. **前后端算法漂移** → 改算法后跑同值校验
10. **口径混用**（城镇 vs 全体）→ 全库统一用居民人均可支配收入

## 八、反例黑名单

- ❌ 宣称"你在全国排第 X 名"——只能说"约前 X%"
- ❌ 把地级市 / 县区的代理估算当作实测结果对外
- ❌ 把挂牌参考价说成成交价
- ❌ 无基准数据仍输出该级分位
- ❌ 编造未经核实的榜单数字
- ❌ 未经许可把用户资产数据写入公开渠道

## 依赖与失败模式

- 关键依赖：仅 Python 标准库
- 失败模式与防护：assets 每项须含 name 与合法数值 value；字段不符时中止并退出码 2（修复前会静默按 0 资产计算并输出「前 99%」，属危险假输出）。
- 原则：依赖缺失或输入非法时**显式报错并非零退出**，绝不静默降级，也绝不输出空结果或假结论。

## 固定输出模板（净资产报告字段）

| 字段 | 口径 |
|---|---|
| 资产归集表 | 类别、标的、估值、估值方式 |
| 负债归集表 | 类别、余额、月供 |
| 净资产 | 资产合计 − 负债合计 |
| 分位定位 | 全国/省/市/县区四层分位 |
| 结构分析 | 各类资产占比与流动性分层 |
| 口径说明 | 估值时点与取值依据 |

## 输出质量规范

- **口径标注与缺口显性化**：每项资产标注估值方式（市价/成本价/询价）与时点；无法核实的估值标【待核：需现场评估】。分位定位须注明为统计近似值。
- **事实与判断分离**：资产估值、负债余额属事实段；"处于什么水平"属判断段，以「判断：」起头并注明分位为统计近似而非真实排名。
- **风险与免责提示**：个人财富属隐私，市面无个人级真实排名，分位结果为统计近似，不构成投资与税务筹划意见。

## 交付附加与迭代

交付时按需追加：变更提示（如房价波动、贷款余额变化）、要点归纳（3—5 条，如流动性短板、负债占比）、下一步动作（可执行项，如补充应急储备）。

多轮迭代：交付后说明可调整维度（估值口径／层级／资产增减），指定后直接改。

## 端到端示例（归集与净值节选）

```
资产：自住房（市价口径）2,600,000｜车辆（折价）78,000｜存款 120,000
      理财 260,000｜公积金 85,000｜应收款 30,000
资产合计：3,173,000
负债：房贷余额 1,150,000｜车贷 0｜消费贷 0
负债合计：1,150,000
净资产：2,023,000
结构判断：房产占比 81.9%，流动性资产（存款+理财）占比 12.0%
```

## 适用范围与分流

本技能处理个人与家庭净资产归集与分位定位。以下场景不适用于本技能，应改用对应技能：

- 需要企业估值与并购定价 → 应使用 `investment-financial-model`
- 需要保险保障缺口分析 → 应使用 `insurance-policy-decoder`
- 需要个税汇算与扣除核对 → 应使用 `tax-finance-butler`
- 需要债务清偿可行性评估 → 应使用 `debt-payoff-calculator`
- 需要门店或摆摊选址 → 应使用 `store-site-selection`
