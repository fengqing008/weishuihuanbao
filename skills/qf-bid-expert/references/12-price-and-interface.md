# 报价环节与评分响应表接口

> 来源：招标投标法与实施条例、政府采购法及实施条例、财政部令第 87 号、财库〔2014〕214 号，以及某环保上市公司资料库中某市水环境治理 PPP、某特许经营项目、某城区污水处理厂委托运营、某污水处理厂B等招标文件的报价章节。法规条文以现行有效版本为准。
>
> 权威源说明：本件负责「报价评分办法解析与报价响应衔接」；技术标写作见 `02-technical-bid.md`，商务标材料见 `03-commercial-bid.md`，评分拆解与响应表范式见 `04-scoring-response.md`，报价测算须联动造价技能（见第五节）。

---

## 一、报价环节的定位与边界

- **本技能做**：解析招标文件的报价评分办法（分值、基准价规则、扣分规则、限价、成本价条款、报价形式），推演得分敏感性，编制报价复核清单，生成可直接并入评分响应表的报价响应条目，把关报价类废标情形。
- **本技能不做**：工程量计算、综合单价分析、成本测算、调价测算、限价测算 —— 一律联动造价技能（`zaojia-dinge` / `cost-estimator`）。
- **判界标准**：凡涉及「算出多少钱」，走造价技能；凡涉及「按规则得多少分、材料怎么摆、废标怎么避」，走本技能。

常用命令：

```bash
python3 scripts/price_scoring_helper.py --file 招标文件.md --out 报价核对表.xlsx
python3 scripts/price_scoring_helper.py --file 招标文件.md --base 0.83 --price 0.80 --out 报价核对表.md
# 把报价条目自动并入响应表（无需手工复制粘贴）
python3 scripts/scoring_response_generator.py --merge --response 响应表.xlsx \
        --price-rows 报价核对表.xlsx --out 响应表_含报价.xlsx
```

脚本输出为 .md（单文件）或 .xlsx（按节分表：摘要／敏感性／推演／复核清单／响应条目／接口）。

## 二、报价评分四种常见得分形态与应对

> 与 `04-scoring-response.md` 的「三种报价评分公式」互为补充：04 件按**计算公式**分类（均值法、区间归一法、低价优先法，对应四个项目实件），本件按**得分形态**分类（四种），两套口径不冲突，使用时以招标文件原文表述为准。

| 口径 | 典型表述 | 得分特征 | 应对要点 |
|---|---|---|---|
| 最低价满分制 | 投标报价最低的为评标基准价，得满分，其余按比例扣分 | 低价优势直接兑现 | 先核成本底线与低价否决风险，再定是否压价 |
| 基准价扣分制 | 以有效报价平均值（或下浮若干）为基准价，每高/低 1% 扣 X 分 | 越靠近基准价得分越高 | 用敏感性表找「得分洼地」，避免离群报价 |
| 分档制 | 报价在 N—M 元区间得 X 分，逐档递减 | 存在台阶效应 | 尽量落在高档区间内并留安全边际 |
| 公式制 | 报价得分 = 满分 ×（1 - \|报价-基准价\|/基准价 × 调整系数） | 连续扣分 | 按公式直接推演边界值 |

> 基准价多在开标后依有效报价计算，属于事后变量；使用时按「规则推演」表述，不作确定性结论。
> 敏感性表仅在「每高/低 X% 扣 Y 分」式规则下自动生成；分档制、公式制与最低价满分制需按公式手工推演。

## 三、得分敏感性表怎么用

1. 运行脚本得到「每高/低 1% 扣 X 分」与偏差 0—5% 的得分数列（表内已标注该行适用的偏差方向，禁止跨方向套用）。
2. 与造价技能给出的**成本底线**对照，确定可承受的最低报价区间。
3. 标出两个红线：一是**低于成本**（工程口径触发否决），二是**超限价**（触发否决）。
4. 将推荐区间交由造价岗出报价，本技能只负责「区间与得分」的对应关系。

## 四、报价复核清单（递交前逐项勾选）

| 类别 | 核查项 | 不满足的后果 |
|---|---|---|
| 限价 | 报价不超过最高投标限价（工程）／采购预算或最高限价（政府采购） | 超限价：工程按《招标投标法实施条例》第五十一条第（五）项否决投标；政府采购按采购文件规定的无效响应情形处理 |
| 唯一性 | 只提交一个有效报价且报价唯一 | 多方案报价未声明主选方案作无效处理 |
| 成本价（工程） | 报价不低于成本 | 低于成本报价的，评标委员会应当否决其投标（《招标投标法实施条例》第五十一条第（五）项） |
| 成本价（政府采购） | 不存在明显低于其他通过符合性审查投标人报价的情形 | 须在评标现场合理时间内提供书面说明，不能证明报价合理性的作无效投标处理（财政部令第 87 号第六十条） |
| 大小写 | 报价大写与小写金额一致 | 不一致且无法认定时按不利解释处理 |
| 一致性 | 报价汇总表与分项报价表合计一致 | 分项加总与总价不符即被质疑 |
| 完整性 | 报价含全部费用，未漏项、未另加条件 | 漏项视为已包含在总价内 |
| 有效期 | 报价在投标有效期内固定不变 | 投标有效期内不得调整报价 |
| 电子标 | 电子标报价文件与上传件内容一致 | 不一致以招标文件规定为准 |

## 五、与造价技能的交接接口

- **何时交接**：需要工程量、综合单价、成本、调价、限价测算时。
- **交什么**：招标文件清单与计价要求、最高投标限价或控制价、项目规模与工艺方案、拟报价策略与目标得分区间。
- **回什么**：分项报价表、综合单价分析表、报价汇总表、报价合理性说明。
- **填哪里**：回填《报价表》与报价响应条目，并同步更新评分响应表中的报价行；报价复核清单逐项勾选留痕。
- **不回什么**：不把测算过程文件直接编入投标文件；对外只提交报价表与说明。
- **无造价支持时**：由造价岗或造价软件出具；本技能不出具测算结论，仅提供「规则—得分」对应关系。

## 六、报价类废标情形与法规依据（工程口径 / 政府采购口径分列）

**工程招标口径**

1. 报价高于最高投标限价，或低于成本：**评标委员会应当否决其投标**——《招标投标法实施条例》第五十一条第（五）项「投标报价低于成本或者高于招标文件设定的最高投标限价」。
2. 招标人设有最高投标限价的，应在招标文件中明确最高投标限价或者其计算方法，且**不得规定最低投标限价**——《招标投标法实施条例》第二十七条第三款。
3. 投标人不得以低于成本的报价竞标，也不得以他人名义投标或者以其他方式弄虚作假骗取中标——《招标投标法》第三十三条（禁止性规定；评标环节的否决依据为上述第五十一条第（五）项）。

**政府采购口径**

4. 报价明显低于其他投标人报价：评标委员会认为投标人的报价明显低于其他通过符合性审查投标人的报价，有可能影响产品质量或者不能诚信履约的，应当要求其在**评标现场合理的时间内**提供书面说明，必要时提交相关证明材料；投标人**不能证明其报价合理性**的，评标委员会应当将其作为**无效投标**处理——财政部令第 87 号第六十条（仅货物与服务项目适用；工程口径无同款，仅按低于成本处理）。
5. 投标报价超过采购文件规定的最高限价，或超过采购预算且未获批准的，按采购文件规定的无效响应情形处理。

**两口径共同**

6. 未按格式填报、关键字迹模糊无法辨认、大写小写不一致且无法认定的，按招标文件规定的否决或无效情形处理。
7. 报价含附加条件或对报价作可调整声明的，构成对招标文件的实质性偏离，易被否决。

## 七、报价响应条目写法（并入五列响应表）

报价行的响应情况建议写法：

> 完全响应：投标报价。报价不超过最高投标限价，唯一报价且大小写一致，已包含全部费用无漏项，附报价合理性与成本说明；报价明细见《报价表》与报价说明。

报价行由脚本自动并入，不再依赖手工粘贴：

```bash
python3 scripts/scoring_response_generator.py --merge --response 响应表.xlsx \
        --price-rows 报价核对表.xlsx --out 响应表_含报价.xlsx
```

- 响应表中已有报价行：脚本定位报价行并填充响应情况与响应位置（保留既有内容以外的列不动）。
- 响应表中无报价行：脚本在末尾追加一行并自动续编号，出处列标「报价核对表」。
- 报价条目来源：`报价核对表.xlsx` 的「响应条目」表（推荐）、`.csv`，或 `.md` 中的「报价响应条目」一节。

响应位置填写《报价表》与报价说明所在章节页码，便于评委定位。

口径提示：脚本生成的响应表骨架另含「原文出处(行号)」辅助列（不属于五列范式本身，仅用于回查）；粘贴报价条目时对应前五列，出处列留空即可。

## 八、常见失分点（自查）

1. 报价表与分项明细表数字口径不一致，被质疑不一。
2. 大写金额与小写金额不一致，未在签章前逐字校对。
3. 漏计某项费用（如税费、污泥处置费），被认定为漏项或低价。
4. 报价超限价未在递交前复核（限价口径含税/不含税易混）。
5. 报价说明缺少成本构成，遇异常低价质疑无法当场举证。
6. 电子标上传件与签章纸质件版本不一致。

## 九、检查点

- 报价不超限价、唯一、大小写与分项合计一致（硬性）。
- 报价不低于成本底线，且备有成本说明（硬性）。
- 得分敏感性表已与造价技能的成本底线对照（过程证据）。
- 报价响应条目已由 `--merge` 自动并入评分响应表，且覆盖度校验报告「报价行校验: PASS」（交付证据）；报价行未并入或未填写时，覆盖度校验会直接判 FAIL 并给出合并命令，不再依赖人工确认。
