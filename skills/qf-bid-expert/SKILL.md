## 〇、快速开始卡（一页）

> 执行前先进入技能根目录（`cd skills/eco-bid-expert`），招标文件放当前目录或用绝对路径。

**最短路径**：预处理输入 → 排查红线 → 拆评分 → 响应表+覆盖度 → 成稿 → 排版出目录 → 质检。

```bash
# 0) 输入预处理：PDF / DOC / DOCX / TXT → md（图片型 PDF 走 OCR 技能）
python3 scripts/tender_input_prep.py --file 招标文件.pdf --out 招标文件.md
# 0.5) 编标计划：按递交截止日倒排四阶段（抓不到日期时用 --deadline 指定）
python3 scripts/bid_plan_builder.py --file 招标文件.md --out 编标计划.xlsx
# 1) 废标红线排查
python3 scripts/bid_red_line_checker.py --file 招标文件.md --out 废标核查表.xlsx
# 2) 评分办法拆解（分值附原文行号）
python3 scripts/scoring_matrix.py --file 招标文件.md --out 得分点清单.xlsx
# 3) 评分响应表 + 覆盖度校验（先逐条填响应情况/响应位置，再校验；空表不合格）
python3 scripts/scoring_response_generator.py --file 招标文件.md --out 响应表.xlsx
python3 scripts/scoring_response_generator.py --coverage --file 招标文件.md --response 响应表.xlsx
# 3.5) 报价评分解析与报价复核（测算联动造价技能；--base/--price 可推演得分）
python3 scripts/price_scoring_helper.py --file 招标文件.md --out 报价核对表.xlsx
# 3.6) 报价条目自动并入响应表（无需手工复制粘贴）
python3 scripts/scoring_response_generator.py --merge --response 响应表.xlsx --price-rows 报价核对表.xlsx --out 响应表_含报价.xlsx
# 4) 骨架 → 成稿 → 排版挂大纲出目录（技术标）
python3 scripts/bid_book_builder.py --type technical --project "XX项目" --out 技术标.md
python3 scripts/bid_docx_formatter.py -i 技术标.md -o 技术标.docx --type technical
python3 scripts/bid_docx_formatter.py --verify 技术标.docx
# 4b) 商务标（命令同上，--type 换 commercial）
python3 scripts/bid_book_builder.py --type commercial --project "XX项目" --out 商务标.md
python3 scripts/bid_docx_formatter.py -i 商务标.md -o 商务标.docx --type commercial
python3 scripts/bid_docx_formatter.py --verify 商务标.docx
```

**三个高频脚本**：`bid_red_line_checker.py`（防废标）、`scoring_response_generator.py`（对分）、`bid_docx_formatter.py`（出目录）。
**五个关键检查点**：① 覆盖度校验 PASS（未覆盖=0）② 主体信息一致 ③ 报价未超限价 ④ 标题挂 Heading 1/2/3 且目录可更新 ⑤ 法规名与文号逐条核验。
**样例**：`examples/sample-tender.md`（行式可跑样例）、`examples/sample-tender-table.md`（前附表式评分办法）、`examples/sample-price-scoring.md`（报价评分办法与限价，独立样例不与主样例合并）、`examples/example-technical-bid-section.md`（第一、二章：项目理解、运行维护整体方案）、`example-technical-bid-section-2.md`（第三至六章：设计、建设、移交、法律方案）、`example-technical-bid-section-3.md`（板块二：项目公司组建与管理）——合计覆盖技术标七板块。
**少见场景**：电子标、联合体、非招标方式（竞争性磋商/谈判/询价/单一来源）、开标唱标 → 见 `references/09-compliance-and-modules.md`、`references/11-non-tender-and-onsite.md`。
**没时间看全文时**：本卡 + `07-quality-checklist.md` 第七节映射表 + 三个高频脚本即可完成一次合格投标。

## 专家级路由（v1.4.0）

### 五维评估

| 维度 | 评估内容 |
|---|---|
| 需求识别 | 招标文件是否到手；投标类型（技术标/商务标/双标）；项目模式（PPP/特许经营/委托运营/EPC/BOO）；采购方式（招标/竞争性磋商/谈判/询价/单一来源）；是否联合体；是否资格预审；是否电子投标 |
| 交付边界 | 交付标书骨架与成稿、废标核查表、得分点清单、响应表、报价评分核对表与报价响应条目、编标计划、挂大纲带目录的 Word 标书；不代出报价测算与技术经济指标（报价测算联动造价技能，本技能只做报价评分规则解析、复核清单与响应衔接） |
| 证据来源 | 某环保水务集团 36 件真实材料（清单见 `10-source-register.md`），另附法规依据四层指引 |
| 质量标准 | 过八项质检（废标红线/评分覆盖/主体信息一致/字数/去AI味/排版/格式/输出）+ 法规与术语专项核对 |
| 风险清单 | 废标一票否决；主体信息不一致；业绩不匹配；报价超限价；盖章与清晰度缺漏；法规引证与术语误用 |

### 四级响应（L1-L4）

- **L1 单点问答**：问"废标条款有哪几类""技术标一级标题怎么设"→ 直接作答，引用对应专家件。
- **L2 标准任务**：编骨架、拆评分、做响应表、排版出目录 → 走八步流程的对应子集。
- **L3 复杂任务**：拿到一份招标文件完成全流程成稿 → 走完整八步 + 全部 🔴 检查点。
- **L4 专家任务**：多项目比选、投标策略与资源倒排、多轮答疑澄清、评审口径推演、联合体与电子标方案 → 八步 + 决策规则 + 专家件全量调用。

**黄金窗口**：单项目、单标书。超 3 个项目并行或单册超 10 万字，按分册拆解后逐册推进。

## 一、适用与不适用

**适用**：

- 环保水务类项目的投标文件编制（技术标、商务标、双标）
- 招标文件解读、判法、废标条款排查、评分办法拆解、得分点准备清单
- 法规适用与术语统一、电子投标与联合体投标方案编制
- 技术标骨架搭建与成稿、商务标材料清单化组织
- 非招标采购方式（竞争性磋商/谈判/询价/单一来源）响应文件编制
- 投标保证金与电子保函、开标唱标现场应对
- 投标文件排版、挂大纲、一键生成目录、装订、密封、递交环节核查

**不适用**：

- 报价测算与财务模型（联动 `cost-estimator`、`ppp-financial-model`、`sewage-investment-model`）
- 工程结算与竣工资料（联动 `settlement-audit`、`acceptance-docs`）
- 合同起草与审查（联动 `contract-review-pro`）
- 招标代理业务与评标专家视角的评审打分

## 二、投标全流程八步

按项目实况裁剪步数；L3/L4 任务走完整八步。

### Step 1 判法与招标文件通读（六要素台账）

先按法规适用判断树判明适用《招标投标法》还是《政府采购法》，确认采购方式，再逐条抓取项目概况、资格条件、评标办法、合同条款、格式要求、时间节点六类信息落表。见 `references/01-bid-lifecycle.md` 与 `references/09-compliance-and-modules.md`。

招标文件到手后先做输入预处理，统一为可解析的文本，再进入后续各步：

```bash
python3 scripts/tender_input_prep.py --file 招标文件.pdf --out 招标文件.txt   # 支持 pdf/doc/docx/txt/md
```

加密电子标、图片型 PDF 等无法直接解析的，先解压取文本或用 OCR 技能转文字后再跑本脚本；可跑样例见 `examples/sample-tender.md`。

随后生成编标计划，把递交截止日倒排为四阶段任务与里程碑：

```bash
python3 scripts/bid_plan_builder.py --file 招标文件.md --out 编标计划.xlsx
```

抓不到递交截止时间时用 `--deadline "YYYY-MM-DD HH:MM"` 指定；运行时打印的关键日期为：澄清/修改发出 T-15、对招标文件异议提出 T-10、编制启动 T-20、内部审核 T-10、递交与开标 T（保证金到账日以招标文件规定为准，需人工填入计划）。四阶段模板与提资链见 `references/01-bid-lifecycle.md`。

### Step 2 废标红线排查

把散见前附表、投标人须知、评标办法中的否决性条款，逐条转为"是否满足/证据在哪"的勾选项：

```bash
python3 scripts/bid_red_line_checker.py --file 招标文件.md --out 废标核查表.xlsx
```

脚本按条款分块并做同义扩展，输出 md/csv/xlsx 三种格式；八类高发红线与核查清单见 `references/07-quality-checklist.md`。

### Step 3 评分办法拆解与资源倒排

```bash
python3 scripts/scoring_matrix.py --file 招标文件.md --out 得分点清单.xlsx
```

机抓分值一律标注"待核"，须回招标文件逐条核对分档与例外条款。三种报价评分公式的应对口径见 `references/04-scoring-response.md`。

### Step 4 评分响应表生成与覆盖度校验

```bash
python3 scripts/scoring_response_generator.py --file 招标文件.md --out 响应表.xlsx
python3 scripts/scoring_response_generator.py --coverage --file 招标文件.md --response 响应表.xlsx
```

覆盖度校验输出"未覆盖"清单，未清零不得交付。**填写约定**：响应表的"响应情况"或"响应位置"列须写明对应评审因素名称（如"完全响应：运行维护整体方案，见第二章 2.1 节"）；校验**逐行判定**——先定位该评审因素所在行，再核该行响应列，含因素名称（长度≥3，归一化后）即通过，否则按分词相似度 0.60 判定；两列为空或仅有未填占位（__／待填／待核）时判 FAIL；报价行须已并入并填写（由 `--merge` 自动并入，未并入即 FAIL 并给出合并命令）。五列范式与编制要点见 `references/04-scoring-response.md` 与 `examples/example-scoring-response.md`；成品示例见 `examples/example-response-with-price.md`。

报价行与报价环节接口见 `references/12-price-and-interface.md`：报价评分办法自动解析、得分敏感性表、八项复核清单与报价响应条目，用 `python3 scripts/price_scoring_helper.py --file 招标文件.md --out 报价核对表.xlsx` 生成；报价行由脚本自动识别并标【报价行】，再用 `--merge` 一条命令并入响应表；覆盖度校验会校验报价行是否已并入并填写。报价测算仍联动造价技能，本技能只做"规则与得分"的对应。

### Step 5 技术标成稿

按七板块骨架推进：项目理解与总体筹划 → 项目公司组建与管理 → 设计方案（工艺）→ 建设方案（施工组织）→ 运营方案 → 移交方案 → 法律方案。标准话术取自 `references/05-writing-templates.md`，骨架细则见 `references/02-technical-bid.md`。

```bash
python3 scripts/bid_book_builder.py --type technical --project "XX项目" --out 技术标骨架.md
```

### Step 6 商务标成稿

按六类材料组织：投标核心文件（投标函/承诺书/报价表）→ 主体资格与授权 → 财务税务社保 → 业绩 → 人员与机构 → 声明承诺。若为联合体、电子标或非招标方式，按 `references/09-compliance-and-modules.md` 与 `references/11-non-tender-and-onsite.md` 增补专项材料。清单与范式见 `references/03-commercial-bid.md`。

```bash
python3 scripts/bid_book_builder.py --type commercial --project "XX项目" --out 商务标骨架.md
```

### Step 7 排版、挂大纲、出目录

```bash
python3 scripts/bid_docx_formatter.py -i 技术标.md -o 技术标.docx --type technical
python3 scripts/bid_docx_formatter.py -i 商务标.md -o 商务标.docx --type commercial
python3 scripts/bid_docx_formatter.py --verify 技术标.docx
```

技术标与商务标两套排版参数见 `references/08-format-and-outline.md`；正副本分别装订密封、封口骑缝盖章。

技术标大纲字体以**某市某水务集团城区污水处理厂投标文件（第二册）**为准：一级黑体三号居中，二级至四级黑体小四左顶格，五级宋体小四左顶格（详见 `references/08-format-and-outline.md` 第一节）。

### Step 8 交付前八项质检

跑质检清单：废标红线、评分覆盖、主体信息一致、字数、去AI味、排版、格式、输出；另按 `references/09-compliance-and-modules.md` 核对法规适用与术语口径。见 `references/07-quality-checklist.md`。

## 三、核心框架

### 框架 1 招标文件六要素台账

**一句话**：任何招标文件都拆成六类信息落表，缺一类就是风险敞口。

**来源证据**：吴忠市水环境治理 PPP 招标文件、大同御东特许经营招标文件、某市城区/三层岩委托运营招标文件四份实件对照。

**应用方式**：项目概况、资格条件、评标办法、合同条款、格式要求、时间节点各建一行，逐栏填实。资格条件与时间节点两栏最易致废标。

**局限**：PPP 与特许经营项目另有资本金、融资、联合体、人员安置等特殊项，须单列。

### 框架 2 废标红线八类排查

**一句话**：否决性条款散落在多章，必须按八类归集后逐条勾选。

**来源证据**：四份招标文件中否决条款的归类统计。

**应用方式**：优先盯防四类高发点——超限价或多报价、资格证明缺项或截图时间不符、未按要求密封签署、实质性响应缺失（照抄招标技术要求即属虚假响应）。

**局限**：招标人最后一刻发出的澄清/修改文件可能新增或改变条款，须以最新书面文件为准。

### 框架 3 评分办法拆解与资源倒排

**一句话**：先算每类需求在总分中的可争取空间，再决定标书编制的用力方向。

**来源证据**：四项目评分构成——PPP 项目技术30+商务25+财务10+法律5、报价30；特许经营项目报价独占50；委托运营项目技术65~70、报价仅10~15。

**应用方式**：报价仅占 10 分的项目，主力放在 70 分技术方案与 20 分业绩资质。机抓分值与人工核对双轨，机抓值标"待核"。

**局限**：报价分的算法（均值法/区间归一法/低价优先法）决定报价策略方向，须先确认算法再定策略。

### 框架 4 评分响应表五列范式

**一句话**：五列表把评分标准逐条锚定到标书章节，让评委照表找证据。

**来源证据**：吴忠投标第二册/第三册响应表、大同御东评分标准响应表。

**应用方式**：评分标准分档全列；响应情况只锚定最高档措辞；可量化处给硬指标；响应位置精确到册-章-节。用 `scoring_response_generator.py` 出骨架、`--coverage` 校验覆盖。

**局限**：分档未列全会漏项；响应位置指错章节等于没响应。

### 框架 5 技术标七板块骨架

**一句话**：技术标按七板块搭骨架，各板块有固定二级子目可复用。

**来源证据**：泰兴、如东、舟山、龙海、湘阴、海陵、标段三、某市八份技术标共性结构。

**应用方式**：项目理解与总体筹划 → 项目公司组建与管理 → 设计方案 → 建设方案 → 运营方案 → 移交方案 → 法律方案。工艺方案按"设计依据→设计原则→设计参数→去除率表"四段式，并对每个工艺段做方案比选后给推荐结论。

**局限**：委托运营类项目无建设方案板块；PPP 与特许经营项目须补资本金与融资章节。

### 框架 6 商务标六类材料清单

**一句话**：商务标材料按六类清单化管理，责任到人、倒排到日。

**来源证据**：某市生物医药产业园项目商务及证明材料分类清单、大同御东编制计划、投标书模版。

**应用方式**：投标核心文件、主体资格与授权、财务税务社保、业绩、人员与机构、声明承诺六类逐项建表，标注招标文件依据、格式要求、责任人、完成时间。

**局限**：各招标文件对声明函附件编号与格式要求不同，须回原文件比对模板。

### 框架 7 运营方案八段式

**一句话**：运营方案按八段展开，目标、组织、制度、措施、考核逐环咬合。

**来源证据**：华谊钦州运营方案（母版）、如东二期、碧湖、舟山、中山河涌、某水务集团运营管理体系。

**应用方式**：运营总则与目标 → 组织架构与岗位职责 → 生产运行管理 → 水质质量保障 → 设备与管网运维 → 成本控制与绩效考核 → 安全环保应急 → 智慧运维与移交。水质目标必落"达标率100%"并注明执行标准；应急必配四级分级+四色预警+专项预案清单。

**局限**：工业废水与流域河网项目的工艺控制与水质指标口径不同于市政污水，须按项目类型替换。

### 框架 8 大纲挂接与一键目录

**一句话**：标题按大纲级别挂样式，目录以域插入，交付即可一键更新。

**来源证据**：舟山与海陵两标格式规范中的标题层级与样式表设计。

**应用方式**：文档标题挂 Title（不进目录）；一/二/三级标题分别挂 Heading 1/2/3（大纲级别 0/1/2）；在标题页后插入 `TOC \o "1-3" \h \z \u` 域并设 `w:updateFields=true`。

**局限**：LibreOffice 转 PDF 不自动更新目录域，交付 docx 时须提示"打开后更新域"。

### 框架 9 法规适用与术语统一

**一句话**：先判法再编标，术语按招标文件原词书写。

**来源证据**：四份招标文件条款表述与现行《招标投标法》《政府采购法》及其实施条例的通行口径；文号与施行日期见 `10-source-register.md`。

**应用方式**：按"采购主体 + 资金性质 + 项目性质"判明适用法律；资格条件承诺书按项目类型引《政府采购法》第二十二条或《招标投标法》相应资格要求；否决性表述严格沿用招标文件原词（否决投标/废标/无效投标/不予受理）。

**局限**：政府采购工程存在两法衔接与监管分工问题，须按项目实际与监管部门认定；条款编号不能确定的，标书内标【待核：条款编号】。

## 四、决策规则

| 条件 | 处置 |
|---|---|
| 采购主体为机关事业单位且用财政性资金 | 适用《政府采购法》，资格条件引第二十二条 |
| 项目为工程建设项目 | 适用《招标投标法》及其实施条例 |
| 采购方式为竞争性磋商 | 允许磋商后实质性调整与最后报价，响应文件按磋商口径编制 |
| 采购方式为竞争性谈判或询价 | 谈判有一次最后报价；询价只报一次不得更改 |
| 报价分值 ≥ 40 分 | 报价策略权重前移，先确认评分算法再定报价区间 |
| 报价分值 ≤ 15 分 | 主力投技术方案与业绩资质，报价取稳妥值 |
| 技术标占 60 分以上 | 工艺方案逐段比选并给推荐结论，重难点写成技术诊断书 |
| 招标文件出现"照抄技术要求视为虚假响应" | 禁止整段复制招标要求，须改写为响应式表述 |
| 招标文件要求电子投标 | 核对 CA 证书有效期、加密与不加密标书内容一致、电子章齐备 |
| 招标文件允许或要求联合体 | 签共同投标协议，明确牵头方与分工，逐条核对资质与业绩认定口径 |
| 收到澄清或修改文件 | 逐份比对，时间节点顺延后重排编标计划 |
| 资格证明含"信用中国截图" | 截图须在公告发布日之后截取，并加盖鲜章 |
| 法定代表人近期变更 | 全部证照、授权书、投标函签字人统一用最新法定代表人 |
| 项目不接受联合体 | 以单一法人主体 + 自有资质响应，资质等级逐项自检 |
| 招标文件未给排版格式 | 技术标套行业基线档、商务标套通用档，并在交付说明中标注 |

## 五、质量门禁与检查点

🔴 **检查点 1 废标红线**：八类否决条款逐条勾选，任一条"不满足"或"证据缺失"，标书不得递交。

🔴 **检查点 2 评分覆盖**：响应表覆盖全部评审因素的全部档次；`scoring_response_generator.py --coverage` 未覆盖项须清零。

🔴 **检查点 3 主体信息一致**：营业执照、资质证书、安全生产许可证、法定代表人身份证明、授权书、投标函的法定代表人姓名与统一社会信用代码逐证核对一致。

🔴 **检查点 4 业绩匹配**：业绩的项目类型、规模、时间全部落在评审口径内，每项附合同或中标通知书扫描件并加盖鲜章。

🔴 **检查点 5 报价合规**：报价不超最高限价、只有一个有效报价、不低于成本价，大小写一致、分项与合计一致。

🔴 **检查点 6 形式合规**：正副本份数、装订方式、密封封口、骑缝章、开标身份核验全部满足；电子标另核 CA 证书与加密标书。

🔴 **检查点 7 大纲与目录**：一/二/三级标题已挂 Heading 1/2/3，导航窗格可见层级；文档含 TOC 域与 updateFields；目录编号与正文编号一致。用 `bid_docx_formatter.py --verify` 校验。

🔴 **检查点 8 法规与术语**：已判明适用法律；资格条件引证条款正确；否决性表述沿用招标文件原词；不确定的条款编号已标【待核】。

🔴 **检查点 9 保证金与现场**：保证金数额不超预算金额 2%、形式与有效期符合要求、汇款信息逐字核对；开标携带身份材料与 CA 锁，现场异议当场提出并取答复记录。

STOP **红线**：以上任一门禁 FAIL，回退重编，不进入下一环节。

## 六、失败模式

投标实务中最常失分与致废标的失败模式如下，交付前逐条比对；每条均给出失败分支的兜底动作与重试路径：

1. **形式性失败：盖章与清晰度缺漏**。复印件未盖鲜章、扫描件缺页或模糊，按"未提供"处理。动作：逐页核对鲜章与扫描清晰度。
2. **资格性失败：证照主体信息不一致**。统一社会信用代码或法定代表人在不同证照上记载不一，授权书签字人与法定代表人未对应。动作：逐证比对后统一。
3. **业绩性失败：业绩口径不匹配**。业绩未落在类似项目口径内，或佐证无法体现项目内容，不计分。动作：按评审口径筛选业绩并备齐佐证。
4. **报价性失败：超限价或恶意低价**。报价等于或超过招标控制价直接无效；报价明显低于平均价且无法说明成本的被判否决。动作：算准报价区间并备好成本说明。
5. **响应性失败：实质性响应缺失**。整段照抄招标技术要求作为投标内容，被认定虚假响应。动作：改写为响应式表述并指向自证材料。
6. **时间性失败：递交环节脱期**。未在截止时间前送达指定地点，或未派授权代理人参加开标并通过身份核验。动作：倒排工期，预留审核审定与打印装订缓冲。
7. **编号性失败：章节与页码错位**。目录编号与正文编号错位、响应表页码栏空白、图表编号重复。动作：成稿后统一编号并回填页码。
8. **地名性失败：项目名与地名串用**。多项目素材拼装致正文混入其他项目地名。动作：全文检索替换并逐一核对。
9. **排版性失败：标题未挂大纲致目录为空**。标题用加粗文本而非 Heading 样式，目录域生成后为空或只显示一条。动作：改用 Heading 1/2/3 挂接，再用 `--verify` 复核后重新生成目录域。
10. **法规性失败：判法错或引证错**。未区分《招标投标法》与《政府采购法》，把资格条件引成《招标投标法》第二十二条（该条为标底保密）；术语混用"废标/否决投标/无效投标"。动作：先判法，按项目类型引对应条款；引证存疑标【待核】并回原文核对。
11. **方式性失败：用错采购方式口径**。把竞争性磋商按公开招标口径编制，缺"最后报价"环节；或询价项目允许多次改价。动作：先确认采购方式，按对应程序组织响应文件与报价。
12. **保证金性失败：数额或形式不合规**。保证金超预算金额 2%、有效期短于投标有效期、汇款信息多字少字。动作：逐项核对上限、形式、有效期与汇款信息，电子保函验真。

## 七、反例清单

以下做法在实务中反复出现且必然失分，明令禁止：

- 反例一：直接沿用其他项目的标书改项目名即投，未重读本次招标文件的资格条件与格式要求。
- 反例二：把招标文件技术要求整段复制进技术标充当应答内容。
- 反例三：评分响应表只写"完全响应"不写具体章节位置，评委无法按图索骥。
- 反例四：证照用旧版（法定代表人未更新），与授权书签字人不一致。
- 反例五：业绩表只填项目名称，不附合同或中标通知书扫描件，或佐证未盖鲜章。
- 反例六：报价表大小写不一致、分项与合计对不上、只提交一个装订本却要求正副多份。
- 反例七：用 WPS 编辑导致格式混乱，或复制粘贴未先经 TXT 中转致格式无法修改。
- 反例八：把成交通知书、履约协议等结果文件混入资格资信材料。
- 反例九：标题仅用加粗与字号区分层级、不挂 Heading 样式，导致导航窗格无结构、目录域生成后为空。
- 反例十：法规引证凭记忆书写（如把资格条件引成《招标投标法》第二十二条），或把"废标"误用于单份投标被否。
- 反例十一：跳过覆盖度校验直接交付响应表，导致漏答评分项。
- 反例十二：保证金未核上限与有效期，或汇款用途多写少写被认定未按规定提交。

## 八、输出模板与交付规范

**标准交付物**：

1. 废标核查表（md/csv/xlsx，含勾选列与证据栏）
2. 得分点准备清单（csv/xlsx，含评审因素、分值、得分点、责任章节）
3. 评分响应表（csv/xlsx，五列范式，附覆盖度校验结果）
4. 技术标骨架（Markdown/Word，七板块 + 各级标题）
5. 商务标骨架（Markdown/Word，六类材料 + 责任人/时限列）
6. 编标计划（Word/Excel，四阶段 + 提资链 + 时间节点）
7. 排版成品标书（Word，标题挂 Heading 1/2/3、含可一键更新的目录域）

**交付规范**：Word 类须挂接 Heading 1/2/3 大纲级别并可按 Word"引用→目录"一键生成目录；金额一律千分位；未核实项标【待核：具体说明】；输出预览完整可读，不以"详见附件"替代。

## 九、运行环境与依赖

| 依赖 | 用途 | 安装 |
|---|---|---|
| Python 3.8+ | 全部脚本 | 系统自带 |
| python-docx>=1.1.0 | 标书 Word 排版、大纲挂接 | `pip install python-docx` |
| openpyxl>=3.1.0 | 核查表/清单/响应表导出 xlsx | `pip install openpyxl` |
| pandoc | Markdown 转 docx（仅处理 .md 输入时需要） | `apt-get install pandoc` |

一键安装：`pip install -r scripts/requirements.txt`

- `bid_red_line_checker.py`、`bid_book_builder.py` 仅用标准库，无需额外依赖
- `scoring_matrix.py`、`scoring_response_generator.py` 输出 csv 无需依赖，输出 xlsx 需 openpyxl
- `bid_docx_formatter.py` 处理 .md 输入需 pandoc；输入已是 .docx 则不需要
- 缺依赖时脚本会给出明确安装提示并退出，不静默失败

**输入准备**：脚本 `--file` 需 txt/md 纯文本。PDF、DOC 与图片扫描件先用文本提取工具转换（如 `textin-xparse`、`anydoc`、`pdfkit`）；`.docx` 可直接用 `bid_docx_formatter.py -i 文件.docx` 调用。无 pandoc 时，先用 Word/WPS 将底稿另存为 `.docx` 再传入，即为降级路径。

## 十一、边界与人工介入

**本技能不做**：

- 不代出报价测算、财务模型、技术经济指标
- 不替代律师出具法律意见、不替代评审专家打分
- 不虚构业绩、资质与证书信息

**须人工确认**：

- 招标文件的澄清与修改文件（以招标人最后书面文件为准）
- 报价区间与让利策略（属经营决策）
- 联合体协议与出资结构（属商务谈判）
- 全部证照有效期与主体信息（须逐证比对最新原件）
- 招标文件对排版的具体要求（格式条款可能覆盖技能默认参数）
- 法规条款编号与适用判断（政府采购工程的两法衔接须按监管部门认定）
- 采购方式变更与保证金形式选择（属采购决策，须与代理机构确认）

## 失败模式与降级路径速查

投标现场最怕“红线踩了还不知道”。下表把常见失败模式、触发信号、降级路径（兜底方案）与补救动作固化，编标途中遇阻先对表；出现异常时先保已定稿的章节不丢，再谈补救。

| 失败模式 | 触发信号 | 降级路径（兜底方案） | 补救动作 |
|---|---|---|---|
| 招标文件解析缺失 | 上传件为扫描件或无文字层 | 降级为人工摘录关键条款，标注【待核：扫描件未解析】 | 补齐文字层后回退重跑解析 |
| 废标红线命中 | 出现★条款未响应、缺实质性材料 | 触发废标拦截，回退到响应表逐条补齐 | 补充材料后重跑 `bid_red_line_checker.py` |
| 评分办法抓取为空 | 报价行、技术分未解析出 | 兜底改用文本兜底通道（正文含报价分即触发门禁） | 人工核对评分因素后重试 |
| 评分响应表出现假 PASS | 一行枚举全部因素名即判过 | 降级为逐行判定（先定位评审因素行，再核该行响应列） | 补真实响应文本后重跑覆盖度校验 |
| 报价低于成本 | 报价核对表报出成本价红线 | 拒绝出价，升级经营决策，不自行让利 | 成本核价确认后再定稿 |
| 法规条款编号过期 | 引用的实施条例已被修订 | 回退到现行有效版本，标注【待核：条款版本】 | 按新增规章补挂否决条款 |
| Word 排版异常 | 标题未挂大纲、目录不更新 | 降级为 Markdown 成稿＋手工套模板 | 重跑 `bid_docx_formatter.py` |
| 长文档生成中断 | 技术标中途截断 | 断点续跑，从最近板块接续 | 校验章节完整性后合并 |
| 多版本口径冲突 | 技术标与商务标数据不一致 | 兜底以招标文件口径为准，全篇回改 | 建立数据口径对照表 |

**降级总则**：任何降级都须写明“降了什么、为什么降、需补什么”，不得以沉默代替风险提示。**异常与错误处理约定**：脚本不可用时 fallback 为人工对照 `references/07-quality-checklist.md` 自检；对空文件、超大表格、编码异常、xlsx 空表等边界条件做容错与防御性校验；任一门禁失败即进入失败分支的降级路径，未通过不得封标交付。
