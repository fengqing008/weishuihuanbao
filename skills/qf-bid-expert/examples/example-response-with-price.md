# 样例：评分响应表（报价行自动并入后的成品）

> 演示 v1.7.x 的机器级打通：响应表骨架由 `scoring_response_generator.py` 生成（自动识别报价类因素并标【报价行】），
> 报价条目由 `--merge` 自动并入（无需手工复制粘贴），再跑 `--coverage` 校验（逐行判定）。
> 本样例的报价条目与响应表骨架同源于 `sample-tender.md`，口径一致（限价 0.83 元/立方米、报价分 15 分）。

## 一、三步命令

```bash
# 1) 生成响应表骨架（自动识别报价类因素并标【报价行】）
python3 scripts/scoring_response_generator.py --file 招标文件.md --out 响应表.xlsx
# 2) 解析报价评分办法并生成报价核对表（xlsx 含「响应条目」表，可被第 3 步直接读取）
python3 scripts/price_scoring_helper.py --file 招标文件.md --out 报价核对表.xlsx
# 3) 自动把报价条目并入响应表
python3 scripts/scoring_response_generator.py --merge --response 响应表.xlsx \
        --price-rows 报价核对表.xlsx --out 响应表_含报价.xlsx
# 4) 覆盖度校验（逐行判定 + 报价行必填）
python3 scripts/scoring_response_generator.py --coverage --file 招标文件.md --response 响应表_含报价.xlsx
```

## 二、合并后的响应表（节选，报价行为自动填充）

| 序号 | 评审因素(含分值) | 评分标准(分档原文) | 响应情况 | 响应位置 |
|---|---|---|---|---|
| 1 | 运行维护整体方案（30分·待核） | 【待核：分档原文】 | 完全响应：运行维护整体方案，详见章节。 | 详见第二章 |
| 2 | 重难点及关键问题分析措施（20分·待核） | 【待核：分档原文】 | 完全响应：重难点及关键问题分析措施，详见章节。 | 详见第二章 |
| 3 | 质量保证体系及措施（5分·待核） | 【待核：分档原文】 | 完全响应：质量保证体系及措施，详见章节。 | 详见第二章 |
| … | （水质自检能力、应急预案、类似项目业绩、项目团队、企业资信等行同法填写） | | | |
| 9 | 报价分（15分·待核）**【报价行】** | 见报价评分办法摘要 | 完全响应：投标报价。报价不超过最高投标限价，唯一报价且大小写一致，已包含全部费用无漏项，附报价合理性与成本说明；报价明细见《报价表》与报价说明（报价数据须先经造价核价确认后定稿）。 | 详见《报价表》及报价说明章节 |

> 第 9 行为 `--merge` 自动并入：脚本定位既有报价行，填充响应情况与响应位置，并在该行分档原文为空或仍为未填占位（如【待核：分档原文】）时同步写入报价核对表中的分档摘要；若响应表本身无报价行，则在末尾追加、自动续编号并在出处列标「报价核对表」。

## 三、覆盖度校验输出（节选）

```
== 覆盖度校验（逐行判定；含名称即通过，否则相似度 0.60）==
报价行校验: PASS —— 报价行 1 行
招标文件评审因素: 9 项（其中报价类 1 项）
已覆盖: 9 项 | 未覆盖: 0 项
结论: PASS
```

反例一：未并入报价行或报价行未填

```
报价行校验: FAIL —— 招标文件含报价分，但响应表无报价行。
  处置：先跑 --merge 并入报价条目（python3 scripts/scoring_response_generator.py --merge --response 响应表.xlsx --price-rows 报价核对表.xlsx --out 响应表_含报价.xlsx）
结论: FAIL（补齐缺失项与报价行后再交付）
```

反例二：仅在一行里枚举全部因素名（意图绕过）

```
  - 缺: 项目团队（6分，0.0）→ 请在该行响应情况中写明该评审因素名称
结论: FAIL（补齐缺失项与报价行后再交付）
```

## 四、判定规则（透明化）

- **逐行判定**：先用评审因素名称定位该行，再核该行响应情况／响应位置是否覆盖；不采用全表交叉匹配，避免在一行里枚举多个因素名而"一次通过全部"。
- **包含即通过**：响应文本中出现该评审因素名称（长度 ≥ 3，含归一化后）即视为已覆盖；否则按分词相似度 0.60 判定。
- **报价行**：招标文件含报价分时，响应表必须存在报价行且两列已填；未并入或未填一律 FAIL 并给出合并命令（即使评审因素解析未标出报价行，只要招标文件文本含报价分，该门禁同样触发）。
- **类别汇总行**（技术分/商务分/财务分/法律分等）不生成响应行，避免把汇总行误当评审因素。
- **空表**：两列均为空或仅有未填占位（__／待填／待核）时直接 FAIL，不给出 PASS 假信号。
- **边界**：本校验只核"是否写明因素名与响应位置"，不核响应位置所指向章节是否真实存在、不核分档是否全列、不核因素清单是否完整；PASS 为必要非充分条件。
