# settlement-sop-generator 案例库（Case Library）

> 本案例库收录 3 个真实作业场景，含背景、做法与结果，供编制结算 SOP 前对照参考。
> 案例脱敏处理：不收录项目代号细节、合同金额与当事人姓名；无法核实的细节标注 `【待核】`。

## 案例 1：某市 PPP 项目竣工结算 SOP（12 章标准结构，源头案例）

- **背景**：污水处理厂及配套管网工程进入竣工结算阶段，施工、设计、监理、建设四方对工程量差异的处理口径与签字顺序长期不统一，返工率高；需要一份可执行、可存档、可审计的结算规程。
- **做法**：采用本技能 12 章标准结构（编制目的与依据 → 适用范围与术语 → 结算基准 → 结算书结构 → 工程量核定流程 → 工程量差异处理 → 结算编制公式 → 签证与材料调差规则 → 必备资料清单 → 报送流程与时点 → 签字盖章与归档 → 附则）；用 `sop_docx_generator.py` 生成 Heading 1/2 挂接的 docx；用 `sop_flowchart_total.py` 出「工程量核对流程」主图、`sop_flowchart_diff.py` 出「差异处理流程」图；四方签字按「管网差异走《工程量确认表》四方确认栏、站点差异走《图纸会审记录》表 D.5、接户管收方走三方现场复核」三套模板分别约定；`sop_quality_check.py` 四项门禁（条款编号连续 / 法规名规范 / 四方签字齐 / AI 味扫描）全 PASS 后入库。
- **结果**：产出 SOP V1.1（docx）+ 2 张模板风格 PNG + 1 个自包含图集 HTML，四件齐备；后续结算争议中因签字顺序有明文依据，四方对签环节返工明显减少，争议件数下降。
- **反思**：流程图中 mermaid 自动布局存在连线回折与节点内特殊字符渲染异常，正式交付改用 matplotlib 精确手绘引擎（零特殊字符）后图面问题消除。

## 案例 2：Y 型瀑布流程图的支线汇聚改造

- **背景**：结算「工程量核定 → 差异判定 → 认定/不予认定」存在多分支汇合，早期 mermaid 版本因连线共线导致歧义，读者误读为串行而非分支。
- **做法**：改用模板风格绘图引擎，主轴垂直居中、三列对称分支、**汇聚线自每个结果框框底引出**（不从列中心引出）再阶梯式汇入总线；配色按语义固定（浅黄判断 `#fff3cd`、浅绿计量结果 `#e6f2e2`、浅红不予认定 `#fbe0e0`）；「是/否」与分支名标注统一置于连线外侧上方，与连线保持 ≥0.15 数据单位间距。
- **结果**：改造后单图 2168×2102 px（dpi 170），可直接插入 Word / PPT；评审时无读者对分支关系提出歧义。
- **反思**：汇聚线引出点与标注位置是流程图可读性的关键边界条件，已固化进绘图规范；换其他流程主题时复制脚本改节点文字即可（布局引擎通用）。

## 案例 3：PNG 渲染失败时的降级交付（降级路径实测）

- **背景**：某次在无 Node.js 与 pretty-mermaid 的环境中编制 SOP，`.mmd` 源已生成，但 PNG 渲染步骤报错。
- **做法**：走降级路径——保留 `.mmd` 源文件，照常生成 HTML 交互页（mermaid.js 内嵌），`manifest.json` 记 `png:*:failed` 与 `degraded` 列表；交付说明中显式标注「已降级：未生成位图」，并给出本地补齐命令；同时为防字体缺失，确认目标环境已装 `fonts-noto-cjk`，未装则提示先安装。
- **结果**：用户在本地环境补齐 PNG 后四件齐备，制度文件与图集页均可正常使用；因降级口径已显式告知，未产生交付争议。
- **反思**：降级不得静默；`manifest.json` 的 `degraded` 字段是后续**断点续跑**（只重跑未完成步骤）的依据，本技能 `scripts/sop_pack_check.py` 会读取该字段并给出告警。
