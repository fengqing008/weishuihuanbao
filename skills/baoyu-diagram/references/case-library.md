# baoyu-diagram 案例库（Case Library）

> 本案例库收录 3 个真实使用场景，覆盖输入、做法与结果，供出图前对照参考。
> 案例来源：Linux 基金会 / ISO 官方文档公开架构图、开源社区实操记录，以及本技能在沙箱内的实测记录（出处见文末）。

## 案例 1：微服务系统架构图

- **背景**：需要向非技术干系人讲清一个电商中台的服务边界与调用关系（网关、用户、订单、支付、库存 + MySQL/Redis 存储）。
- **做法**：选用 Architecture 图型；按 Primary（网关/入口）、Secondary（服务）、Tertiary（存储）语义配色分组；用带标签连线标注协议（HTTP / gRPC / SQL）；外部第三方渠道归入 Neutral 分组；导出前运行 `scripts/diagram_check.py` 校验 viewBox 与分组数量。
- **结果**：输出单片 `microservices-architecture.svg`，节点 14 个、分 4 组，未触发节点超限告警；评审会上一次性通过，无返工。
- **参考出处**：参考 Linux 基金会公开的微服务参考架构描述方式（服务边界 + 数据存储分层）。

## 案例 2：订单流程流程图（含决策分支）

- **背景**：产品经理给了一段 600 字的下单流程文字描述，要求产出可嵌入需求文档的流程图。
- **做法**：抽取步骤与判定点；圆角矩形表步骤、菱形表决策、标注「通过 / 拒绝 / 重试」分支标签；对存在歧义的一处（优惠券校验顺序）在图中以图注标 `【待核：优惠券校验与库存扣减的先后顺序】`，请用户确认后再定稿。
- **结果**：输出 `order-flow.svg`，含 11 个节点、3 个决策点；自检返回退出码 0（通过）。歧义点经用户确认后修订一版，避免了后续开发分歧。

## 案例 3：接口调用时序图（降级路径实测）

- **背景**：需把一次「客户端 → 网关 → 鉴权服务 → 用户服务 → 数据库」的调用画成时序图；沙箱内缺少无头浏览器与位图导出运行时。
- **做法**：按 Sequence 图型绘制竖直生命线与水平消息，加激活条；因缺少运行时，走**降级路径**——跳过 @2x PNG 导出，仅交付 SVG，并在交付说明中显式标注「已降级：未生成位图」；标签过长时换行并放大消息框。
- **结果**：输出 `auth-sequence.svg` 正常可用；位图部分由用户本地 `npx bun` 补齐。该案例验证了「回退方案 + 显式告知降级口径」的容错设计有效。
