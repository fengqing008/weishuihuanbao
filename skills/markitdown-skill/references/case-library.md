# MarkItDown 转换案例库（case-library）

本案例库收录 markitdown 批量转换的典型处置场景，供同类任务套用。
每则案例按「场景 / 处理 / 结论 / 要点」四段呈现；套用时须按实际文件复核，
凡未能实测确认的数值与路径，一律标注【待核】。命令与退出码语义以本案例库为参照。

---

## 案例一　合同目录批量转 Markdown 供条款检索

- **场景**：一个装有 N 份（【待核：实际份数】）`.docx` 合同的目录，需要转成 Markdown 后按关键词定位条款。
- **处理**：先跑 `python3 scripts/md_convert.py --input /data/contracts --outdir /data/contracts_md --log convert.log`，再 `python3 scripts/md_check.py --dir /data/contracts_md --require-heading 1` 校验非空与标题落地，最后 `grep -rn "违约金" /data/contracts_md/` 定位。
- **结论**：交付 `.md` 集合 + 运行日志 + 质检报告三件；命中位置回填审查底稿。
- **要点**：①先干跑 `--dry-run` 盘点件数；②标题层级与表格须抽查；③产物未过闸门不得落库。

## 案例二　扫描件 PDF 无文字层（失败模式 2）

- **场景**：用户上传扫描版 PDF，`markitdown scan.pdf > scan.md` 输出为空或仅含元数据。
- **处理**：判定为纯图片扫描件且未配置 OCR 服务；按失败模式 F2 走 OCR 取得文字层后再转换；若无 OCR 通道，标注"需人工处理"，**不得交付空文件**。
- **结论**：先补文字层再转；空产物一律视为失败交付，须回退并说明。
- **要点**：①空文件是不可接受的失败交付；②OCR 未配置时如实告知，不静默通过；③来源与通道在交付说明中注明。

## 案例三　GBK 中文文档乱码（失败模式 5）

- **场景**：中文源文件为 GBK 编码，转换输出乱码或抛 UnicodeDecodeError。
- **处理**：先 `iconv -f GBK -t UTF-8 source.txt > source_utf8.txt` 转码，再重新转换；转码后复跑 `md_check.py` 确认无 U+FFFD、无 BOM 残留。
- **结论**：编码问题在入口修复，出口只做校验；交付时标明已转 UTF-8。
- **要点**：①编码检查优先级链由 text-io 承担，本技能只管乱码后的返工；②不允许跳过编码检测直转；③返工只重跑乱码件。

## 案例四　超大文件内存溢出（失败模式 7）

- **场景**：单份 >100MB 的 PDF/Excel，一次性加载被 OOM Killer 终止。
- **处理**：按失败模式 F7 先 `pdftk large.pdf cat 1-50 output part1.pdf` 拆页（Excel 按工作表拆），逐件转换后**对账件数**，确认无遗漏。
- **结论**：以「拆分 → 逐件转换 → 件数对账 → 合并」闭环，交付合并 Markdown 与拆分清单。
- **要点**：①单文件 >100MB 不得一次性加载；②件数对账是硬检查；③断点续跑只补失败分片。

## 案例五　脚本依赖缺失时的零依赖兜底（失败模式 1）

- **场景**：环境无 `markitdown` 命令且无法 `pip install`，任务含若干 `.txt/.csv/.html`。
- **处理**：触发失败模式 F1，**回退到本技能零依赖脚本** `md_convert.py` 处理纯文本类文件（`.txt/.log/.html/.htm/.csv`），PDF/Office 类分流到 anydoc 或 textin-xparse；在交付说明中标注所用兜底通道。
- **结论**：尽力覆盖可处理部分，其余分流并列明依赖缺口，不隐瞒未覆盖件。
- **要点**：①兜底脚本只覆盖纯文本类；②未覆盖件须单列并给替代路径；③异常与错误处理均写入运行日志。

## 案例六　加密文档与 ZIP 嵌套（失败模式 6 / 9）

- **场景**：一组资料中含带密码的 Office 文档与嵌套子 ZIP。
- **处理**：加密文档按 F6 不做暴力破解，解密另存可读副本再转，无法解密时终止该项并记录"待人工授权"；嵌套 ZIP 按 F9 先递归解压再批量转换。
- **结论**：两项均以「先解阻再转」处理，交付清单中逐项标注状态。
- **要点**：①严禁越权解密（红线）；②嵌套包不递归，须先解压；③失败项留痕可追溯。

涉及用户文档的，一律本地处理，文件不出本机。参考来源：microsoft/markitdown 官方仓库与
