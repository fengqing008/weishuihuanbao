# 模板库 — 发票/票据识别与汇总（invoice-processor）

> 用途：直接复制下方骨架改成自己的任务，省去从零搭结构。
> 脚本：`invoice-processor/scripts/invoice_tool.py`。

---

## 模板 1｜发票汇总表 13 列字段说明

**用途**：作为台账模板，说明每列含义、来源与核对口径；可直接贴到 Excel 第一行说明区，或作为交付附件。

**结构骨架**（可直接复制）：

```
# 发票汇总表 · 字段说明（13 列）
序号 | 列名 | 含义 | 口径/取值 | 核对要点
1  | 文件名             | 票据源文件名                    | 取文件 basename         | 与源目录逐个对应，无遗漏/无重复
2  | 发票类型           | 票种                            | 见下方"票种取值"         | 以票面文字为准，不靠颜色判断
3  | 发票代码           | 发票代码                        | 票面"发票代码"后 10-12 位 | 位数核对；数电票可能为空
4  | 发票号码           | 发票号码                        | 票面"发票号码"后 8-20 位  | 与代码区分，勿串列
5  | 开票日期           | 开票日期                        | 统一格式 YYYY-MM-DD      | 与票面"X年X月X日"一致
6  | 购买方名称         | 购买方（付款方）名称            | 票面购买方信息            | 应与本单位一致
7  | 购买方税号         | 购买方纳税人识别号/统一社会信用代码 | 票面首个纳税人识别号     | 18 位或 15/17/20 位，重点抽验
8  | 销售方名称         | 销售方（开票方）名称            | 票面销售方信息            | 与合同/订单对方一致
9  | 销售方税号         | 销售方纳税人识别号              | 票面第二个纳税人识别号    | 重点抽验，勿与购买方串位
10 | 金额(不含税)       | 不含税金额                      | 两位小数，无千分位         | 金额+税额=价税合计（容差 0.01）
11 | 税额               | 税额                            | 两位小数                  | 与税率口径一致
12 | 价税合计           | 含税合计金额                    | 两位小数；缺失时=金额+税额 | 末行"合计"=各票价税合计之和
13 | 状态               | 识别结果                        | "成功" 或 "失败: <原因>"   | 失败条目须处理后才可入账

## 票种取值（第 2 列）
增值税专用发票 / 增值税普通发票 / 电子发票（专用发票）/ 电子发票（普通发票）/
增值税电子专用发票 / 增值税电子普通发票 / 机动车销售统一发票 /
二手车销售统一发票 / 区块链电子发票 / 其他发票（票种未识别）

## 着色约定（导出 Excel 自动套用）
- 含"专用"的行 → 发票类型栏 红字加粗（C00000）
- 含"普通"的行 → 发票类型栏 蓝字加粗（1F4E79）
- 首行表头灰底加粗（CCCCCC）；末行"合计"行加粗
- 首行冻结（滚动时表头常驻）
```

**填写说明**：
- 第 1 列"文件名"来自源文件 basename，用来把每一行回溯到原始票据，**不可省**。
- 金额三列（10/11/12）默认由识别得到；若价税合计缺失且金额与税额齐全，脚本会**自动相加**补齐。
- 抽取字段名（JSON 内）与列名对应：`发票类型/发票代码/发票号码/开票日期/购买方名称/购买方税号/销售方名称/销售方税号/金额不含税/税额/价税合计`。
- 识别为"尽力而为"，第 6-9 列（单位与税号）与第 10-12 列（金额）是**人工抽验重点**。

**真实示例**：

```

票001.pdf         电子发票（普通发票）  011002100111 24312000000012345678 2026-08-15 【待核：单位全称】 91【待核】…  【待核：开票方全称】 91【待核】…  1000.00   60.00   1060.00  成功

合计                                                                                                                              3000.00          3320.00
```

## 模板 2｜识别结果核验表（重点抽验金额与税号）

**用途**：识别结果入账前的核验留痕。金额与税号按**重点抽验**执行，写明抽验比例、差异与处理。

**结构骨架**（可直接复制）：

```
# 发票识别结果核验表
- 汇总文件：invoice_results.xlsx      识别 JSON：invoice_results.json
- 识别日期 / 操作人：
- 票据总数：____   识别成功：____   失败：____
- 来源分布：text-layer ____ 张 / ocr ____ 张

## A. 重点字段抽验（金额、税号）
- 抽验比例：ocr 来源票据 100% 抽验；text-layer 来源按 ≥____% 抽验（建议不低于 20%）
- 抽验方法：逐张对照票面原件，核 4 项——金额(不含税) / 税额 / 价税合计 / 销售方税号

| 序号 | 文件名 | 票面 金额 | 表中 金额 | 票面 税额 | 表中 税额 | 票面 价税合计 | 表中 价税合计 | 票面 销售方税号 | 表中 销售方税号 | 是否一致 |
|---|---|---|---|---|---|---|---|---|---|---|
| 1 |  |  |  |  |  |  |  |  |  | □是 □否 |
| 2 |  |  |  |  |  |  |  |  |  | □是 □否 |

- 差异项清单与处理：____________________

## B. 内部一致性校验
- □ 每张：金额(不含税) + 税额 = 价税合计（容差 0.01）
- □ 末行"合计" = 各票"价税合计"之和
- □ 发票代码 / 发票号码 位数符合票种（数电票代码可能为空）

## C. 空字段与失败项
| 文件名 | 空字段 | 原因初判（版式特殊/图片模糊/OCR 误差） | 处理（提高DPI重试/裁剪/人工补录） | 处理结果 |
|---|---|---|---|---|
|  |  |  |  |  |

## D. 结论
□ 全部核验通过，可入账   □ 存在未处理差异，原因：____________
核验人 / 日期：
```

**填写说明**：
- **`source=ocr` 的票必须 100% 抽验金额与税号**；`source=text-layer` 的票抽样即可，但抽到差异要扩大抽验范围。
- 税号抽验看位数与数字串，**购买方税号应是本单位**、销售方税号应与开票方一致，别把两栏看串。
- B 区是"零成本自查"：金额 + 税额 = 价税合计，能快速抓出 OCR 数字错位。
- C 区对空字段与失败项逐条处理完，未处理不得入账。

**真实示例**：

```
抽验第 2 行（票002.jpg，source=ocr）：
票面 金额 2000.00 → 表中 2000.00 一致；票面 税额 260.00 → 表中 260.00 一致；
票面 价税合计 2260.00 → 表中 2260.00 一致；税号一致 → □是
B 区：2000.00 + 260.00 = 2260.00 ✓
```

## 模板 3｜批量识别操作单

**用途**：一次批量识别任务的执行清单，写明输入、命令、参数、输出与初步校验，便于交接与复现。

**结构骨架**（可直接复制）：

```
# 批量识别操作单
- 任务名称：
- 票据来源与授权：       （自有 / 已获授权；来源存疑→停下）
- 输入路径：             （单个文件或目录，自动递归 PDF/JPG/PNG/BMP/TIF/TIFF/WEBP）
- 票据预估张数：          ____
- 输出 JSON：            invoice_results.json
- 输出 Excel：           invoice_results.xlsx
- PDF 转图 DPI：         200（默认） / ____（扫描件模糊时提高）
- 存放目录：             （受控目录，勿外传）

## 第 1 步 批量识别
命令：python3 invoice-processor/scripts/invoice_tool.py ocr <输入路径> -o invoice_results.json [--dpi 300]
返回：files=____  recognized=____
核对：files 是否=预估张数？recognized 是否=files？不等则查失败项。

## 第 2 步 导出 Excel
命令：python3 invoice-processor/scripts/invoice_tool.py excel invoice_results.json -o invoice_results.xlsx
返回：rows=____  total=____（价税合计合计）

## 第 3 步 初步校验
- □ 行数 rows 与票据张数一致（无遗漏、无重复）
- □ 末行合计 = 各票价税合计之和
- □ 发票类型列已着色（专票红/普票蓝），"其他发票（票种未识别）"已单独挑出
- □ 状态列失败条目已记录并跟进

## 第 4 步 交接
- 交核验人：____   日期：____
- 配套核验表："识别结果核验表"（模板 2）
```

**填写说明**：
- 第 1 步的 `files` 与 `recognized` 是**质量闸门**：两者不等说明有票没识别成功，先解决再进第 2 步。
- `--dpi` 默认 200；扫描件较模糊、字小或倾斜时提到 300 重试。
- 输入目录会**递归**收集，注意排除历史重复票（可用文件名去重）。
- 全部产物落受控目录：JSON 含票面原文、Excel 含税号金额，均属敏感。

**真实示例**：

```
- 输入路径：发票待整理/
- 票据预估张数：23
- 第 1 步 ocr → files=23  recognized=23  ✓
- 第 2 步 excel → rows=23  total=126 800.00（示意）
- 第 3 步：23 行齐；合计对得上；票种已着色；失败 0 条
- 第 4 步：交张三核验，配套核验表
```
