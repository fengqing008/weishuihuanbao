# 质检清单 — 发票/票据识别与汇总（invoice-processor）

> 用途：交付前最后一道关，逐条打勾；命中"一票否决"即返工。
> 脚本：`scripts/invoice_tool.py`。

---

## 一、交付前必查（逐条打勾）

- [ ] **票据来源与授权已确认**：仅处理**自有或已获授权**的票据；来源存疑的一律停下追问，未擅自处理。
- [ ] **全程本地离线**：OCR 用本地 rapidocr-onnxruntime，PDF 转图用 PyMuPDF，导出用 openpyxl；**未把票据上传到任何外部 OCR / 云 API**（零外部 API）。
- [ ] **批量识别的张数对得上**：`ocr` 返回的 `files` = 源目录实际票据数（无遗漏、无重复），`recognized` 与 `files` 的差异已逐条查明。
- [ ] **来源已标注并复核**：`invoice_results.json` 中每条的 `source` 为 `text-layer` 或 `ocr`；**电子发票 PDF 优先走文字层**（文字层去空白后 ≥40 字符即走 `text-layer`，不做多余 OCR），落到 `ocr` 的票已列为重点抽验对象。
- [ ] **金额与税号已人工抽验**：`source=ocr` 的票据**金额（不含税/税额/价税合计）与销售方税号 100% 对照票面原件抽验**；`text-layer` 来源按不低于约定比例抽样，抽到差异已扩大范围。
- [ ] **金额内部一致性通过**：每张"金额(不含税) + 税额 = 价税合计"（容差 0.01）；末行"合计" = 各票"价税合计"之和。
- [ ] **票种已判定且颜色与票面一致**：第 2 列 `发票类型` 按票面文字判定，含"专用"行标红字、含"普通"行标蓝字；**未识别的 `其他发票（票种未识别）` 已人工回看原图补录**，未靠颜色臆断。
- [ ] **发票代码与发票号码分列核对**：代码为票面"发票代码"后 10-12 位、号码为"发票号码"后 8-20 位，两栏未串位；数电票代码可为空，属正常。
- [ ] **购买方/销售方信息未串位**：购买方名称与税号应为付款方（本单位），销售方名称与税号应为开票方；税号位数与内容已核。
- [ ] **空字段已复核**：13 列任一必填列为空的票已单列成表，判明原因（版式特殊/图片模糊/OCR 误差）并给出处理（提高 `--dpi` 重试 / 裁剪后重试 / 人工补录）。
- [ ] **失败条目已处理**：`状态` 列 `失败: <原因>` 的条目已去 JSON 的 `error` 字段定位原因并解决，未当空白票据跳过。
- [ ] **输出文件存放受控目录**：JSON（含票面原文）与 Excel（含税号、金额）均存于受控目录，未随意外发；文件名不含敏感信息。

## 二、一票否决（FAIL 即返工）

- **金额或税号未经人工抽验即入账/交付**：OCR 抽取是"尽力识别"，数字错位会直接造成账务与抵扣错误。改法：对 `source=ocr` 的票 100% 抽验金额三列与销售方税号，抽验留痕。
- **处理来源不明或未获授权的票据**：可能侵害他人隐私或违反保密义务。改法：先确认权属与授权，来源不明一律停下追问。
- **把票据上传到外部 OCR / 云服务，或通过联网接口处理**：违背"本地离线、零外部 API"的承诺，票据敏感信息外泄。改法：只用本地 rapidocr 流程，全程断网可用。
- **空字段或失败项未处理就当作"识别完成"交付**：汇总表残缺，仍会被误用。改法：空字段与失败项逐条处理完才可交付。
- **合计行与逐张金额对不上仍交付**：账目口径不一致，属实质性错误。改法：重算"各票价税合计之和"，与末行"合计"核对一致后再出。

---

## 三、常见错误

1. **忽视 `source=ocr` 的误差风险** → 扫描件/照片票的数字被认错（如 0/6、1/7、5/6 混淆）→ 把 `source=ocr` 的票列为 100% 抽验对象，必要时 `--dpi 300` 重识别。
2. **发票代码与发票号码串列，或购买方/销售方税号串位** → 台账关键字段错位，抵扣与对账出错 → 按 13 列字段说明逐列核对；税号按"出现顺序=购买方在前、销售方在后"复核。
3. **票种只凭颜色判断，不回看文字** → 专票/普票抵扣口径搞错 → 颜色仅为提示，一律以第 2 列票面判定文字为准；`其他发票（票种未识别）` 必须人工补录。
4. **图片模糊/倾斜不调 DPI 就交付** → 大面积空字段 → 提高 `--dpi`（如 300）重试，或先裁剪、摆正后重识别，仍不行就人工读原图补录。
5. **目录里混入重复或多版票据未去重** → `files` 与 `rows` 虚高、合计重复计算 → 识别前按文件名/票号去重，识别后核对行数与真实票数。
6. **把 JSON/Excel 放在公共目录或随手外发** → 票面原文、税号、金额外泄 → 统一存受控目录，交付范围最小化。

> 备注：支持票据格式 `.pdf / .jpg / .jpeg / .png / .bmp / .tif / .tiff / .webp`，输入可为单文件或目录（自动递归）；PDF 转图默认 200 DPI，可 `--dpi` 调整。【待核：抽验比例、受控目录路径、核验责任人按单位制度填写。】
