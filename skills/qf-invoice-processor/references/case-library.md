# 场景案例库 — 发票/票据识别与汇总（invoice-processor）

> 用途：遇到同类任务时先对照本库，复用已验证做法、规避已踩过的坑。
> 数据截至 2026-09-11；发票金额、税号等以票面原件为准，示例数字为占位示意，未核实处标【待核：...】。
> 工具路径：`invoice-processor/scripts/invoice_tool.py`（子命令 ocr / excel）。

---

## 案例 1｜一批发票批量识别，一键汇总成 Excel

- **背景**：一次报销/归档收到一个目录下的多张票据，格式混杂（数电票 PDF + 手机拍的纸质发票照片 JPG/PNG），需要整理成一张台账表交财务。输入=一个目录，里面的文件**递归**收集。
- **做法**：
  1. 批量识别：`python3 invoice_tool.py ocr /path/to/发票目录 -o invoice_results.json`。命令返回 `{"status":"ok","files":N,"recognized":M,"output":...}`，先看 N（文件数）与 M（识别成功数）是否吻合。
  2. 生成汇总表：`python3 invoice_tool.py excel invoice_results.json -o invoice_results.xlsx`，返回 `rows` 与 `total`（价税合计合计值）。
  3. 打开 Excel，按 13 列核对，末行为价税合计合计。
- **结果**：得到 `invoice_results.json`（每张票的 OCR 原文 + 抽取字段 + `source`）与 `invoice_results.xlsx`（13 列汇总表，票种着色、价格合计行）。
- **教训**：一是**识别是"正则 + OCR 的尽力识别"**，金额、税号必须人工抽验后再入账；二是文件数 N 与预期不符时，先查目录是否漏放文件、是否含不支持的后缀（只认 `.pdf/.jpg/.jpeg/.png/.bmp/.tif/.tiff/.webp`）；三是**识别失败的条目**在 `状态` 列会写 `失败: <原因>`，要去 JSON 的 `error` 字段看具体报错，别把它当"空白票"跳过。

## 案例 2｜数电票（电子发票）优先读文字层，不做多余 OCR

- **背景**：一批票中有相当比例是**电子发票（数电票）PDF**，这类 PDF 自带文字层。若一律走 OCR，既慢又可能把数字认错（如 0/6、1/7 混淆）。同时另有若干扫描件 PDF 无文字层。
- **做法**：
  1. 直接用 `ocr` 命令处理整个目录，脚本对 PDF **先取文字层**：把文字层去空白后长度 ≥ 40 字符即判为"有文字层"，走 `text-layer` 路径，**不做 OCR**；否则才转图走 OCR。
  2. 处理后在 `invoice_results.json` 中逐条看 `source` 字段：`"text-layer"`（读文字层，最准）或 `"ocr"`（走 OCR）。`pages[].note` 为 `pdf-text-layer` 的即文字层来源。
  3. 对落到 `ocr` 的关键票，必要时提高 DPI 重试：`--dpi 300`。
- **结果**：数电票字段取自文字层，识别准确度高、速度快；扫描件由本地 OCR 兜底。`source` 字段让复核者一眼看出哪几张是 OCR 来的，抽验优先级明确。
- **教训**：一是**电子发票 PDF 优先读文字层，无文字层再 OCR**，这是本工具的核心策略，不要人为绕过；二是**文字层阈值是 40 字符**，若某电子 PDF 实为"图片型 PDF"（文字层为空/极短），会自动落到 OCR，此时 `source` 会显示 `ocr`，属正常降级；三是 **OCR 来源的票是复核重点**，金额与税号优先抽这批。

## 案例 3｜专票与普票混在一批里，靠颜色与票种列一眼区分

- **背景**：一批用于进项抵扣整理的票据里，**增值税专用发票、增值税普通发票、电子发票（数电票）**混在一起。票据用途不同（专票涉及抵扣、普票不抵扣），需要台账上能一眼分辨票种。
- **做法**：
  1. 正常跑 `ocr` → `excel`。
  2. 脚本按票面文字判定票种写入**第 2 列 `发票类型`**；导出 Excel 时，含"专用"的行该栏标**红字加粗**（色值 `C00000`），含"普通"的标**蓝字加粗**（`1F4E79`）。
  3. 筛"发票类型"列，把未识别的（`其他发票（票种未识别）`）挑出来人工回看原图补录。
- **结果**：13 列汇总表里票种集中可辨；专票/普票按颜色分流，抵扣台账与费用台账可分开整理。表头固定、首行冻结（可滚动看标题）。
- **教训**：一是**票种判定依据是票面关键字**（如"电子发票(专用发票)""增值税专用发票""区块链电子发票"等），版式特殊或图片模糊时可能落到 `其他发票（票种未识别）`，必须人工补录，**不能猜**；二是**颜色只是提示，不是结论**——专票与普票关系到抵扣口径，一律以票面文字为准；三是票种枚举含增值税专用发票 / 增值税普通发票 / 电子发票（专用发票）/ 电子发票（普通发票）/ 增值税电子专用发票 / 增值税电子普通发票 / 机动车销售统一发票 / 二手车销售统一发票 / 区块链电子发票 / 其他发票（票种未识别）。

## 通用提示（三个案例共用）

- 命令速记：`ocr <文件或目录> -o xxx.json [--dpi 200]` → `excel xxx.json -o xxx.xlsx`。
- 全程**本地离线、零外部 API**：OCR 用本地 rapidocr-onnxruntime，PDF 转图用 PyMuPDF，导出用 openpyxl。
- **仅用于处理自有或已获授权的票据**；票据含税号、金额、开户行等敏感信息，输出 JSON/Excel 存放在受控目录，勿外传。
- 抽取字段共 11 个：发票类型、发票代码、发票号码、开票日期、购买方名称、购买方税号、销售方名称、销售方税号、金额不含税、税额、价税合计；Excel 再加"文件名"与"状态"共 13 列。
