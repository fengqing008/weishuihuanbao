# 会议行为洞察分析器（meeting-insights-analyzer）

把已带说话人与时间信息的会议转录还原为可验证的沟通行为证据链，输出带时间戳的可执行反馈与跨场次趋势台账。

## 〇、专家级路由（v1.0.0）

**专家定位**：以"转录即证据"的取证口径，把会议发言拆成可复算的统计量与可核验的原话片段，产出当事人当场就能认账的行为反馈。

**五维评估**：
- 适用场景：个人沟通复盘、管理者带教与主持能力提升、述职与晋升的实证准备、培训前后的效果对照。
- 能力边界：本技能只做"行为模式洞察层"，不做录音转写、不做纪要成文、不做绩效评分定级；转写与纪要由 meeting-minutes-pipeline 承担，二者以转录件为接口衔接。
- 依赖资产：references/case-library.md、references/quality-checklist.md、references/output-template.md、scripts/meeting_stats.py。
- 交付质量：每条结论须挂原话引用与时间戳；统计口径可复算；样本不足时显式标注证据强度与不确定性。
- 性能表现：单场 1 小时转录（约 8 千至 1.2 万字）解析与统计在数十秒内完成；10 场以内批量统计走一次批处理命令，无需外部服务。

**四级响应（L1-L4）**：
- **L1 速查**：1 场会议 + 1 个明确问题。直接给结论、2 条时间戳证据与 1 条改进动作。
- **L2 标准分析**：1 至 3 场会议。跑全量统计脚本，产出行为模式清单、发言比表与反馈表。
- **L3 深度洞察**：3 场以上或需趋势。加跨场次趋势对比，按 references/quality-checklist.md 全流程质检。
- **L4 体系化**：季度复盘或团队辅导。加辅导方案、培训前后对照、趋势台账与季度报告。

**黄金窗口**：转录件到手后 48 小时内完成分析。当事人对现场仍有记忆，反馈可被当场验证与接受；超过一周，当事人对具体语境的回忆衰减，证据的说服力下降。

**专家件索引**：
- 案例库与登记模板：references/case-library.md
- 质量检查清单：references/quality-checklist.md
- 输出模板：references/output-template.md
- 发言统计脚本：scripts/meeting_stats.py

## 一、定位声明

本技能服务"我把这会开成什么样、我该改哪一句"这一类问题。它消费已经完成转写的会议文本，产出行为层面的证据与反馈；它不生产内容纪要，也不替代录音转写。

与 meeting-minutes-pipeline 的能力边界与衔接方式：

| 环节 | meeting-minutes-pipeline | 本技能 |
|---|---|---|
| 录音转写 | 承担（ali-asr / whisper-local 后端） | 不承担，只消费其转写产物 |
| 纪要成文 | 承担（议题、决议、待办、公文格式 Word） | 不承担，不回写纪要正文 |
| 行为统计 | 不承担 | 承担（发言比、打断、填充词、提问比） |
| 反馈与趋势 | 不承担 | 承担（时间戳证据、改进行为、跨场次台账） |
| 数据接口 | 产出转写件与纪要 | 直接读同一份转写件 |

衔接做法：先由 meeting-minutes-pipeline 得到转写件，把该文件落盘为 `会议转录.md` 或 `.vtt`，再以本技能的批处理命令消费同一目录。两条链路可串行执行，也可先出纪要、次日再出行为洞察，互不阻塞。

产物三类：洞察报告（Markdown，可直接进述职材料）、统计底稿（stats.json，可复算可追溯）、趋势台账（跨场次指标对照）。

## 二、触发条件

**中文触发词**：会议分析、会议洞察、沟通分析、发言比例、发言占比、领导风格、主持风格、会议复盘、打断分析、填充词、倾听机会、提问与陈述、趋势追踪、述职实证、带教反馈、行为模式识别。

**英文触发词**：meeting insights、communication analysis、speaking ratio、conflict avoidance、filler words、interruption analysis、active listening、leadership style、facilitation feedback、trend tracking。

**不触发**：仅需会议纪要成文（走 meeting-minutes-pipeline）、仅需录音转文字（走 ali-asr 或 whisper-local）、需要心理诊断或绩效定级（不在本技能范围）、需要把会议发言作为法律证据固定。

## 三、常驻规则

1. **先验数据，后出结论**：任何行为结论须挂转录原文引用与时间戳；无原文支撑的判断一律不写入报告。
2. **口径并列**：发言占比同时给出按字符数（中文为主）与按词数（英文为主）两种口径，避免单一口径造成误读。
3. **描述行为，不评判人格**：措辞落在"在哪个时间点说了什么、造成什么影响"，禁止使用"你就是回避型"这类人格定性。
4. **隐私优先**：转录件与报告默认留在本地目录；导出前做人名、客户名、金额的脱敏替换，脱敏规则须随报告一并交付。
5. **样本门槛**：少于 3 场或总时长少于 60 分钟的样本，所有结论须加标注"证据强度低，仅作线索"，不得写成定论。
6. **改动聚焦**：单次交付只推 1 至 3 项可被观察的改进行为，每项须能在一周内的下一次会议中被复算验证。

## Phase 0｜分析前校验（未过不进主流程）

| 检查项 | 通过标准 | 未过动作 |
|---|---|---|
| 转录文件可用 | 为 .txt/.md/.vtt/.srt/.docx 且含发言人标记 | 补齐发言人或重转 |
| 发言人口径 | 发言人标识统一（实名或代号），同一人无多标识 | 统一标识后重跑 |
| 指标定义 | 发言时长/轮次/打断/提问比等口径明确 | 明确口径后再统计 |
| 样本范围 | 分析的会议场次与时间范围明确 | 明确范围 |
| 用途明确 | 明确为个人复盘/团队辅导/述职举证哪一类 | 明确用途 |

🔴 检查点：任一检查项未过，先补齐再进入标准工作流；口径不一致会导致指标失真。

## 四、标准工作流

1. **数据清点**。输入：转录所在目录或单文件；动作：扫描 .txt/.md/.vtt/.srt/.docx，逐件核对是否含说话人标签与时间戳，登记文件数与总时长；输出：转录清单表（文件名、场次、时长、标签有无、时间戳有无）。
2. **目标确认**。输入：用户诉求与转录清单；动作：把诉求收敛为 1 至 3 个待测行为维度（发言比、打断、冲突规避、填充词、提问比、倾听信号、主持控制）；输出：分析大纲（维度、判据、预期证据形态）。诉求模糊时先向用户确认维度，确认后再往下走。
3. **视角锚定**。输入：转录清单；动作：确定"我"在转录中的标识名与全部别名（姓名、昵称、职务、英文名），建立说话人映射；输出：说话人映射表（别名 → 规范名）。
4. **统计计算**。输入：转录文件与说话人映射；动作：执行 scripts/meeting_stats.py 完成逐场统计与跨场汇总；输出：stats.json 底稿与发言比表。
5. **证据抽取**。输入：stats.json；动作：按维度定位命中的时间戳片段，逐条回读前后各 2 分钟上下文，剔除转录错字与叠句造成的假命中；输出：证据清单（时间戳、原话、命中规则、上下文结论）。
6. **模式归纳**。输入：证据清单；动作：跨场次聚类，统计频次与出现场景，标注影响等级；输出：行为模式清单（模式名、频次、场景、影响、证据编号）。
7. **反馈成文**。输入：行为模式清单；动作：按 references/output-template.md 套骨架，每条写"发生了什么 / 为什么重要 / 更好的说法"，更好的说法须给出可直接照念的替代句；输出：洞察报告初稿。
8. **质检交付**。输入：洞察报告初稿；动作：逐条对照 references/quality-checklist.md，跑复核命令校验统计口径与时间戳，核对脱敏；输出：洞察报告定稿、stats.json、趋势台账。

工作流支持断点续跑：第 4 步之后的每步都以文件为交接物（清单、映射表、stats.json、证据清单、报告初稿），中途暂停后从最近一个交接物继续即可，无需重复转写与统计。

## 五、核心方法与命令

### 5.1 转录格式与解析口径

- **.txt / .md**：以行首 `说话人:` 或 `[HH:MM:SS] 说话人:` 为一条发言；连续行无说话人前缀时并入上一条发言。
- **.vtt**：按 cue 块切分，取 `<v 说话人>` 标注或文本行首 `说话人:`；`WEBVTT` 头与 `NOTE` 块丢弃。
- **.srt**：按序号 + 时间轴 + 文本三行结构切分，文本首行 `说话人:` 为发言人；时间轴 `00:00:01,000 --> 00:00:04,000` 转秒。
- **.docx**：用 python-docx 抽段落文本，段落首行沿用 .txt 口径；表格内文本按行拼接。
- **时间轴统一**：一律换算为秒；无时间轴的转录用行序编号代替，报告内标注"序位代替时间"。

### 5.2 批量统计（主命令）

```bash
python3 scripts/meeting_stats.py --input ./meetings --me "我" --out ./reports --json
python3 scripts/meeting_stats.py --input ./meetings/示例-周例会.vtt --me "我" --top-n 8
python3 scripts/meeting_stats.py --input ./meetings --me "我" --filler both --min-turn 12 --out ./reports
```

输出两个文件：`./reports/stats.json`（逐场逐人全部指标，可复算）与 `./reports/发言比表.md`（人读表格）。命令回显样例（截断）：

```

[ME] 我 | share_chars=0.47 | share_words=0.44 | turns=96 | avg_turn_chars=61
[CHK] filler_per_1k=6.8 | hedge_per_1k=4.1 | question_ratio=0.18 | interrupt_given=7
written: ./reports/stats.json
written: ./reports/发言比表.md
```

### 5.3 无脚本时的内联统计（Python）

脚本不可用时，用下面这段标准库代码兜底，口径与主脚本一致：

```python
import re, json
from pathlib import Path

SPEAKER = re.compile(r'^\s*(?:\[(?P<t>\d{1,2}:\d{2}(?::\d{2})?)\]\s*)?'
                     r'(?P<sp>[\u4e00-\u9fa5A-Za-z][\w\u4e00-\u9fa5·\- ]{0,11})\s*[:：]\s*(?P<tx>.+)$')
FILLER_CN = ["嗯", "呃", "那个", "这个", "就是说", "怎么说呢", "是吧"]
FILLER_EN = ["um", "uh", "like", "you know", "actually", "sort of", "kind of"]
HEDGE = ["可能", "也许", "大概", "稍微", "有点", "我觉得", "maybe", "potentially", "i think"]
Q_MARK = ("?", "？")
LISTEN = ["你说的", "你刚才", "如你所说", "我复述一下", "补充一点", "对", "是的"]

def stats(path, me):
    turns, cur = [], None
    for line in Path(path).read_text(encoding="utf-8", errors="replace").splitlines():
        m = SPEAKER.match(line)
        if m:
            cur = {"sp": m.group("sp").strip(), "tx": m.group("tx").strip(), "t": m.group("t") or ""}
            turns.append(cur)
        elif cur and line.strip():
            cur["tx"] += " " + line.strip()
    mine = [t for t in turns if t["sp"] == me]
    chars = sum(len(t["tx"]) for t in mine)
    return {
        "speakers": sorted({t["sp"] for t in turns}),
        "turns": len(turns),
        "my_turns": len(mine),
        "my_share_chars": round(chars / max(1, sum(len(t["tx"]) for t in turns)), 3),
        "question_ratio": round(sum(1 for t in mine if t["tx"].endswith(Q_MARK)) / max(1, len(mine)), 3),
        "filler_hits": sum(t["tx"].lower().count(w) for t in mine for w in FILLER_CN + FILLER_EN),
        "hedge_hits": sum(t["tx"].lower().count(w) for t in mine for w in HEDGE),
        "listen_hits": sum(1 for t in mine if any(w in t["tx"] for w in LISTEN)),
    }

print(json.dumps(stats("./meetings/示例-周例会.txt", "我"), ensure_ascii=False, indent=2))
```

### 5.4 指标口径表

| 指标 | 计算口径 | 中文会议参考区间 | 超区间时的处置 |
|---|---|---|---|
| 发言占比 | 我的字符数 ÷ 全场字符数 | 主持 0.25-0.40；参会 0.10-0.25 | 超 0.50 判定为主导过度，须给出打断明细 |
| 平均轮长 | 我的字符数 ÷ 我的轮次 | 40-120 字 | 超 200 字判定为独白，须标注对手方插话机会 |
| 打断（发出） | 前一轮未结束时切入，且切入轮长 < 15 字 | 每场 0-2 次 | 超 5 次列为高频风险行为 |
| 打断（承受） | 同上口径，方向反转 | 每场 0-3 次 | 持续高于对方时标注参与受阻 |
| 提问比 | 以问号结尾轮次 ÷ 我的总轮次 | 0.20-0.35 | 低于 0.10 判定为陈述主导 |
| 填充词密度 | 填充词次数 ÷ 千字 | 低于 5 | 超 10 须给出场景定位（紧张、不确定） |
| 模糊限定语 | 可能/也许/我觉得/maybe 类词 ÷ 千字 | 低于 4 | 超 8 判定为冲突规避信号 |
| 倾听信号 | 复述、追问、承接他人观点的轮次数 | 每场 3 次以上 | 为 0 时列为倾听机会缺失 |

### 5.5 复核命令

```bash
python3 scripts/meeting_stats.py --input ./meetings --me "我" --out ./reports --min-turn 12
```

复核时抽取 3 条统计命中片段回到原转录逐字比对，比对一致才写入报告；不一致时改口径重算，不许带疑问的数字进报告。

## 六、输出规范

**交付三件**（缺一不可）：
1. `YYYY-MM-DD-会议洞察报告.md`：人读报告，骨架见 references/output-template.md。
2. `./reports/stats.json`：机器可读底稿，含逐场逐人指标与生成参数（输入路径、min-turn、filler 口径）。
3. `趋势台账.md`：跨场次指标对照表，一行一场，列为各核心指标。

**报告内格式约束**：
- 每条时间戳写作 `[HH:MM:SS]`，与转录件时间轴一致。
- 每条证据写成三段式：原话引用（引用块）→ 影响判断（一两句）→ 更好的说法（可直接照念的整句）。
- 统计表与证据引用须编号对应（证据 P1、P2…），便于当事人抽查。
- 报告首部给证据强度等级：场次数与总时长达标标"证据强度：中"，不足标"证据强度：低，仅作线索"。

**脱敏要求**：报告对外流转前，把客户名替换为"客户 A/B"、金额替换为量级、外部人名替换为"对方 / 同事 X"，脱敏映射表与报告分开存放，不随报告外发。

## 七、边界与反模式

**能力边界**：
- 不做录音转写与字幕生成；不做会议内容纪要、决议与待办整理。
- 不做心理测评、人格诊断、情绪障碍判断；不做绩效评分与定级。
- 不把会议发言加工为诉讼证据、仲裁材料或劳动争议证据链。
- 不分析未经授权的他人录音；不在缺少说话人标签的文本上强行归因到人。

**反模式黑名单（出现即重做）**：
1. **无原文的断言**：写"你经常逃避冲突"却不给时间戳与原话。
2. **单场定论**：只分析 1 场会议就下"长期模式"的判断。
3. **人格定性**：把行为描述写成性格标签。
4. **数字漂移**：报告里的占比与 stats.json 不一致。
5. **反馈过载**：一次甩给用户 8 条改进项。
6. **越界代替**：拿本技能的报告当纪要用，或当绩效证据用。
7. **隐私外溢**：把原始转录（含客户名、金额）直接贴在报告附件里。

红线两条：一是不做未授权他人的行为分析；二是不把洞察结论用于人事处置决策。

## 八、失败模式与降级

| 失败模式 | 判据 | 处置与降级路径 |
|---|---|---|
| 转录无说话人标签 | 全篇无 `说话人:` 前缀，脚本 speakers=1 | 停止逐人统计，改为"我参与度"整体分析；请用户回原工具导出带说话人的 VTT/SRT 后重试；仍无标签则降级为内容语义分析并显式标注无法归因 |
| 多人重叠发言 | 同一时间轴出现两条以上发言人，或大量 5 字以内碎片轮次 | 启用 `--min-turn 12` 过滤碎片，重叠段单独列出并标"归属不确定"；该段不参与打断统计 |
| 会议时长过长 | 单场超过 3 小时或单文件超过 5 万字 | 分段处理：按议题切 30 分钟窗口逐段统计再汇总，避免一次性读取造成截断；汇总时保留分段明细以便复核 |
| 隐私敏感 | 转录含客户名、金额、身份证、病历等 | 先脱敏再分析，原始件留在本地目录不移动；导出件仅含脱敏文本；无法判断敏感度时暂停并向用户确认处置方式 |
| 样本过少 | 少于 3 场或总时长少于 60 分钟 | 结论降级为线索级，去掉趋势对比章节，只保留单场证据与 1 条改进行为 |
| 脚本不可用 | 缺 python3 或脚本报错 | 用 5.3 节内联代码兜底；仍失败则回退到人工计数，抽样 20% 轮次手工统计并标注为近似值 |
| 转录错字致假命中 | 填充词/限定语统计命中但回读上下文无该语义 | 建立误命名词表，重跑统计做二次过滤；过滤后差异超过 20% 时改口径重算 |
| 用户诉求与证据不匹配 | 用户要的维度在转录中无足够证据 | 明确告知证据不足，不出该维度结论；请用户提供更多场次或更换维度 |

兜底原则：任何一步失败都不得静默跳过，须在报告的"数据说明"段落写明哪一步降级、降级后的口径与可信度，报告才可交付。

## 九、关键检查点

🔴 **检查点 1（统计前）**：说话人映射表未经用户确认，不得开始统计。别名归并错一人，全部占比数据作废。

🔴 **检查点 2（成文前）**：证据清单里每条命中都回读过上下文；发现假命中先剔除再归纳，不许带病归纳。

🔴 **检查点 3（交付前）**：报告数字与 stats.json 逐项对齐；脱敏检查通过；证据强度标注到位。三项任一未过，退回重做。

🔴 **检查点 4（趋势结论前）**：趋势对比须两组样本场次数相当（相差不超过 1 倍）、场合可比（同类会议）。不可比时暂停趋势章节，只出单组分析。

🔴 **检查点 5（对外流转前）**：报告外发（进述职材料、交 HR、交上级）须人工确认脱敏范围与使用边界，确认后方可流转。

## 十、实战范例

**范例一：单场速查——定位一次打断高发**

```bash
python3 scripts/meeting_stats.py --input ./meetings/示例-周例会.vtt --me "我" --top-n 8
```

预期输出（数值为示例占位，实际以脚本回显为准）：

```
[OK] 1 file parsed | turns=138 | speakers=4 | duration_sec=2940
[ME] 我 | share_chars=0.52 | turns=41 | avg_turn_chars=74
[CHK] interrupt_given=6 | filler_per_1k=9.2 | question_ratio=0.12
```

据此出 L1 交付：发言占比 0.52 超主持区间上限，打断发出 6 次超阈值，给出 3 条时间戳证据与一条可照念的替代句；不写趋势章节。

**范例二：两场对照——验证倾听改进是否落地**

```bash
python3 scripts/meeting_stats.py --input ./meetings/Q1 --me "我" --out ./reports/q1 --json
python3 scripts/meeting_stats.py --input ./meetings/Q2 --me "我" --out ./reports/q2 --json
```

预期输出：两份 stats.json 生成后，按`倾听信号、提问比、打断发出`三列做对照表；场次数相当、场合同类时给趋势结论，否则只出两组单场分析并说明不可比原因。

**范例三：兜底路径演练——无脚本环境**

脚本不可用时执行 5.3 节内联代码：

```bash
python3 -c "exec(open('inline_stats.py', encoding='utf-8').read())"
```

预期输出：一份含 speakers、my_share_chars、question_ratio、filler_hits 的 JSON；报告内标注"统计为内联兜底口径，填充词仅覆盖中英基础词表"。

## 十一、依赖说明与降级

- **运行环境**：Python 3.8 及以上，仅用标准库（re、json、argparse、pathlib）即可完成 .txt/.md/.vtt/.srt 解析与全量统计。
- **可选依赖**：python-docx，用于 .docx 转录解析。未安装时脚本跳过 .docx 并在回显中提示，用户把 .docx 另存为 .txt 后重跑即可，其余格式不受影响。
- **音频依赖**：本技能不做转写，无 ffmpeg、无模型依赖；需要转写时先经 meeting-minutes-pipeline 的 ali-asr 或 whisper-local 后端产出转写件。
- **字体与图表**：需要出趋势图时用 matplotlib 叠加 Noto Sans SC 中文字体，避免方框字；不使用外部图表服务。
- **降级顺序**：标准脚本 → 内联兜底代码 → 抽样人工计数（标注近似）→ 只出定性结论并说明量化不可得。

## 输出质量规范

- **数据溯源与来源分级**：每项指标标注统计口径与来源文件（含时间戳区间）并分级——P0 原始转录｜P1 统计脚本输出｜P2 人工估算；无来源者标【待核：需补来源】。
- **缺口显性化**：转录缺失段落、无法辨识发言内容一律写【待核：具体项】，不推算填补。
- **事实与判断分离**：发言时长、轮次、打断次数等属事实段直陈；领导风格与沟通改进的判断以「判断：」起头，并附原话证据与时间戳。
- **能力边界提示**：本输出为行为统计分析，不构成对个人能力的评价结论；用于绩效或人事决策时须结合完整绩效材料。

## 交付附加与迭代

交付时按需追加：关联提示、要点归纳（3—5 条，如发言占比、打断分布、提问率）、下一步动作（可执行项，如改进项与观察周期）。

多轮迭代：交付后说明可调整维度（会议范围／指标口径／输出颗粒度），指定后直接改。
