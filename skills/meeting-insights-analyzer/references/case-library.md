# 案例库（meeting-insights-analyzer）

本文件用于沉淀可复用的会议行为洞察案例。**严禁编造具体项目名、客户名、人名、金额、日期与统计数值。**

## 一、使用方式

1. 每完成一次 L2 及以上交付，用第二节模板登记一条案例（只登记方法论与口径，不落真实敏感信息）。
2. 登记后的案例只用于校准判据与口径，不作为任何结论的既成证据。
3. 数据来源须可追溯：写明该案例的依据文件类型与样本规模区间，不写具体人名与单位名。

## 二、案例登记模板（复制后填写，未采集到的字段一律保留【待填】）

```
### 案例编号：CASE-【待填】

- 会议类型：【待填：周例会/项目协调会/一对一沟通/评审会/客户会/其他】
- 样本规模：场次【待填：X 场】；总时长区间【待填：小时区间】；转录格式【待填：.vtt/.srt/.txt/.md/.docx】
- 数据完整性：说话人标签【有/无】；时间戳【有/无】；重叠发言【有/无】
- 待测维度：【待填：发言比/打断/冲突规避/填充词/提问比/倾听信号/主持控制】
- 判据与阈值：【待填：命名使用了哪些口径与阈值】
- 观察到的行为模式：【待填：模式名 + 出现场景类型（不写人名与单位）】
- 影响判断：【待填：对会议效率或决策质量的影响，去标识化表述】
- 实际采纳的改进行为：【待填：1-3 项，须可被下一次会议复算验证】
- 复算结果：【待填：改进后指标变化区间；无复算则填"未复算"，不得留空】
- 口径踩坑记录：【待填：哪一条口径出现过误判、如何修正】
- 证据强度：【中/低】；降级原因【待填或"无"】
- 登记人：【待填】；登记日期：【待填】
```

## 三、数据来源指引（案例素材从哪里来）

1. **自有会议转录**：当事人本人参加的会议，取得与会方同意后使用；转录件落在本地目录，登记时只写脱敏后的口径与模式。
2. **公开演讲与访谈**：公开发布的路演录像、播客访谈、会议公开回放，其转写文本可作为"主持与提问风格"类案例素材；须保留公开来源链接字段。
3. **团队培训前后对照**：同一团队同类会议的培训前后两批转录，用于校准"倾听信号""提问比"两项指标的敏感度。
4. **自造校准样本**：为验证脚本口径，用人工编写的合成对话文本（不含任何真实人物与机构）测试填充词、打断、提问比的解析正确性。此类样本登记时标注"合成样本，仅用于口径校准"。
5. **来源登记要求**：每条案例须标注来源类型（自有转录 / 公开素材 / 合成样本），不得混用。

## 五、案例使用红线

1. 禁止把案例中的模式名直接套到当事人身上当结论；案例只用于校准判据。
2. 禁止在案例库中写入客户名、真实人名、真实金额、可定位的项目名。
3. 禁止编造案例填充条目；没有真实素材时保留【待填】占位。
4. 案例库不外发，随技能目录保存，导出报告时不附案例库全文。
