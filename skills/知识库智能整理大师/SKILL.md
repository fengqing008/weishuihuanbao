## 〇、专家级路由（v2.1.0）

**专家定位**：把知识库从"一堆散落资源"变成"有条理的知识体系"——扫描判模式→出分类方案→建夹→归类→移动→验证，移动前留原路径、不误删不覆盖。
**五维评估**：
- 适用场景：①无文件夹/需重新分类（完整模式）②根目录散乱（整理模式）③多知识库体系梳理
- 能力边界：不做新建知识库（→ima-knowledge）；不做内容搜索阅读；不做笔记管理；不做单篇文档编辑
- 依赖资产：`references/`（case-library/writing-templates/quality-checklist + marketplace-intro/usage-guide）、`scripts/kb_organizer_check.py`（整理方案自检器）；平台接口 `get_knowledge_list`（分页 50/次，上限 10 次）、`create_folder`、`move_knowledge`（每批 ≤10）
- 交付质量：分类方案先出供确认；移动前留原路径记录；整理前后总数一致；接口无删除能力，禁删禁覆盖
- 性能表现：约 500 条内单次可扫；大库分批处理
**四级响应（L1-L4）**：
- L1 轻量问答 → 直接答：两大模式与适用
- L2 标准任务 → 扫描 + 模式判定
- L3 复杂任务 → 出方案 + 建夹 + 归类移动
- L4 专家任务 → 完整模式全流程（分析→提案→建夹→归类→移动→验证）
**黄金窗口**：单知识库；>500 条分批；每批移动 ≤10 条。
**专家件索引**：`references/case-library.md`、`references/writing-templates.md`、`references/quality-checklist.md`、`references/marketplace-intro.md`、`references/usage-guide.md`、`scripts/kb_organizer_check.py`。

# 知识库智能整理大师

## 使用说明

1. **用途**：知识库智能整理大师——自动分析知识库内容分布，生成个性化分类方案，创建文件夹并批量归类归位。
2. **调用方式**：在 ima 对话中直接描述需求或上传相关文件，本技能按触发词自动匹配调用。
3. **注意事项**：新建知识库、内容搜索阅读、笔记管理、单篇文档编辑。

## 核心能力

本技能将知识库从"一堆散落资源"变成"有条理的知识体系"。分为两大工作模式：

| 模式 | 适用场景 | 核心流程 |
|------|---------|---------|
| **完整模式** | 知识库无文件夹/需重新分类 | 分析 → 提案 → 建夹 → 归类 → 移动 → 验证 |
| **整理模式** | 有文件夹但根目录散乱 | 扫描 → 归类 → 移动 → 验证 |

> 先通过一次快速扫描判断当前知识库的状态，自动选择模式。

---

## Phase 0：快速扫描与意图对齐

### 第一步：获取知识库基础信息

使用 `search_knowledge_base` 确认 `kb_id` 和基础信息。

### 第二步：扫描根目录

调用 `get_knowledge_list` 获取根目录全部内容。**必须处理分页**——API 单次最多 50 条，`is_end=false` 时用 `next_cursor` 翻页。设定翻页上限 10 次（约 500 条）。

记录以下信息：
- **已有文件夹数**（media_type == 99）
- **散落资源数**（非文件夹条目）
- **资源类型分布**（PDF/公众号/网页/笔记/PPT 等）
- **标题关键词分析**（提取高频词，判断内容主题领域）

### 第三步：判断模式

```python
if 已有文件夹 == 0:
    → 完整模式（需要分析内容、提案分类、建夹、归类）
elif 散落资源数 > 5:
    → 整理模式（归入已有文件夹）
else:
    → 告知用户"根目录已整洁，无需整理"，直接结束
```

并向用户简要说明当前知识库状态和推荐模式，等待确认后继续。

## Phase 1：深度内容画像

### 搜索内容主题

使用 `search(source="kb", kb_id=xxx)` 对知识库进行**内容语义搜索**，用以下查询理解知识库的内容面：

- 搜索"工具 教程 指南"——是否有大量教程类内容
- 搜索"AI 人工智能 智能化"——是否以AI为主题
- 搜索"教学 课堂 教师 学生"——是否涉及教育领域
- 搜索"政策 报告 文件 通知"——是否有政策文件
- 搜索"设计 图片 海报 视频"——是否有创意类素材

> 提示：每次 search 调用消耗 ≈ 扫描 200 条标题，所以优先 scan 标题而非大量 search。

### 统计媒体类型分布

从已获取的 `knowledge_list` 中统计 `media_type` 分布：

| media_type | 含义 |
|-----------|------|
| 1 | PDF |
| 2 | 网页 |
| 6 | 公众号文章 |
| 7 | Markdown |
| 11 | 笔记 |
| 99 | 文件夹 |

### 标题关键词聚类

对全部非文件夹资源的标题进行关键词聚类，识别高频主题词：

- 遍历标题，提取核心主题词（排除"的""了""是""在"等停用词）
- 统计出现频次，找出 Top 15 高频主题词
- 根据关键词组合判断内容领域（教育 / 科技 / 金融 / 医疗 / 设计 / 编程等）

### 如果你在完整模式

**Before：确认门**——将内容画像结果整理输出，让用户"看一眼就知道知识库里有什么"：

```markdown
📊 AI工具箱知识库内容画像
━━━━━━━━━━━━━━━━━━━━
📁 当前已有文件夹：0 个
📄 总资源数：214 条
┌──────────────┬──────┐
│ 公众号文章    │ 180  │
│ PDF文档       │  15  │
│ 网页链接      │  10  │
│ PPT           │   5  │
│ 笔记          │   4  │
└──────────────┴──────┘

🔍 内容主题分布：
教学备课/课件   ████████████ 35%
AI工具/平台     ██████████   30%
论文/课题       ██████       18%
图片/视频制作   ████         12%
政策/报告       ██           5%

🏷️ 高频关键词：教学、备课、AI、论文、WorkBuddy、提示词、
   课件、设计、视频、ima、课题、工具
```

### 生成分类方案

基于内容画像，生成 **2-3 个分类方案**，每个方案包含：
- 方案名称和核心理念
- 文件夹列表及预计放入的资源数
- 优缺点说明

**典型方案模板：**

#### 方案A：按应用场景分类（推荐）
最直观实用，适合"我需要解决什么问题→去哪个文件夹找"的使用习惯。

| 文件夹 | 预计资源数 | 典型内容 |
|--------|-----------|---------|
| 01-教学备课与课件制作 | ~40 | 教案、课件、教学设计 |
| 02-论文写作与课题研究 | ~12 | 论文、课题申报、科研 |
| 03-AI生图与视觉设计 | ~17 | 图片、海报、绘画工具 |
| ...基于实际数据... | ... | ... |

#### 方案B：按内容类型分类
适合按"这是什么"而非"用在哪儿"的人。

#### 方案C：按工具/平台分类
适合熟悉各工具名称的用户。

> 如果知识库已经有一些文件夹（整理模式），跳过此阶段，直接进入 Phase 4 映射归类。

**重要：必须等待用户选择方案后再进入 Phase 3。**

---

## Phase 3：创建文件夹

根据用户选定的方案，调用 `create_folder` API 在知识库根目录下创建所有文件夹。

**API 调用要点：**
- 使用 `knowledge_base_id` 和 `name` 字段
- 可选传 `kb_name` 用于二次校验
- 记录返回的 `media_id`（即 `folder_xxxxx` 格式）作为后续移动的目标 `dst_folder_id`

**并行创建：** 多个文件夹可同时创建，互不依赖。

成功创建后告知用户文件夹结构。

## Phase 4：智能归类与批量移动

### 4.1 构建归类规则

基于用户选定的分类方案和文件夹名称，构建**关键词归类映射表**。规则优先级：

1. **专有名词/品牌词优先**：如"WorkBuddy""龙虾""ima""Coze"等平台名称
2. **功能词匹配**：如"备课""课件""教案" → 教学类
3. **内容形式词**：如"论文""课题""申报" → 学术类
4. **兜底规则**：未匹配的按语义相似度归入最近文件夹

**切勿硬编码——必须根据实际文件夹名称动态构建规则。**

### 4.2 规则构建方法

```
对每个文件夹名称，提取核心关键词：

文件夹: "01-教学备课与课件制作"
→ 核心词: [教学, 备课, 课件, 教案, 课堂, 教师, 学生, 上课, 授课, 考试, 复习, AI助教, 教育, 班级, 班主任, AI教学, 课例, 课程, 作业, 习题, 互动, padlet]

文件夹: "07-WorkBuddy龙虾专区"
→ 核心词: [workbuddy, 龙虾, workbuddy教程, openclaw, qclaw, 万剑诀, workbuddy技能, 工作流, agent工作流]

文件夹: "06-提示词工程与Skills"
→ 核心词: [提示词, prompt, skill, skills, 智能体, agent, coze, 扣子, 调教, 系统提示词]
```

### 4.3 执行归类

遍历根目录全部非文件夹资源，逐条匹配：

```python
for item in all_items:
    title = item["title"].lower()
    
    # 按文件夹顺序匹配（优先级高的在前）
    for folder in ordered_folders:
        if any(keyword in title for keyword in folder_keywords[folder]):
            classified[folder].append(item)
            break
    else:
        unclassified.append(item)
```

**输出归类预览给用户确认**（仅展示各文件夹数量统计和未分类条目）：

```markdown
### 归类方案预览

| 目标文件夹 | 条数 |
|-----------|------|
| 01-教学备课与课件制作 | 40 |
| 02-论文写作与课题研究 | 12 |
| ... | ... |
| **未分类** | **3** |

未分类条目需您指定归入哪个文件夹：
1. xxx —— 建议归入？
2. yyy —— 建议归入？

确认后执行，或您直接修改？(回复"确认"开始移动)
```

> **用户在之前已清晰表达过意图时，可以跳过此确认直接执行。** 例如用户说"按方案A直接做"或已经确认过方案——此时归类预览改为快速展示，直接进入移动。

### 4.4 批量移动

调用 `move_knowledge` API：

**关键参数：**
```json
{
  "src_knowledge_base_id": "同一知识库ID",
  "dst_knowledge_base_id": "同一知识库ID",
  "dst_folder_id": "目标文件夹ID（folder_前缀）",
  "dst_folder_name": "目标文件夹名称（二次校验用）",
  "infos": [{"media_id": "资源ID"}, ...]
}
```

**移动策略：**
- 同一目标文件夹的资源，合并为批次移动
- 每批次最多 **10 条**（API 限制）
- 同一文件夹分多批次的，连续执行

**错误处理：**
- 每批次返回 `move_results`，检查每个 `ret_code`
- ret_code=0 → 成功
- ret_code≠0 → 记录失败项的 `media_id` 和 `err_msg`，在总结中报告

## Phase 5：验证与总结

### 5.1 根目录验证

再次调用 `get_knowledge_list` 检查根目录，确认：
- 是否只剩余文件夹
- 是否有遗漏的散落资源

### 5.2 输出整理报告

```markdown
## ✅ 知识库整理完成

### 整理前后对比
```
之前：根目录 214 条散落资源
之后：11 个分类文件夹，0 条散落资源
```

### 最终结构

```
📁 根目录
├── 📁 01-教学备课与课件制作（40条）
├── 📁 02-论文写作与课题研究（12条）
├── 📁 03-AI生图与视觉设计（17条）
├── ... ...
└── 📁 11-办公效率与数据分析（7条）
```

### 如有失败
| 资源 | 原因 | media_id |
|------|------|----------|
| xxx | 移动失败（err_msg） | xxxx |
```

### 5.3 可选：重复文件检测

**先询问用户是否需要检测重复文件。**

> 重复检测需要遍历所有文件夹，耗时较长。仅在用户明确需要时执行。

如果用户确认，检测规则：
- 文件名高度相似（标题相同或仅差后缀如"（1）""-副本""_copy"）
- 文件类型相同（media_type 一致）
- 列出疑似重复清单，让用户确认是否删除（注意：API 不支持删除操作，需告知用户手动处理）

## 边界情况处理

| 场景 | 处理方式 |
|------|---------|
| 根目录已整洁 | 告知用户，直接结束 |
| 资源无法归入任何文件夹 | 列出清单，让用户指定或新建"其他"文件夹 |
| 文件夹名含义模糊 | 浏览文件夹内容后再判断适合放入哪些资源 |
| API 返回错误 | 区分可重试错误（网络超时）和不可重试错误（参数错误），可重试的自动重试一次 |
| 超大知识库（>500条） | 按主题分批处理，先处理主题最清晰的类别 |
| 用户说"直接做" | 跳过确认门，全自动执行 |

| 知识库内容画像 | Markdown（对话内输出） | 已有文件夹数、散落资源数、媒体类型分布、Top15 高频主题词 | 用户"看一眼就知道库里有什么" |
| 分类方案（2–3 个） | Markdown | 每案含名称、理念、文件夹列表与预计条数、优缺点 | 用户选定后方可进入建夹 |
| 文件夹结构 | 平台实体（`create_folder`） | 命名统一为"两位序号-主题"，同一维度下 ≤12 个 | 回执 `media_id` 全部登记为 `dst_folder_id` |
| 归类预览表 | Markdown | 各夹条数统计 + 未分类清单 + 逐条建议归属 | 用户确认后方可移动 |
| 整理执行清单 | Markdown / `.csv` | 逐条记录 `media_id`、原所在位置、目标文件夹、`ret_code` | 移动前留原路径，可断点续跑补移 |
| 整理前后对照表 | Markdown | 整理前散件数、整理后文件夹数与散件数、失败项清单 | 前后总数一致，散件归零 |
| 自检报告 | `scripts/kb_organizer_check.py` 输出 | 方案条目数、命名规范、命名重复、批次上限、危险短语 | 退出码 0；非 0 项逐条整改 |
| 重复文件清单 | Markdown（可选） | 疑似重复条目与两库 `media_id` | 仅列清单交用户手工处置，本技能不做移除以外的处置 |

所有对外材料中，凡涉及项目条数、金额、时间，**注明来源**；未核实处标【待核：来源】并给出取数路径。

## 降级路径与失败模式

本技能对每一类**失败模式**都规定了**降级**口径与**补救**动作；任一环节触发**异常**时，一律走**错误处理**分支而非静默跳过。核心原则是：保留**失败分支**的中间记录以支持**断点续跑**，为每个环节设置**边界条件**校验，对不可用接口做**容错**与**防御**性处理，外部依赖必须准备 **fallback** 与**回退**方案，瞬时故障允许有限**重试**，最坏情形退到**兜底**方案并向用户如实披露，不得掩盖失败结果。

| 场景 | 触发条件 | 降级与补救处置 |
|---|---|---|
| 接口分页异常 | `get_knowledge_list` 返回 `is_end=false` 未按预期翻页 | **错误处理**：以 `next_cursor` 续翻，上限 10 次；仍异常则降级为"标题抽样 + 关键词聚类"出粗分方案并说明 |
| 超大知识库 | 散件数 > 500 条 | **降级**：按主题分批处理，先做最清晰的类别；每批完成后落盘记录以支持**断点续跑** |
| 接口超时／限流 | 返回网络超时或限流码 | **容错**：可重试错误自动**重试**一次（间隔递增）；不可重试错误跳过并记录 `media_id` 与 `err_msg` |
| 移动部分失败 | 批次返回任一 `ret_code≠0` | **补救**：凭执行清单的 `media_id` + 原路径定位失败项并补移，不重扫全库；不**fallback** 到"口头确认已归位" |
| 条目无法归类 | 无任何关键词命中任何文件夹 | **兜底**：先入"其他"夹并列清单；"其他"超过 10 条时改逐条问用户，避免形成第二个杂物堆 |
| 文件夹名含义模糊 | 名称缩写、语义不明 | **防御**：先浏览夹内 3–5 条内容再判断归属，不按名称猜测 |
| 跨库移动诉求 | 用户要求把 A 库内容并到 B 库 | **边界条件**限制：接口要求 src 与 dst 为同一 kb_id，主动声明不在能力范围内，改为逐库串行 + 统一命名前缀 |
| 重复文件清理诉求 | 用户要求去重 | 仅输出疑似重复清单（含 `media_id`）交用户手工处置；本技能不执行移除动作，只做归类归位 |
| 根目录已整洁 | 扫描后散件 ≤5 条且结构清晰 | 直接判定"无需整理"，**不做**任何改动；对整洁库强行重分类属过度整理 |
| 命名冲突 | 目标文件夹重名或前缀写法不一 | **补救**：锁定统一写法"两位序号-主题"，重名夹先改名再移动；入口前跑 `scripts/kb_organizer_check.py` 校验 |
| 用户中途变更方案 | 建夹后要求换分类维度 | **回退**：以已建夹为基准重新生成映射，不半途混用两套维度；必要时先归"其他"再二次归类 |
| 沙箱会话中断 | 任务执行中被中断 | **断点续跑**：以执行清单与对照表为准恢复现场，已完成批次不重做 |

异常总则：任一环节失败先落中间记录（扫描快照、归类预览、执行清单）以支持**断点续跑**，不得因末段失败丢弃前序成果；所有**异常**须在交付回复中列明，不允许掩盖**错误处理**结果。

## 红线声明（固定拒绝口径）

1. **不做移除类操作**：本技能只做归类与移动，不执行任何内容清除动作；涉及重复与冗余条目，仅输出清单交用户手工处置。
2. **不越界替代专业判断**：不替代知识资产的权属认定、定密定级与档案合规审查，此类判断须由有权机构作出。
3. **不擅自替用户定分类**：分类维度必须由用户在 2–3 个方案中选择，未经确认不得建夹与移动。
4. **不承诺整理效果**：不承诺"整理后一定更好找""一定提升检索效率"等主观效果，只保证流程可执行、前后总数一致。
5. **不泄露条目内容**：整理过程只处理标题与元信息，不摘录、不扩散含个人信息或涉密内容的正文；对外材料一律脱敏。
6. **不编造数据**：涉及项目条数、金额、时间一律标注来源，未核实标【待核】，严禁臆造。

## 脚本工具

```bash
python3 scripts/kb_organizer_check.py --plan plan.json            # 校验分类方案（命名规范/重复/条目数）
python3 scripts/kb_organizer_check.py --skill . --json           # 技能目录自检（SKILL.md 体量/危险短语/依赖可达）
python3 scripts/kb_organizer_check.py --plan plan.json --max-folders 12 --max-batch 10
```

退出码：0＝全部通过；1＝存在硬性不合规项（命名重复、批次超限、危险短语）；2＝输入不足或参数非法（文件不存在/JSON 非法）。
