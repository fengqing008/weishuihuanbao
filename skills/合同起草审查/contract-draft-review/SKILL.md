# 合同起草与审查

## 概述

基于"合同范本库"知识库中的合同范本，帮助用户起草新合同或审查已有合同，最终输出带修订格式的 Word 文档。起草模式下生成规范合同文本；审查模式下标注风险条款、生成修改建议，并在 Word 中以修订标记呈现（删除内容红色删除线、新增内容蓝色下划线）。

## 你的工作方式

合同工作涉及以下步骤：

1. **意图识别与信息收集** — 判断起草还是审查，收集必要信息
2. **范本检索与加载** — 从知识库获取匹配的合同范本
3. **起草/审查执行** — 按流程生成合同内容或审查意见
4. **确认门** — 与用户确认内容后再生成 Word
5. **输出 Word 文档** — 调用脚本生成带修订格式的 .docx

## Phase 1：意图识别与信息收集

判断用户意图：

| 用户行为 | 模式 | 下一步 |
|---------|------|--------|
| "帮我起草一份XX合同" / "写一份XX协议" | 起草模式 | 收集合同要素 |
| "帮我审查这份合同" / 上传合同文件 | 审查模式 | 加载合同内容 |
| "这个条款有没有风险" / "修改这个合同" | 审查模式 | 定向审查 |

### 起草模式 — 需要收集的信息

必须确认以下要素（缺少时主动追问，不逐一罗列问题，用自然对话收集）：

- **合同类型**：买卖、租赁、委托、借款、技术开发、建设工程等
- **合同主体**：甲方/乙方信息（名称、角色定位）
- **核心交易条款**：标的物/服务、金额/价格、付款方式、交付/履约期限
- **特殊诉求**：重点关注的风险点、偏好的条款倾向

### 审查模式 — 需要收集的信息

- **合同全文**：用户上传文件则读取，用户粘贴文本则直接使用
- **审查视角**：用户代表哪一方（甲方/乙方），以便判断风险倾向
- **重点关注**：用户是否有特别关注的条款或风险点

## Phase 2：范本检索与加载

### 起草模式

1. 根据合同类型，在知识库"合同范本库"中搜索匹配的范本：
   ```
   search(source="kb", kb_id="（已脱敏）", question="XX合同范本")
   ```
2. 使用 `fetch` 加载范本全文内容
3. 以范本结构为骨架，结合用户提供的信息填充条款

### 审查模式

1. 如用户未上传文件但口头描述了合同类型，同样检索范本作为对比基准
2. 如用户已上传文件，直接读取文件内容进行审查
3. 范本在此模式下的作用：作为"标准参照"，帮助识别缺失条款和不合理约定

## Phase 3：起草/审查执行

### 起草模式流程

1. 以范本结构为蓝本，逐条起草合同内容
2. 根据用户信息调整具体条款措辞和参数
3. 补充范本中未涵盖但该类型合同应有的条款
4. 确保合同条款完整覆盖以下核心模块：
   - 合同主体信息
   - 标的与数量/质量
   - 价款与支付
   - 交付/履行
   - 权利义务
   - 违约责任
   - 不可抗力
   - 争议解决
   - 保密/知识产权（如适用）
   - 合同生效与期限

### 审查模式流程

1. 读取 `references/review-checklist.md` 获取审查要点清单
2. 逐条对照清单审查合同条款
3. 对每个发现的问题，记录：
   - **位置**：所在条款编号
   - **风险等级**：🔴 高风险 / 🟡 中风险 / 🟢 低风险
   - **问题描述**：具体风险点
   - **修改建议**：建议的新措辞（提供具体文本，而非模糊建议）
4. 将审查结果整理为结构化内容，包含：
   - 总体风险评级
   - 各条款审查详情（含原文与建议修改的对照）
   - 缺失条款提醒

## Phase 4：确认门

在生成 Word 文档前，将起草的合同全文或审查修改对比呈现给用户确认：

- **起草模式**：展示完整合同文本，提示用户确认
- **审查模式**：展示风险摘要表 + 主要修改建议，提示用户确认

> ⚠️ 必须等用户明确确认后才进入 Phase 5 生成 Word。如用户提出修改，先更新内容再重新确认。

## Phase 5：输出 Word 文档

### 数据准备

将确认后的内容整理为 JSON 格式，写入 workspace 临时文件，然后调用脚本生成 Word。

**起草模式 JSON 结构：**
```json
{
  "mode": "draft",
  "title": "合同标题",
  "parties": {
    "party_a": "甲方名称",
    "party_b": "乙方名称"
  },
  "sections": [
    {
      "heading": "第一条 合同主体",
      "paragraphs": [
        {"type": "normal", "text": "甲方：xxx，乙方：xxx"}
      ]
    }
  ]
}
```

**审查模式 JSON 结构：**
```json
{
  "mode": "review",
  "title": "合同标题",
  "review_summary": {
    "overall_risk": "中高风险",
    "total_issues": 5,
    "high_risk": 2,
    "medium_risk": 2,
    "low_risk": 1
  },
  "sections": [
    {
      "heading": "第三条 价款与支付",
      "paragraphs": [
        {
          "type": "unchanged",
          "text": "本合同总价款为人民币100万元。"
        },
        {
          "type": "delete",
          "text": "甲方应在合同签订后3日内支付全部价款。"
        },
        {
          "type": "insert",
          "text": "甲方应在合同签订后支付30%预付款，交付验收合格后支付60%，余款10%作为质保金于质保期满后支付。"
        }
      ]
    }
  ],
  "review_notes": [
    {
      "location": "第三条",
      "risk_level": "high",
      "issue": "一次性付全款对甲方风险极大，无任何付款保障",
      "suggestion": "改为分阶段付款"
    }
  ]
}
```

### 调用脚本生成 Word

```bash
python3 skills/contract-draft-review/scripts/gen_contract_docx.py outputs/{filename}.json
```

脚本会在相同目录下生成 `.docx` 文件。

生成后使用 `provide_file` 提供下载链接给用户。

## 资源目录

### scripts/
`gen_contract_docx.py` — 合同 Word 文档生成脚本，支持起草模式（纯文本）和审查模式（带修订标记）。

### references/
`review-checklist.md` — 合同审查要点清单，审查模式下按需加载。

## 工作流示例

### 示例 1：起草买卖合同

> 用户："帮我起草一份设备买卖合同，甲方是XX科技公司，乙方是YY制造公司，总价200万"

1. 识别为起草模式，确认合同类型为买卖合同
2. 搜索知识库"合同范本库"中的买卖合同范本，加载范本全文
3. 以范本为蓝本，填充甲方/乙方信息、价款200万、设备标的等
4. 展示完整合同文本，等待用户确认
5. 确认后生成 JSON → 调用脚本输出 Word

### 示例 2：审查租赁合同

> 用户上传了一份房屋租赁合同："帮我审查一下这份合同，我是承租方"

1. 识别为审查模式，读取上传的合同文件
2. 加载审查清单 `references/review-checklist.md`
3. 逐条审查，特别关注承租方利益保护
4. 输出风险摘要表，列出建议修改（含原文 vs 建议文本）
5. 用户确认修改方案后，生成带修订标记的 Word
