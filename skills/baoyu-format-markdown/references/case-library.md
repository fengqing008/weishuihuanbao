# 案例库（case-library）

本文件登记「Markdown 排版美化」技能的实战与方法示范案例。收录纪律：**只登记真实、可追溯的案例；无真实案例时以「方法示范案例」给出，标注为按技能默认参数推演，不得编造作者名、数字与结论。**

> 来源与溯源：结构口径参考 `references/title-formulas.md`（标题公式与规范）；排版原则遵循技能「只调整格式、不增删改写内容」的核心准则。

## 一、方法示范案例

### 案例 1：公众号长文由纯文本转为结构化 Markdown

- 背景：一篇 3000 字左右的纯文本稿，无标题层级、关键结论淹没在段落中、并列要点写成流水句。
- 做法：Step 1 判定为 plain text → Step 2 从读者视角分析出亮点、结构断点与可列表化内容 → Step 3 生成 frontmatter（title/slug/summary/description）→ Step 4 加 `##`/`###` 标题、加粗核心结论、把并列项转为无序列表、把对比数据转为表格 → Step 6 跑排版脚本（CJK 间距 + 强调修复）。
- 结果：输出 `{filename}-formatted.md`，扫码可读性显著提升，正文一字未增删。复盘：短句成段的内容保持散文体，避免「列表刷屏」。

### 案例 2：已带 Markdown 格式的技术文档优化

- 背景：已有 `#`/`**bold**`/代码块的技术文档，但标题层级跳跃（H2 直接到 H4），代码块围栏偶有未闭合。
- 做法：选择「Optimize formatting」→ 补齐跳跃的中间标题层级 → 用 `mdformat_check.py` 检出未闭合围栏并回修 → 统一为语言标注的围栏（```python 等）。
- 结果：层级连续、代码块闭合，渲染无溢出。复盘：交付前必跑自检脚本，围栏未闭合是最高频渲染事故。

### 案例 3：仅做排版微调（Typography fixes only）

- 背景：作者对结构满意，仅希望统一中文标点、补中英文间距。
- 做法：选择第 3 项「Typography fixes only」，在原文就地跑排版脚本，不生成副本；开启 `--spacing` 与 `--emphasis`，不改结构。
- 结果：标点与间距规范化，正文语义零改动。复盘：就地修改前应留副本或版本控制，便于回退。
