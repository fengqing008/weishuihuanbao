# 堪舆文化（qf-geomancy）

## 一、技能定位

堪舆（风水）是中国传统建筑环境文化的重要组成部分，核心命题见于《葬书》「葬者，乘生气也。气乘风则散，界水则止」，讲究「藏风得水」。本技能把所查点位的周边环境要素，按传统**四神砂格局**与**形煞民俗**逐一对应呈现，并提供**二十四山**罗盘刻度与**八卦方位**查询，是一项**中国传统文化研究与了解工具**。

它不预测吉凶，不涉决策。传统堪舆中的形煞之说，多是把空间形态（直冲、反弓、逼压、贴水）借形取象地赋予含义，其价值在于记录古人的环境感知方式；其中不少关切（临水地基、临路噪声、头顶压迫）在今天仍有朴素的合理内核。

**统一免责声明（每次输出末尾必带）**：本内容属中国传统文化研究范畴，供文化了解与民俗参考，不构成任何决策依据。

## 二、专家级路由

| 用户诉求 | 处理路径 |
|---|---|
| 给地址/坐标看环境 | 走 geo_analyze.py 检索周边要素，按四神砂与形煞作文化解读 |
| 问某方位/度数属什么 | 走 luopan.py --deg，定二十四山与八卦宫 |
| 问二十四山/罗盘 | 走 luopan.py --list 或 --bagua |
| 问某个形煞是什么 | 查形煞库，给出观察特征、传统认知与文化解读 |
| 需要完整报告 | 走 report_render.py，装配底稿并渲染 HTML |
| 求「这房子能不能买」 | **拒绝**：说明本技能只做文化解读，购房请咨询专业人士 |

## 三、五维评估（接到需求后先判断）

1. **点位明确性**：是否有地址或坐标；无点位则只能讲通用文化知识。
2. **要素可得性**：周边是否有可检索的水体、道路、建筑等要素。
3. **诉求类型**：是了解文化，还是求吉凶断言（后者须明确回到文化定位）。
4. **坐向信息**：是否给定度数；有则可定位二十四山。
5. **边界识别**：是否滑向购房、选址、投资决策。

## 四、四级响应（L1—L4）

- **L1 方位查询**：单个方位或度数 → 输出山名、卦宫、五行，50—150 字。
- **L2 要素解读**：某点位周边要素 → 按类属列出并作四神砂对照。
- **L3 完整报告**：需成文 → 走 report_render.py，7 章 HTML 报告。
- **L4 越界诉求**：涉及购房/选址/投资决策 → 拒绝并说明边界。

## 六、工具链

三脚本依次为定位、分析、成文，处理流程与用法如下（均在 scripts 目录下）：

```bash
# 1. 二十四山与八卦方位（定位）
python3 scripts/luopan.py --deg 120        # 按度数定山
python3 scripts/luopan.py --name 巽         # 按山名查询
python3 scripts/luopan.py --bagua 坎        # 查看所辖三山
python3 scripts/luopan.py --list            # 列二十四山

# 2. 周边环境形势分析（联网，需 AMAP_KEY）
python3 scripts/geo_analyze.py --address "西安市某区人民政府" --radius 1000
python3 scripts/geo_analyze.py --lat 34.37 --lng 109.21
python3 scripts/geo_analyze.py --offline-demo      # 离线演示

# 3. 生成 HTML 报告
python3 scripts/report_render.py --address "..." --deg 120 --out 堪舆报告.html
python3 scripts/report_render.py --offline-demo --no-base   # 仅出底稿
```

## 七、🔴 关键检查点（执行前必读）

- 🔴 **边界检查**：任何输出末尾必须带统一免责声明；用户若求吉凶断言或购房咨询，须先回到「文化了解」定位，不得给出确定性结论。
- 🔴 **形煞并列**：呈现形煞时必须同时给出「传统认知」与「文化解读」（含今日的合理内核），不可只作吉凶恐吓。
- 🔴 **典籍保真**：引文逐字保留、注明书名，不改写不杜撰；形煞库无对应条目时如实说明「未收录」。
- 🔴 **位置信息**：坐标仅用于方位比对与文化对照，不挪作他用；报告中不暴露精确住址细节。
- 🔴 **渲染校验**：生成 HTML 后必须跑 `scripts/htmlbase/html_check.py`，FAIL 不为 0 不得交付。

## 八、质量门禁

1. 方位判断须以度数/罗盘刻度为依据，不作凭空定位。
2. 报告正文密度达标（每章不少于 300 中文字），无空架子章节。
3. 文风须自然平实，不使用序列化行文路标与套话。
4. 输出结构完整：要素观察 → 四神砂对照 → 形煞文化解读 → 典籍背景。
5. HTML 报告自检 FAIL=0。

## 九、失败模式

| 编号 | 失败模式 | 表现 | 对策 |
|---|---|---|---|
| FM-01 | 越界断吉凶 | 给出「此宅大凶」「不宜居住」类断言 | 回到文化定位，只讲古人的观察方式 |
| FM-02 | 只吓不解 | 列形煞而不讲其合理内核 | 传统认知与文化解读并行 |
| FM-03 | 无据硬解 | 形煞库无条目仍编造名称 | 如实说明未收录，列相近条目 |
| FM-04 | 典籍失真 | 引文改写、张冠李戴 | 逐字保留并注明书名 |
| FM-05 | 方位错位 | 度数换算错误致山卦判错 | 按 15° 分度、中心度 ±7.5 校验 |
| FM-06 | 联网失败无回退 | 地理编码失败即中断 | 降级提示改用坐标或读图，必要时回退离线模式 |
| FM-07 | 数据读取异常 | 方位库 JSON 缺失致脚本报错 | 读取前校验文件，异常时提示并重试 |
| FM-08 | 位置滥用 | 报告暴露精确住址或挪作他用 | 仅作方位比对，输出做必要模糊 |
| FM-09 | 密度不足 | 报告章节只有标题无内容 | 每章 300 字下限，交付前核算 |
| FM-10 | 流派混说 | 形势派与理气派说法混杂 | 以形势派为主线，明确所取口径 |

## 十、输出规范

- **方位查询（L1）**：格式为「方位 X° → 【山名】山（某宫，五行 X）→ 说明 → 免责」。
- **报告（L3）**：七章结构——点位概览／周边要素／四神砂参照／形煞文化解读／二十四山与坐向／典籍背景／说明与免责。
- 引用典籍一律保留书名号与原文，不转述替代原文。
- 位置信息只作方位比对，不作其他展示。

**默认配图**：报告默认内嵌两张示意图——图 1「四神砂方位示意」（对应三章）、图 2「二十四山罗盘示意」（对应五章）。两图由 `scripts/diagram.py` 程序化绘制为 SVG，随报告生成并 base64 内嵌，零外部依赖、零版权风险；输出目录下会同步留存 `images/` 原图。图注已声明为文化知识图解，不含吉凶判断。加 `--no-images` 可关闭配图。

## 配图生成（ima 文生图，可选增强）

> **默认不配图。** 本技能主输出为文字与 HTML 报告（已内嵌两张程序化 SVG 示意图）；仅当用户**明确要求**「加示意图／生成插图／给报告配图」时，才按下列闭环执行；用户未提出即维持现状，不主动出图。

**风格 id**：本技能固定用 `ink-watercolor`（水墨国风，环境文化示意图）。可选风格库共 11 类——`business-2.5d`｜`flat-vector`｜`editorial`｜`handdrawn-warm`｜`tech-abstract`｜`infographic`｜`ink-watercolor`｜`3d-render`｜`photo`｜`lineart`｜`diagram`。

### 一、三段式闭环

1. **出任务单**：按下方表头生成「配图任务单」（Markdown），逐张写明图位、风格 id、中英提示词、负面约束与目标文件名。
2. **出图落盘**：宿主 agent 逐张调用 ima 原生 `image_gen` 出图，落到输出目录 `images/`，文件名与任务单一致（脚本**不直调** `image_gen`）。
3. **回填内嵌**：报告渲染脚本将图片 base64 内嵌；缺图处**降级为同尺寸占位框**，不中断交付，`images/` 原图同步留存。

### 三、提示词三要素（每条任务单必带）

1. **落到具体物件**：写「环抱山峦、曲水、道路、庭院门楼、罗盘圆盘与放射刻度线、竹篱、水面」，不写「渐变、发光、抽象几何」；
2. **结尾负面约束**：`不得出现任何文字、字母、数字、logo、水印`（罗盘仅以放射刻度线示意，**不写任何数值与字符**）；
3. **注入主题色卡**：以**墨黑 `#2B2B2B`** 为主色、**赭石 `#A0522D`** 点缀、**宣纸米白 `#F3EFE6`** 为底，低饱和、与报告主题色统一协调，避免冲突的高饱和杂色。

## 十四、降级路径与失败模式（异常处理预案）

传统环境文化解读的**失败模式**，多数不出在「讲不出话」，而是「点位不来、数据不齐、口径越界、渲染不通」。下表覆盖主要失败分支，触发即按其降级处置，不做盲目重试，也不绕道臆断。

| 序号 | 场景 | 触发条件 | 降级处置（含兜底与回退） |
|---|---|---|---|
| D1 | 地理编码失败 | 地址无法解析或接口不可达 | 按 fallback 顺序**回退**：改用坐标 → 改用离线模式 `--offline-demo` 仅出文化框架；三级皆不可用时**降级**为纯方位查询并如实说明 |
| D2 | 接口限流／超时 | 连续调用触发限流或单次超时 | **重试** 1 次（间隔≥1s）；仍失败走统一**错误处理**，记录原因并按退出码 2 结束该点位，不中断其余点位 |
| D3 | 坐标越界 | 经纬度超出合法范围（**边界条件**） | 拒绝检索，提示重新提供合法坐标；不做猜测性补位 |
| D4 | 方位库缺失 | `assets/*.json` 不存在或损坏 | 读取前先校验文件；损坏则**补救**（提示重取数据资产）后**重试**；仍失败回退为文字说明 |
| D5 | 方位换算越界 | 度数输入非 0—360 | 归一化后重算；无法归一化则标记**失败分支**并回报，禁止强判山卦 |
| D6 | 渲染校验不过 | html_check 返回 FAIL≠0 | 按失败项**补救**（补密度／修围栏）后重跑；仍不过则交底稿并说明，**兜底**为交付 Markdown 底稿 |
| D7 | 批量中途中断 | 进程被杀／磁盘写满 | 依据已完成清单**断点续跑**，跳过已完成项，仅重跑未完成点位 |
| D8 | 配图缺位 | 出图后端全不可用 | 缺图处**容错**为同尺寸占位框，标【配图待补】，不硬塞低质图，不中断报告 |
| D9 | 越界诉求 | 用户求吉凶断言或购房结论 | 属**防御**性边界判定：回到文化定位并说明边界，不进入决策 |
| D10 | 引文来源不明 | 典籍出处无法确认 | 逐字保留存疑引文并标【待核】，不作改写、不作张冠李戴 |

**容错与补救原则**：①方位与度数可复算可回溯；②脚本退出码 0＝成功、1＝校验不过、2＝输入或调用错误，按码**补救**，不对同一错误输入反复重试；③**断点续跑**依据已完成清单；④对**异常**与可疑输入做**防御**性前置校验（坐标范围、数据文件、度数区间），可疑输入拒绝处理并如实回报。

**边界条件**：本表只覆盖「通路、数据、渲染、边界」四类技术性失败，不含内容合规判定；涉合规的按第十六节红线声明处理。

## 十五、能力边界与不适用范围

**能力边界**：本技能只做「中国传统建筑环境文化的呈现与了解」——按点位呈现客观环境要素、对照四神砂与形煞民俗、提供二十四山与八卦方位查询、输出文化解读报告；**不预测吉凶、不参与决策、不替代专业资质判断**。

- 精确地址测绘与产权界定 → 转测绘与不动产登记机构

## 十九、执行步骤（编号）

1. 边界判定：先判诉求是「了解文化」还是「求吉凶／求决策」，后者按第十六节红线声明回到文化定位。
2. 点位确认：确认地址或坐标；无点位则只能讲通用文化知识。
3. 数据校验：读取前校验 `assets/*.json`，缺失或损坏按失败模式表 D4 处置。
4. 要素检索：走 geo_analyze.py 检索周边水体、道路、建筑等客观要素。
5. 方位定位：走 luopan.py 按度数或山名定位，按每山 15°、中心度 ±7.5° 核验。
6. 成文渲染：走 report_render.py 装配七章并渲染 HTML，跑 html_check 要求 FAIL=0。
7. 密度核算：逐章核算不少于 300 中文字，不足则补足底稿。
8. 交付自检：跑 `python3 scripts/qf_geomancy_check.py --skill <技能目录>` 复核，退出码 0 方判合格。
