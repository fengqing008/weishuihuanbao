# 失败模式详解

## 失败模式 1：过度压缩导致语义反转

**症状**：把 "do NOT use root" 压成 "use root"。
**原因**：压缩算法把否定词当冗余删了。
**修复**：保留所有 not/never/unless/if not/避免/禁止。压缩对象是修饰词，不是逻辑约束。

## 失败模式 2：代码块被误压缩

**症状**：把 `import pandas as pd` 缩写为 `import pd`。
**原因**：未识别 ` ``` ` 边界。
**修复**：检测到 ``` 后，整块内容 0% 改动，直到下一个 ```。

## 失败模式 3：安全信息被简化

**症状**："此操作不可逆，会删除生产库全部数据" 被压成 "会删数据"。
**原因**：把安全描述当冗余。
**修复**：涉及 rm -rf、DROP、DELETE、生产、不可逆、删除全部等关键词时，完整保留。

## 失败模式 4：技术术语被替换

**症状**："TCP 三次握手" 被压成 "联网"。
**原因**：把专业名词当可替换词。
**修复**：专业术语（HTTP/Kubernetes/PostgreSQL/DNS 等）保持原文，不做同义替换。

## 失败模式 5：客套未清除

**症状**：开头仍是 "好的，我来解释一下..."。
**原因**：未触发删除规则。
**修复**：第一句必须是实质内容，零前缀。

## 失败模式 6：压缩率不足

**症状**：回复和正常模式差不多长。
**原因**：只做了 L1（删废话），没做 L2-L4。
**修复**：输出后自检 token 数，≤ 正常模式 60% 才算合格。
