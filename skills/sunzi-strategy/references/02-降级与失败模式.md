# 降级路径与失败模式（references/02）

博弈推演的失败，多数不是「想不出策略」，而是「局势不清、要素打架、越界越轨」。
本文件登记常见**失败分支**及其**降级处置（含兜底方案）**，触发即按表处置，不得绕道臆断。

## 一、降级路径与失败模式表

| 序号 | 场景 | 触发条件 | 降级处置（含兜底方案） |
|---|---|---|---|
| F1 | 局势要素缺失 | 只给「我该怎么赢」，无双方实力 / 目标 / 约束 / 期限 | **不直接给结论**；降级输出五维要素清单 + 【待核：需补充局势】，补齐后重跑 |
| F2 | 目标不可衡量 | 目标为「赢」「压住对方」等模糊表述 | 降级为可衡量口径（量化到数字 / 比例 / 期限），标【待核】并回退到确认门 |
| F3 | 越界红线 | 情境涉及违法、暴力、欺诈或侵害他人权益 | **立即停止推演**，说明边界并引导合法渠道 |
| F4 | 篇章归属不可考 | 引用原文无法确定篇名或版本有异文 | 并列标注版本差异，不强行归篇；以 `references/01` 版本表为准 |
| F5 | 误作决策依据 | 用户将推演当作法律 / 投资 / 商业决策依据 | 明确本推演为思维框架应用，重大决策须转专业渠道 |
| F6 | 力量悬殊无可造之势 | 双方差距极大且无可用窗口与地形 | 如实给出「不宜正面相争」的评估，不给勉强方案 |
| F7 | 局势中途变化 | 推演过程中目标 / 约束 / 对手动作改变 | 以新要素**重跑**五维评估，不复用旧结论 |
| F8 | 交付物被误读 | 用户只取结论、不取推理链条 | 补交推理链条与适用条件，明示结论的边界条件 |

## 二、容错与补救原则

1. **边界条件**：任一要素缺依据即标【待核】并列明取数路径，禁止用行业惯例替代实际局势。
2. **可复算**：推演结论须可复算——列出五维取值与差值，便于第三方复核。
3. **错误处理**：脚本 `sz_check.py` 先看退出码（0 通过 / 1 校验不通过 / 2 输入不足），按码补救；**不重试**同一错误输入。
4. **断点续跑**：多轮推演可保存局势卡（JSON）为断点，要素补齐后从中断处继续，不必从头重推。
5. **防御**：对外交付前做一次红线自检（`sz_check.py --canvas`），命中红线即回退到边界声明。
6. **补救**：已发出的推演口径有误的，出具更正说明并留痕；原结论作废，不给「两版并存」。

## 三、兜底方案（工具侧）

- 无法运行 `sz_check.py`（无 Python 环境）时，**回退到人工核对**：按「五事齐备 / 目标可衡量 / 退出条件 / 红线未触」四项逐一勾选。
- 局势卡 JSON 不可解析时返回退出码 2，降级为**框架清单交付**（把五维表与要素清单直接给用户填写），不硬出结论。
