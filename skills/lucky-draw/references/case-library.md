# 案例库（模板与留痕清单）

> **编写纪律**：本文件不收录任何未经核实的具体案例。网络上流传的抽奖纠纷、摇号质疑事件多存在信息失真，直接引用会误导使用者。以下仅提供空白案例模板与核查清单，需要引用真实事件时请先核实来源并按【待填】补齐，核实完成前不得作为事实引用。

## 通用留痕核查清单

1. 候选池文件是否在抽取前已固定，并留存哈希与时间戳？
2. 排除名单的依据是否形成书面说明？
3. 权重列是否来自可核验的台账，而非临时口头给定？
4. 抽取过程是否有见证人或录屏？
5. 证明文件是否与名单同批归档，命名是否可检索？
6. `verify_proof.py` 的校验结论是否留存？
7. 若采用固定种子模式，种子是否在抽取完成后按约定公开？
8. 中签名单的流转范围是否受控，敏感字段是否已脱敏？
9. 是否收到质疑，质疑的答复口径与依据是否留档？

## 常见质疑与答复口径（模板）

| 质疑 | 答复口径（模板，按实际情况填写） |
| --- | --- |
| 「是不是内定的？」 | 出示候选池哈希与证明文件，说明随机源为操作系统熵源，并请对方运行校验脚本。 |
| 「为什么是他不是我？」 | 说明等权或加权规则、权重依据，以及抽取为无放回抽样。 |
| 「名单是不是抽完才改的？」 | 出示抽取前公示的 candidates_sha256 与公示时间。 |
| 「能不能重跑一遍验证？」 | 若为固定种子模式，公开 seed 并让对方复现；若为密码学模式，说明不可重放并出示结构与承诺校验结论。 |
