# 摇号抽签（lucky-draw）

## 一、专家定位与适用边界

本技能把「从一份已知且有限的名单中公平地选出若干人」这件事，做成可执行、可检查、可留痕的标准动作。核心引擎是 Python 标准库 `secrets` 模块——它直接读取操作系统熵源（`os.urandom`），生成的结果不可预测、不可从历史输出反推，与教学演示常用的 `random` 模块有本质区别。

定位覆盖四类问题：等权随机抽取、加权随机抽取、多轮抽取、带排除规则与跨轮去重的抽取。每一种都能附带一份可由他人独立复核的证明文件。

边界之外的三类请求不属于本技能：对未知结果做概率预测或走势判断；为博彩、赌博、彩票选号提供任何形式的号码或方案；把抽签当作规避内控、绕过审批流程的工具。碰到这三类，直接转出并说明理由。

## 二、触发条件与不适用场景

**触发条件**

- 用户给出名单（txt 每行一名、csv 含姓名列、json 数组）并要求「抽出 N 个人」。
- 用户提到年会抽奖、客户答谢、优秀员工评选、专家评审抽取、面试顺序抽签、保障房摇号、公租房分配、配额或名额分配、课堂随机点名、值班排班随机分配、红包或礼品分发对象确定。
- 用户要求「公平」「随机」「不能内定」「要能复核」「要留痕」「要出证明」。
- 用户要求加权抽取（老员工权重高、会员等级权重高）或多轮抽取且已中奖者不再参与。
- 用户要求用固定种子复现一次历史抽取，用于审计或公示。

**不适用场景（须拒绝或转出）**

- 赌博、博彩、网络博彩、赌球、赌马、彩票号码预测、开奖结果推算、抽盲盒的博彩化玩法——本技能不提供任何支持，原样拒绝并说明。
- 抽签结果要用来决定必须依法定程序表决的事项（如人事任免、重大投资决策），此类事项的合法性来自程序而非随机。
- 名单来源不明、包含未经授权的个人信息，或抽签目的涉及歧视性筛选。
- 用户要求「保证抽到某个人」——这是内定，直接拒绝。

一句话口径：**本技能不用于赌博、博彩、彩票预测等场景**，触碰即转出。

## 四、四级响应

| 级别 | 场景 | 动作 | 交付物 |
| --- | --- | --- | --- |
| L1 极简抽签 | 纯名单、等权、单轮、无留痕要求 | 直接执行脚本，回显中奖名单 | 中奖名单文本 |
| L2 常规抽签 | 涉及 csv、权重、排除、多轮之一 | 执行脚本，打印抽取摘要与人数核对 | 中奖名单文本 + 抽取摘要 |
| L3 可验证抽签 | 用户要求「能复核」「要留痕」 | 追加 `--prove` 产出证明，并跑一遍 `verify_proof.py` | 名单 + 证明 JSON + 校验报告 |
| L4 审计级抽签 | 现场摇号、对外公示、监管核查 | 用 `--seed` 固定种子 + `--prove`，出具第三方复核命令与流程脚本，归档全部输出 | 名单 + 可复现证明 + 校验报告 + 现场流程与归档说明 |

## 五、核心工作流

1. **确认用途**：问清抽签目的、参与方、是否涉及博彩红线。用途不合规则终止。
2. **收拢名单**：取到名单文件，识别格式（txt/csv/json），确认姓名列名与权重列名。
3. **清洗与核对**：统一编码为 UTF-8，去掉空行与注释行，统计人数，标记重复名，与用户核对候选池规模。
4. **装载排除名单**：读取 `--exclude` 文件，剔除已中奖、已弃权或本轮不参与的人员，确认剔除后池非空。
5. **设定抽取参数**：确定每轮人数 `--count`、轮数 `--rounds`、是否跨轮去重 `--unique`、是否加权、是否固定种子 `--seed`。
6. **执行抽取**：运行 `lucky_draw.py`，随机源默认取 `secrets`；需要复现审计时加 `--seed` 并加 `--replay`。
7. **产出证明**：加 `--prove` 写出证明 JSON，内含候选池哈希、随机源标识、每轮随机轨迹与熵摘要、抽取索引、结果哈希、承诺值与时间戳。
8. **校验与交付**：运行 `verify_proof.py` 校验证明，退出码为 0 表示一致；把名单、证明、校验结论一并交付，并附上复核命令。

## 六、交付物与输出规范

- **中奖名单**（`--out`）：单轮时每行一个姓名；多轮时按 `== 第 N 轮 ==` 分段。UTF-8 无 BOM，行尾 LF，姓名保持原样不排序。
- **证明文件**（`--prove`）：JSON，字段固定为 `schema`、`tool`、`version`、`created_at`、`mode`、`replay`、`random_source`、`seed`、`parameters`、`candidates`、`candidates_sha256`、`draws`、`winners`、`winners_sha256`、`commitment_sha256`。
- **抽取摘要**（标准输出）：随机源、seed、候选池人数（原始/排除）、抽取设置、逐条中奖名单、每轮熵摘要、两个 SHA256、时间戳、输出路径。
- **校验报告**：`verify_proof.py` 的十项检查结论与最终一行结论，退出码 0 或 1。
- 所有交付物写入同一目录，命名宜采用 `winners_<日期>.txt`、`proof_<日期>.json`，便于归档检索。

## 七、🔒 关键检查点

1. **随机源必须是 `secrets`**：默认模式禁止使用 `random.random`、`random.choice`、`random.shuffle` 直接决定中奖者；这两类函数使用可预测的梅森旋转算法，仅允许在 `--seed` 复现审计模式下经由固定包装使用。
2. **跨轮去重生效**：`--unique` 开启时，已中奖者的索引进入 `used` 集合，后续轮次候选池须剔除；去重模式下「轮数 × 人数」不得超过候选池人数。
3. **权重归一为正整数**：浮点权重统一乘以 `10^6` 取整，最小值为 1；遇到 0 或负数须报错退出，不得静默按等权处理。
4. **候选池非空且有下限**：排除后候选池为空须报错；候选池人数少于抽取需求时须报错，不得少抽后照常输出。
5. **结果可留痕且可校验**：证明文件须同时记录输入候选池哈希与输出名单哈希，索引须能回溯到候选池同名条目，承诺值须由两个哈希与时间戳合成；交付前跑一遍 `verify_proof.py`。
6. **场景合规前置检查**：确认用途不在博彩、赌博、彩票预测范围；确认名单来源合法、个人信息已获授权。
7. **编码与格式兜底**：读入文件按 UTF-8 处理并容忍 BOM，txt 忽略空行与 `#` 注释行，csv 缺列时明确报错而非跳过。

## 八、失败模式

| 编号 | 失败模式 | 后果 | 处置 |
| --- | --- | --- | --- |
| F1 | 用 `random` 模块抽签 | 序列可被预测，公平性失守 | 改回 `secrets` 默认模式 |
| F2 | 名单含重复姓名且未提示 | 同一人被计入多次，实质加权 | 打印重复名提醒，与用户确认是否去重 |
| F3 | 权重含 0 或负数 | 抽取异常或个别人永久不可中 | 报错退出，请用户修正权重列 |
| F4 | 排除文件编码或分隔符不符 | 排除失效，已中奖者被重复抽出 | 检查文件编码，逐行核验命中条数 |
| F5 | 去重模式人数超过候选池 | 后续轮次抽不满，结果残缺 | 提前校验并报错，请用户调整参数 |
| F6 | 证明文件缺输出哈希或索引 | 事后无法核验，公示遭质疑 | 补齐字段后重新生成证明 |
| F7 | 复用被篡改的证明 | 名单或结果被改动而不自知 | 依赖 `verify_proof.py` 的哈希与重放校验拦截 |
| F8 | 复现审计时 seed 提前泄露 | 结果在下一次抽取前被推算 | 审计场景把 seed 与证明一并公开，抽取前对承诺值先行公示 |

## 十一、使用示例（端到端）

```bash
# 1) 最简：等权单轮抽取（默认 secrets 密码学随机源）
python3 scripts/lucky_draw.py --input examples/names.txt --count 3 --out winners.txt

# 2) 加权 + 排除名单（csv 含姓名列与权重列）
python3 scripts/lucky_draw.py --input examples/staff.csv --name-col 姓名 --weight-col 权重 \
    --count 5 --exclude examples/excluded.txt --out winners.txt

# 3) 可复现审计：固定种子 + 证明 + 事后重放校验
python3 scripts/lucky_draw.py --input examples/names.txt --count 3 --seed 42 --replay \
    --prove proof.json --out winners.txt
python3 scripts/verify_proof.py --proof proof.json --input examples/names.txt --out verify.txt

# 4) 多轮 + 跨轮去重（已中奖者不再参与）
python3 scripts/lucky_draw.py --input examples/names.txt --count 2 --rounds 3 --unique \
    --out winners.txt --prove proof.json
```

示例输出片段：

```text
随机源：secrets（os.urandom）
候选池：30 人（排除后 27 人）  seed：—（密码学模式）
第 1 轮中奖（3 人）：【姓名A / 姓名B / 姓名C】
candidates_sha256：3f9c…   winners_sha256：a1b2…   commitment_sha256：7d4e…
```

## 十四、降级路径与失败模式（含容错与兜底）

本技能为"本地工具型"技能，无网络依赖；但输入、参数、环境仍可能出现异常。下表给出完整的失败模式与降级处置（场景｜触发条件（失败分支／边界条件）｜降级处置），确保任何**异常**都有**兜底**。

| 场景 | 触发条件（失败分支 / 边界条件） | 降级处置（回退方案 / 兜底） |
| --- | --- | --- |
| 名单文件缺失或路径错误 | `--input` 路径不存在、**错误处理**未命中 | 报错退出（退出码 2），回显期望路径与格式样例，提示改用 `examples/` 演示名单**重试** |
| 编码不兼容（GBK 等） | 读取时出现解码**异常** | **回退**到 UTF-8 with BOM 兼容读取并容忍 BOM；仍失败则提示用户转码为 UTF-8 后重跑 |
| csv 缺少姓名列 / 权重列 | 指定列名在表头中不存在 | 报错退出并打印实际表头，请用户核对列名；**不做**静默跳过或按等权**补救** |
| 权重含 0 或负数 | 解析到非正权重 | 直接报错退出（退出码 2），请用户修正权重列；**不得**按等权兜底 |
| 排除名单未命中或失效 | 编码/分隔符不符导致排除项为空 | 打印命中条数，为 0 时提示核查；命中异常时暂停抽取并请用户确认 |
| 候选池为空或人数不足 | 排除后池为空，或池人数 < 轮数×人数 | 提前校验并报错退出，请用户调整参数；**不做**少抽后照常输出 |
| 复现模式下 seed 冲突 | 同一 seed 与参数下结果不符 | 进入**容错**校验：对照 `verify_proof.py` 的重放结论定位差异，标记为不可复现并暂停公示 |
| 证明文件缺字段 | 缺输出哈希、索引或承诺值 | **补救**：补齐字段后重新生成证明，再跑一次校验；缺字段的证明不得对外公示 |
| 证明被篡改 | `verify_proof.py` 校验不一致（退出码 1） | 拦截交付：以候选池与结果的原始哈希为准重算，原证明作废并留存证据 |
| 长流程中断（多轮抽取中途停止） | 进程被杀、会话重置 | 支持**断点续跑**：以已产出的证明与 `used` 索引为准从断点继续，避免重复抽取 |
| 现场断网或脚本损坏 | 运行环境**异常**、脚本文件被改 | **降级**为手工种子抽签＋双人见证＋书面记录，事后补齐电子证明；此为**边界条件**下的最低留痕口径 |
| 用途触碰博彩红线 | 用户诉求属赌博/彩票预测 | 终止任务（**防御**优先），说明拒绝依据，不产出任何号码或方案 |

**统一口径**：脚本报错时先读退出码（0 成功 / 1 校验不一致 / 2 参数或输入错误），再进入上表对应行处置；禁止以"你自己再核一下"类空话代替处置。

## 十六、能力边界 / 不适用范围

- **能做**：等权／加权随机抽取、多轮抽取与跨轮去重、带排除名单的抽取、固定种子的可复现审计、证明文件生成与第三方校验。
- **不做**：博彩、赌博、彩票预测、开奖推算；内定结果；法定表决事项的替代程序；名单来源合法性审查以外的合规判断。
- **英文触发词（English triggers）**：lucky draw, random draw, raffle, lottery-free fair pick, weighted selection, draw winners, audit replay, cryptographic randomness, verifiable draw.

## 十七、可交付物与输出规范（清单）

| 交付物 | 格式 | 关键字段 / 规范 |
| --- | --- | --- |
| 中奖名单 | `.txt`（`--out`） | 单轮每行一名；多轮按 `== 第 N 轮 ==` 分段；UTF-8 无 BOM、行尾 LF，姓名保持原样不排序 |
| 证明文件 | `.json`（`--prove`） | `schema/tool/version/created_at/mode/replay/random_source/seed/parameters/candidates/candidates_sha256/draws/winners/winners_sha256/commitment_sha256` |
| 抽取摘要 | 标准输出 | 随机源、seed、候选池人数（原始/排除）、抽取设置、逐条中奖名单、每轮熵摘要、两个 SHA256、时间戳、输出路径 |
| 校验报告 | `.txt`（`verify_proof.py`） | 十项检查结论 + 最终结论行；退出码 0（一致）/ 1（不一致） |
| 归档命名 | — | `winners_<日期>.txt`、`proof_<日期>.json`、`verify_<日期>.txt`，同目录同批归档 |

**交付前置门（一键核验）**：

```bash
python3 scripts/lucky_draw.py --input examples/names.txt --count 3 --prove proof.json --out winners.txt
python3 scripts/verify_proof.py --proof proof.json --input examples/names.txt --out verify.txt
```
