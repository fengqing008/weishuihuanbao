# 图像增强案例库（case-library）

> 用途：为 image-enhancer 提供可回溯的真实案例登记位与来源指引。
> 纪律：本文件严禁写入编造的项目名、客户名、金额、日期、尺寸数据。所有未核实的字段一律保留【待填：…】占位，由使用者按真实素材回填并署名来源。

## 一、登记要求

1. 每个案例只登记真实发生过的处理任务，且能提供源图路径或台账编号作为佐证。
2. 凡涉及具体尺寸、体积、耗时、通过率的数字，必须来自脚本输出（manifest.json / failed.log / 质检记录），不得凭印象填写。
3. 涉及客户信息、项目名称、合同编号的字段，先做脱敏再登记；脱敏规则按使用者所在单位的保密口径执行。
4. 未取得佐证的条目保留【待填】占位，不得为凑满条目而虚构。
5. 每条案例登记后，在"复用价值"栏写明它可被哪个预设或哪类场景直接参考。

## 三、来源指引（去哪里找真实案例）

| 来源类型 | 获取位置 | 可用字段 | 备注 |
|---|---|---|---|
| 批量任务台账 | 批量输出目录的 manifest.json | 逐图参数、输入输出尺寸、体积、status | 数字直接引用，不得改写 |
| 失败清单 | 输出目录的 failed.log | 失败文件名、原因、处置动作 | 对照 SKILL.md 第八节失败模式表归类 |
| 质检记录 | references/quality-checklist.md 的勾选结果 | 逐项结论、未过项 | 未过项须写清处置方式 |
| 历史交付包 | 【待填：本单位交付包归档目录】 | 报告、增强图、原图对照 | 登记前先脱敏 |
| 用户回执 | 【待填：需求单 / 沟通记录编号】 | 用途、验收意见 | 仅作满意度参考，不作数据来源 |

采集口径提醒：
- manifest.json 与 failed.log 由 scripts/batch_enhance.py 自动生成，是唯一可信数据源。
- 手工估算的"看起来清晰多了"类描述不得进入数据字段，只可写入"主观备注"。
- 若某条案例只有主观描述而无脚本输出，登记时数据字段全部保留【待填】。
