# 失败模式详解与反例

## FM-01 无出处引文

**表现**：报告写「古籍云：眉长过目者主贵」，查不到是哪本书哪一篇。

**成因**：凭印象拼凑古典句式，看起来像引文，实际上无出处。

**处置**：规则库条目必须带 source 字段。手工补条时先查典籍再落笔，查不到就删。引用时格式固定为「《书名·篇章》」。

**反例**：`"classic": "《相书》云：……"` —— 《相书》不是具体书名，属无效出处。

## FM-02 滑向判断语

**表现**：「此相主早年得志」「三停匀称者多有所成」。

**成因**：写论述时不自觉地把主语换成了读者，古籍的「论述」变成了对读者的「断言」。

**处置**：改写为「古籍以三停匀称为贵相之说」。主语还给古籍，读者留在述说之外。

**反例**：`"reading": "浓长之眉主情义厚重"` → 正解 `"reading": "传统相学以浓长之眉论为情义厚重的表述，属面貌描述的文化比附"`

## FM-03 读图过度延伸

**表现**：从照片推断性格、职业、婚姻、健康。

**成因**：把形态描述当成了推理起点。

**处置**：只写形体，不写人。报告中的一切句子，去掉照片后仍应成立（即它是在讲相学，不是在讲某人）。

## FM-04 词库外描述

**表现**：写了「眉如新月」，词库无此词，规则匹配落空。

**成因**：观察时随手用词，未回到词表。

**处置**：录入后先跑 `--validate`；不在词库内则改用最近的规范词。确实需要新词时，同时补进 vocab.json 与 rules.json，两处齐备才算完成。

## FM-05 多张照片混用

**表现**：一次上传三张，一张眉毛浓、一张眉毛淡，报告里不知取哪个。

**成因**：省略了「一次一张」的约定。

**处置**：一次只处理一张面容。多张时逐张出报告；或明确指定以哪张为准，并在报告中说明。

## FM-06 妆造滤镜误读

**表现**：照片经过美颜，脸型被拉长、眼形被放大，形态描述与本人相差大。

**成因**：读图未识别照片是否经过处理。

**处置**：观察到明显化妆、美颜、滤镜痕迹时，在报告中加一行说明，提示形态可能失真；同时把描述词降到较宽的层级（如「眼形细长」而非更细的名目）。

## FM-07 十二宫位置述错

**表现**：把妻妾宫（鱼尾）说成男女宫（泪堂），或把疾厄宫（山根）说成命宫（印堂）。

**成因**：凭记忆写位置，未查表。

**处置**：位置一律取自 `assets/palace12.json` 的 pos 字段，脚本直读，不手写。

## FM-08 报告空壳

**表现**：特征全部缺失，仍生成一份只有章节标题的报告。

**成因**：未做前置检查。

**处置**：无有效特征时输出明确提示，不出空报告。

## FM-09 免责声明被吞

**表现**：报告内容丰富，页脚却没有免责声明。

**成因**：改动模板时漏掉页脚注入，或声明写在 Markdown 里被渲染吞掉。

**处置**：生成后用 grep 检查产物 HTML 是否含「不构成任何判断」字样；缺失即返工。

## FM-10 拒绝服务型越界

**表现**：用户要求「帮我看看这个人能不能合作」，技能顺势输出了对人的评价。

**成因**：把形态描述与人事判断混为一谈。

**处置**：明确告知本技能只作文化解读，不承接对人的评价性用途（招聘、婚恋、合作决策等），并说明理由。

## FM-11 引文数量夸大

**表现**：报告开头写「依据三十余部典籍」，实际规则库只引用六部。

**成因**：数字未与数据核对。

**处置**：报告中的数字（部位数、命中数、典籍数）一律由脚本从数据中算出，不手写。

## FM-12 图注与正文脱节

**表现**：图注写「面部十二宫分布」，图上却没有任何宫位标注。

**成因**：图注是模板文字，未随图调整。

**处置**：图注须指出图上实际可见的内容；无对应图时不留图注位。
