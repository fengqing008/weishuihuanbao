# 相学文化

两种用法：**上传照片**，识别可观测的面容形态特征，对照相学典籍中的相关论述，生成描述性的文化解读报告；**或不开照片**，按知识全集模式系统呈现相学文化——十二宫通论、五官详论、气色、神骨、议题史、流派典籍。

## 一、定位与边界

本技能处理的是**中国传统的相学文献与形态描述体系**。相学以五行比类脸形、以十二宫划分面部、以五官分论形态，是传统时代以最直观方式观察与记录相貌的一套话语。

定位边界（每次输出都要守住）：

| 维度 | 本技能采纳 | 一律不出现 |
|---|---|---|
| 表述视角 | 「传统相学论述为……」「古人认为……」 | 「你将……」「注定……」 |
| 结论性质 | 形态描述、象征意义、典籍引用、文化史陈述 | 运势判断、吉凶预测、改运承诺 |
| 引文要求 | 标书名与篇章，不逐字杜撰 | 无出处的「古籍云」 |
| 输出落点 | 文化知识介绍 | 指导现实决策 |

禁止出现的判断词：运势、命运、吉凶、富贵、克夫、克妻、旺夫、必、注定。
禁止出现的交易性暗示：请符、开光、大师指导、付费化解。

### 两种报告模式

| 模式 | 输入 | 输出 | 口径 |
|---|---|---|---|
| 个人特征解读（physiognomy） | 一张正脸照片 | 七节 HTML 报告 | 只作形态描述，主语还给古籍 |
| 相学文化知识全集（knowledge） | 无（读知识库） | 九节 HTML 报告 | 只作知识史陈述，不指向任何个人 |
| 照片×知识融合（combined） | 照片 + 知识库 | 八节 HTML 报告 | 知识在前、形态记录在后，均不作判断 |

两种模式共用同一条红线：**不针对真实个人作命运、寿夭、禄命、性情等任何判断**。知识全集模式若被用来「查我这张脸对应的断语」，应转回个人解读模式的口径（只描述形态），不得输出对人断语。

## 二、适用与不适用

适用：了解相学典籍体系、了解面部十二宫的划分、把照片上的可观察形态对应到传统论述、了解相学的议题史与流派典籍、作文化科普素材。

不适用：医疗与心理疾病诊断、收费测算与改运、人像美化与修图、人脸识别与身份核验、招聘婚恋等对人的评价性用途。遇到这类请求，直接说明本技能只作文化解读，不承接。

## 三、标准工作流

### 模式 A：个人特征解读（六步）

1. **读图观察**：由 AI 助手读取照片，按第四节的可观察项逐项观察形态 → 口头观察结论。
2. **特征规范化** → features.json。

```bash
python3 scripts/face_analyze.py --image 照片.jpg --out features.json   # 读图片信息 + 出模板
python3 scripts/face_analyze.py --template --out features.json         # 仅出空白模板
python3 scripts/face_analyze.py --validate features.json               # 校验特征是否在词库内
```

3. **规则匹配** → result.json。

```bash
python3 scripts/rule_engine.py --features features.json --out result.json
python3 scripts/rule_engine.py --list-rules        # 列全部 60 条规则
python3 scripts/rule_engine.py --list-palaces      # 列十二宫
```

4. **生成报告** → 相学文化解读.html。

```bash
python3 scripts/report_render.py --input result.json --out 相学文化解读.html
python3 scripts/report_render.py --demo --out 示例.html    # 用内置样例数据
```

5. **自检门禁**：跑第七节门禁，对照第八节失败模式自查。
6. **交付归档**：上传成果库并给出下载入口。

### 模式 B：相学文化知识全集（三步）

1. **查知识库**（可选，供预览或调用单件）。

```bash
python3 scripts/knowledge_query.py --overview            # 知识全景计数
python3 scripts/knowledge_query.py --palaces-full        # 十二宫逐宫通论
python3 scripts/knowledge_query.py --themes              # 议题史清单
python3 scripts/knowledge_query.py --show-theme 寿夭      # 单议题（含现代审视）
python3 scripts/knowledge_query.py --schools --timeline  # 流派 + 典籍年表
```

2. **生成报告** → 相学文化知识全集.html（九节）。

```bash
python3 scripts/report_render.py --mode knowledge --out 相学文化知识全集.html
```

3. **自检门禁**：议题模式自检（见第七节门 1-B），再交付归档。

## 四、可观察项与描述词

| 部位 | 观察点 | 描述词数 |
|---|---|---|
| 脸型 | 轮廓方圆、骨肉比例 | 6（五形 + 复合形）|
| 额部 | 饱满度、高阔度、印堂 | 6 |
| 眉部 | 浓淡、长短、走势、完整度 | 8 |
| 眼部 | 眼形、眼尾走势、卧蚕、神采 | 8 |
| 鼻部 | 鼻梁、准头、鼻翼、山根 | 8 |
| 口部 | 唇厚薄、口角、唇色、人中 | 8 |
| 耳部 | 耳垂、耳轮、耳位、贴张 | 6 |
| 颏部 | 方正度、丰满度、颐部、下颌线 | 6 |

合计 60 条形态描述词，每条都对应规则库中的一处相学论述与出处。

## 五、读图观察的字面规则

**🔴 只描述可观测的形态，不描述人。** 观察对象是「眉长过目」「准头饱满」这类形体特征，不是「这个人怎样」。凡是需要主观评价才能得出的描述，一律不写。

**🔴 不确定就不写。** 光线差、角度偏、遮挡多、分辨率低时，宁可少写几项，也不猜测。缺失项在报告里如实标为「—」。

**🔴 不使用带评价色彩的词。** 用「眼形细长」而非「眼小」，用「唇厚丰润」而非「嘴唇厚」，用「下颏尖削」而非「下巴尖」。

**🔴 妆造与滤镜干扰须声明。** 若照片有明显化妆、美颜、滤镜痕迹，在报告中加一行说明，提示形态可能失真。

**🔴 输出前核验引文出处。** 规则库中的每条论述都带 source 字段；若手工补充条文，须能指明书名与篇章，无出处者不得写入。

页脚固定免责声明：本报告为中国传统相学文化的知识介绍与形态描述整理，不构成任何判断、预测或决策依据。

**默认配图**：报告默认内嵌两张示意图——图 1「五行形相示意」（对应脸型归类）、图 2「面部十二宫分布示意」（对应第四节）。两图由 `scripts/diagram.py` 程序化绘制为 SVG，随报告生成并 base64 内嵌，零外部依赖、零版权风险；输出目录下会同步留存 `images/` 原图。两图均为文化知识图解，图注已声明非对面容之判断。加 `--no-images` 可关闭配图。

## 配图生成（ima 文生图，可选增强）

> **默认不配图。** 本技能主输出为文字与 HTML 报告（已内嵌两张程序化 SVG 示意图）；仅当用户**明确要求**「加配图／生成插图／给报告配图」时，才按下列闭环执行；用户未提出即维持现状，不主动出图。

**风格 id**：本技能固定用 `ink-watercolor`（水墨国风；**仅作抽象意象与器物**）。可选风格库共 11 类——`business-2.5d`｜`flat-vector`｜`editorial`｜`handdrawn-warm`｜`tech-abstract`｜`infographic`｜`ink-watercolor`｜`3d-render`｜`photo`｜`lineart`｜`diagram`。

### 一、三段式闭环

1. **出任务单**：按下方表头生成「配图任务单」（Markdown），逐张写明图位、风格 id、中英提示词、负面约束与目标文件名。
2. **出图落盘**：宿主 agent 逐张调用 ima 原生 `image_gen` 出图，落到输出目录 `images/`，文件名与任务单一致（脚本**不直调** `image_gen`）。
3. **回填内嵌**：报告渲染脚本将图片 base64 内嵌；缺图处**降级为同尺寸占位框**，不中断交付，`images/` 原图同步留存。

| 序 | 后端 | 前提 | 说明 |

### 三、提示词三要素（每条任务单必带）

1. **落到具体物件**：写「铜镜、砚台、竹简、卷轴、笔架、折扇、灯盏、案几、屏风」，不写「渐变、发光、抽象几何」；
2. **结尾负面约束**：`不得出现任何文字、字母、数字、logo、水印`；
3. **注入主题色卡**：以**墨黑 `#2B2B2B`** 为主色、**淡青灰 `#7A8B99`** 点缀、**宣纸米白 `#F3EFE6`** 为底，低饱和、与报告主题色统一协调，避免冲突的高饱和杂色。


## 七、质量门禁

**🔴 门 1：合规自检（分模式）。**
- 1-A 个人解读：`python3 scripts/xiangxue_check.py --file 报告.html`——扫描禁止判断词（运势／命运／吉凶／富贵／克／旺／注定／必然）与交易性暗示，命中即返工。
- 1-B 知识全集：`python3 scripts/xiangxue_check.py --file 报告.html --mode themes`——命题词（寿夭/禄命等）只登记提示，**严查对个人作论的痕迹（人称「你/您/此人/这个人」）与交易性暗示**，并须含命题史声明。

**🔴 门 2：引文出处齐备。** 每条论述须有 source；无出处条目不得进入报告。

**🔴 门 3：词库一致性。** 所有特征词须在 vocab.json 内，`face_analyze.py --validate` 返回 0。

**🔴 门 4：误差声明在位。** 报告须含识别误差声明与免责声明。

**🔴 门 5：HTML 自检。** html_check.py 须 FAIL=0，正文密度 ≥225 字/章。

## 八、失败模式

**FM-01 无出处引文。** 凭印象写「古籍云」，查不到书名与篇章。处置：规则库条目必须带 source 字段；手工补条时先查典籍再落笔，查不到则删。

**FM-02 滑向判断语。** 「此相主早年得志」一类的表述，看似古典实则已是判断。处置：改写为「古籍以……为论」，主语还给古籍，不还给读者。

**FM-03 读图过度延伸。** 从照片推断性格、职业、婚姻。处置：只写形体，不写人。

**FM-04 词库外描述。** 写了「眉如新月」，词库无此词，规则匹配不到，报告出现空条。处置：先 `--validate`，不在词库内则改用最近的规范词。

**FM-05 多张照片混用。** 一次上传多张，特征互相矛盾却混在一份报告里。处置：一次只处理一张面容；多张时逐张出报告，或明确以其中一张为准并说明。

**FM-06 妆造滤镜导致误读。** 美颜照片的形态与实际相差大。处置：报告中声明形态可能失真，并降低描述词的具体程度。

**FM-07 十二宫位置述错。** 把鱼尾与泪堂混为一处。处置：十二宫位置以 assets/palace12.json（及 palaces_full.json）的 pos 字段为准，脚本直读不手写。

**FM-08 报告为空壳。** 特征全部缺失仍出报告。处置：无有效特征时输出明确提示，不出空报告。

**FM-09 免责声明被吞。** 报告内容丰富，页脚却没有免责声明。处置：生成后 grep 检查产物是否含「免责声明」与「识别误差」字样；缺失即返工。

**FM-10 拒绝服务型越界。** 用户要求「帮我看看这个人能不能合作」，技能顺势输出对人的评价。处置：明确告知本技能只作文化解读，不承接对人的评价性用途（招聘、婚恋、合作决策等），并说明理由。

**FM-11 引文数量夸大。** 报告开头写「依据三十余部典籍」，实际只引六部。处置：报告中的数字一律由脚本从数据中算出，不手写。

**FM-12 图注与正文脱节。** 图注写「面部十二宫分布」，图上却无宫位标注。处置：图注须指出图上实际可见的内容；无对应图时不留图注位。

**FM-13 议题史滑坡为个人断语。** 知识全集模式写「寿夭」议题时，滑向「凡人中深长者寿」一类的个人断言。处置：命题必述为「古籍以……为说」，并逐条附现代审视；生成后必须跑 `xiangxue_check.py --mode themes`，命中人称即返工。

**FM-14 议题史美化古人。** 把相书的江湖话术写得像有道理。处置：审视段须落到可证伪性、认知偏差、历史语境与现实风险，不作反向立论。

## 十二、降级路径与失败模式（v1.2.0 增补）

> 本节为可执行容错层：读图、特征校验、渲染、配图任一环节出错，按「降级路径」逐级回退，不中断交付。

**降级路径与失败模式对照表**

| 场景 | 触发条件 | 降级处置 |
|---|---|---|
| 照片不可读 | 缺失 / 损坏 / 格式不支持 | 硬错误分支：提示重传，并回退到「仅知识查询」模式 |
| 读图特征不足 | 光线差 / 遮挡 / 分辨率低 | 兜底：宁少写不多猜，缺失项在报告中标「—」 |
| 特征词不在词库 | `--validate` 返回非 0 | 补救：改用最近的规范词，重跑 `rule_engine.py` |
| 规则匹配为空 | 无有效特征 | 降级为「不出空报告」，输出明确提示请用户补充特征 |
| 报告渲染失败 | 模板或依赖异常 | 回退到 Markdown 底稿交付，HTML 作为待补项 |
| 配图后端全不可用 | 多后端降级链全失败 | 降级为同尺寸占位框 + 任务单标【配图待补】，不硬塞低质图 |
| 多张照片混用 | 一次上传多张 | 失败分支单列：一次只处理一张面容，多张逐张出报告 |
| 妆造滤镜干扰 | 检出美颜 / 滤镜痕迹 | 在报告中加误差声明，降低描述词的具体程度 |

**失败模式清单（14 类，详见 references/failure-modes.md）**：FM-01 无出处引文；FM-02 滑向判断语；FM-03 读图过度延伸；FM-04 词库外描述；FM-05 多张照片混用；FM-06 妆造滤镜误读；FM-07 十二宫位置述错；FM-08 报告为空壳；FM-09 免责声明被吞；FM-10 拒绝服务型越界；FM-11 引文数量夸大；FM-12 图注与正文脱节；FM-13 议题史滑坡为个人断语；FM-14 议题史美化古人。

**容错与防御设计**：无出处条文不得进入报告；输出前跑 `scripts/xiangxue_check.py`（分模式）做防御式自检（退出码 0 通过 / 1 告警 / 2 硬错误），命中禁止项即返工；同时保留 html_check.py 的 HTML 自检门禁作为第二道防线。

## 十四、红线声明（固定拒绝口径）

1. **不作判断**：不作运势、命运、吉凶、富贵等任何推断，只作形态描述与传统论述引用；知识全集模式亦只作文化史陈述，不针对个人。
2. **不编造**：不杜撰典籍原文、篇章出处；查不到出处则删。
3. **不承接待办**：不承接改运、付费化解、请符开光等交易性请求。
4. **不替代专业**：不替代医疗与心理疾病诊断、人脸识别与身份核验。
5. **不用于评价人**：不用于招聘、婚恋等对人的评价性用途。
6. **不生成真人像**：配图禁止生成可辨识人脸与写实人物肖像，只作抽象意象与器物示意。
7. **不把命题落到个人**：议题史（寿夭/禄命/性情/才具/气色等）只述「古人如何论」，不判断任何真实个人。
