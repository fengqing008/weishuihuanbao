# 姓氏溯源

## 专家定位

以「文化解读 + 数据可视化」为基调的姓氏文化工具。将公安部官方姓名报告数据、公版姓氏学典籍与高德地图能力整合，输出既有考据深度、又具可视化表现力的姓氏报告。定位为**文化溯源与数据可视化**，不做算命、改运或吉凶判断。

## 适用边界

**适用**：查姓氏起源源流、郡望堂号、历史名人；看全国/省/地区人口分布；生成可视化姓氏报告。

**不适用**：族谱编纂与家谱校对（属专门谱牒工作）；基因溯源与血缘鉴定（属科学检测）；名人谥号、名号考释（非姓氏查询）。

## 数据来源与口径

| 层级 | 来源 | 口径 |
|---|---|---|
| 全国排名 | 公安部户政管理研究中心《二〇一九年全国姓名报告》 | 官方，按户籍人口数量排序 |
| 全国人口 | 第七次全国人口普查·百家姓排名（2022年发布） | 官方约数，前10位有逐姓数据 |
| 省级第一大姓 | 公安部《二〇一九年全国姓名报告》 | 官方，31省区市逐省公布 |
| 省级人口 | 按「全国占比 × 省常住人口」估算（省常住人口用2020七普） | 【估算值】，非官方逐省统计 |
| 地区级 | 姓氏地名密度（高德 POI：姓+村/庄/家/营/寨/屯） | 侧面证据，不作人口数字断言 |

**口径纪律**：官方数据标来源；估算值一律带【估算值】；地区级只作侧面参考。

## 工作流程

1. **识别姓氏**：从用户输入提取姓氏（含复姓，如欧阳）。
2. **基础查询**：运行 `scripts/surname_query.py` 取排名、人口、源流、郡望、堂号、名人。
3. **三级测算**：运行 `scripts/pop_calc.py` 出全国/省级口径。
4. **地名扫描**：需要地区级视角时，运行 `scripts/place_scan.py` 扫描姓氏地名密度。
5. **渲染报告**：运行 `scripts/report_render.py` 装配底稿并产出单文件 HTML。

## 脚本工具

**1. 姓氏基础查询**

```bash
python3 scripts/surname_query.py --surname 王
python3 scripts/surname_query.py --surname 王 --format json
python3 scripts/surname_query.py --list 20
```

**2. 三级人口测算**

```bash
python3 scripts/pop_calc.py --surname 王 --province 陕西
python3 scripts/pop_calc.py --surname 王 --province 陕西 --format json
```

**3. 姓氏地名扫描（需环境变量 AMAP_KEY）**

```bash
python3 scripts/place_scan.py --surname 王 --city 西安 --format json > scan.json
```

**4. 报告渲染（HTML 基座 v9）**

```bash
python3 scripts/report_render.py --surname 王 --province 陕西 --city 西安 \
  --scan-json scan.json --out 王姓溯源报告.html
```

配色用 `--theme`（golden/sunset/forest/ocean/minimal/botanical/galaxy/arctic/desert/tech），版式用 `--motif`（editorial/narrative/blueprint/classic）；基座缺失时加 `--no-base` 走简易模板。

## 输出规范

1. 报告为单文件自包含 HTML，含 KPI 卡、源流考据、郡望堂号、迁徙分布、本省本地五章以上；
2. 每章正文不少于 300 字；
3. 页脚固定免责声明「本内容属中国传统文化研究范畴，供文化了解与民俗参考，不构成任何决策依据」；
4. 渲染后须跑 html_check.py，要求 FAIL=0。

**默认配图**：报告默认内嵌「姓氏人口排名示意」（对应一章，全国前十姓条形图 + 本姓排名定位，本姓自动高亮）。该图由 `scripts/diagram.py` 依排名数据程序化绘制为 SVG，随报告生成并 base64 内嵌，零外部依赖、零版权风险；输出目录下会同步留存 `images/` 原图。图注已声明数字为约数。加 `--no-images` 可关闭配图。

## 配图生成（ima 文生图）

> **默认不配图**——报告默认已内嵌程序化 SVG「姓氏人口排名示意」（见上节，零依赖、零版权风险），AI 配图属**可选题图增强**；仅当用户明确要求配图（如"给报告配几张水墨题图""要一份有插图的姓氏报告"）时，才按下述闭环执行。**AI 配图定位为「报告章节题图」**，不替代默认的排名示意 SVG（该 SVG 仍按原逻辑生成并 base64 内嵌）。

配图统一由 ima 自带文生图（宿主 `image_gen` 工具）生成。**脚本不直接调 `image_gen`**（脚本无法直调宿主工具），统一走三段式闭环：

1. **出任务单**：报告底稿确定章节后，按「源流考据 / 郡望堂号 / 迁徙分布 / 本地分布」各章列「配图任务单」（表头见下）。题图只放在章首，**不逐段插图**；画面内不出现任何文字（姓氏字、章名由排版层叠加）。
2. **出图落盘**：宿主 agent 逐张调 `image_gen`，图落 `images/`（与排名示意 SVG 同目录），文件名与任务单「输出文件」列一致；重复出单时标 `[√ 已有]` / `[待生成]`，只补缺口。
3. **内嵌与降级**：`report_render.py` 按既有机制将图片 base64 内嵌进单文件自包含 HTML（随包携带亦可）；**缺图处降级为占位框**（写明图位与提示词），不中断报告生成；`--no-images` 时仍照旧关闭全部配图。

**多后端降级链**（按序尝试，命中即止）：`image_gen`（主，ima 环境、无需 Key）→ `pollinations-image`（免 Key、仅需联网，SkillHub / WorkBuddy 跨平台兜底）→ `generate-image`（百炼 Qwen-Image，需 DASHSCOPE Key）→ 全不可用则只交「配图任务单」并标 **【配图待补】**，**禁止硬塞低质占位图**。**无 `image_gen` 时一律走 pollinations 兜底。**

## 🔴 关键检查点（执行前必读）

- 🔴 **数据溯源**：所有人口数字须标注来源；省级估算值必须带【估算值】，不得将估算当官方数据输出。
- 🔴 **红线把关**：全文不得出现算命、改运、吉凶、旺衰等表述，只做文化解读。
- 🔴 **围栏语法**：`:kpi` 等围栏须单独成行，内容行用竖线分隔；行内写内容会导致围栏泄漏（FENCE_LEAK FAIL）。
- 🔴 **密度校验**：渲染后必须跑 html_check，DENSITY 未达 300 字/章须补足底稿再交付。
- 🔴 **高德降级**：AMAP_KEY 缺失或限流时，地区级扫描降级为说明文字，不得中断报告生成。

## 失败模式

1. **数据集未收录**：查询不在前100大姓与前20详细源流库中的姓氏，surname_query 返回空并退出码 2；此时应改出通用源流说明，不编造具体源流。
2. **高德限流/超时**：place_scan 连续调用触发 429 或超时，脚本已内置 0.5s 间隔与逐词重试；仍失败则该章降级为说明文字。
3. **围栏泄漏**：把 `:kpi「...」` 写成行内会残留原文（FENCE_LEAK FAIL），须改为块状写法。
4. **密度不足**：底稿各章偏短会触发 DENSITY FAIL/WARN，须为每章补足 300 字以上有信息量的正文。
5. **基座副本缺失**：`scripts/htmlbase/` 未就位时报告降级为简易模板，须先补齐基座副本。
6. **复姓误切**：单字切分会把「欧阳」拆成「欧」，须先按复姓表整体匹配。

## 降级路径与失败模式（异常处理预案）

姓氏查询的**失败模式**，多数不出在「查不到人」，而是「数据未收录、接口限流、围栏渲染不通、口径越界」。下表覆盖主要失败分支，触发即按其降级处置，不做盲目重试，也不绕道臆断。

| 序号 | 场景 | 触发条件 | 降级处置（含兜底与回退） |
|---|---|---|---|
| F1 | 数据集未收录 | 姓氏不在前 100／前 20 详细库 | 按 fallback **回退**为**通用六类源流**说明（以国为氏／以邑为氏／以官为氏／以职业为氏／以王父字为氏／赐姓改姓），标【暂未收录】，**降级**输出并说明数据边界，不冒充分值 |
| F2 | 高德限流／超时 | 连续调用触发 429 或超时 | 脚本内置 0.5s 间隔与逐词**重试**；仍失败走统一**错误处理**，该章**降级**为说明文字，不中断报告 |
| F3 | 高德无 Key | 环境变量 AMAP_KEY 未配置 | 地区级**兜底**为说明文字（不检索），报告照常生成 |
| F4 | 围栏泄漏 | `:kpi「...」` 写成行内 | 改为块状写法（单独行 `:::kpi`＋内容行＋`:::`）后**补救**重跑 |
| F5 | 密度不足 | 底稿各章偏短（**边界条件**） | 逐章补足 300 字以上有信息量正文后重跑 |
| F6 | 基座副本缺失 | `scripts/htmlbase/` 未就位 | 从基座源补副本，或用 `--no-base` **兜底**为简易模板 |
| F7 | 复姓误切 | 单字切分把「欧阳」拆成「欧」 | 先按复姓表整体匹配并**补救**；无法匹配则标记**失败分支** |
| F8 | 渲染告警 | md2report 返回非 0 | 查看 stderr 尾部（多为围栏或密度），按项**补救**后**重试** |
| F9 | 数据资产损坏 | `assets/*.json` 缺失或解析**异常** | 读取前校验；损坏则提示重取数据资产，**回退**为通用说明 |
| F10 | 批量中途中断 | 进程被杀／磁盘写满 | 依据已完成清单**断点续跑**，仅重跑未完成项 |
| F11 | 越界诉求 | 用户求「我姓 X 一生运势」类判断 | 属**防御**性边界判定：回到文化溯源定位并说明边界，不进入决策 |

**容错与补救原则**：①人口数字可复算可回溯；②脚本退出码 0＝成功、1＝校验不过、2＝输入或调用错误，按码**补救**，不对同一错误输入反复重试；③**断点续跑**依据已完成清单对账；④对**异常**与可疑输入做**防御**性前置校验（姓氏字符、省名、资产文件、围栏写法），可疑输入拒绝处理并如实回报。

**边界条件**：本表只覆盖「数据、接口、渲染、边界」四类技术性失败，不含内容合规判定；涉合规的按「红线声明」处理。

## 能力边界与不适用范围

**能力边界**：本技能只做「姓氏文化的溯源呈现与人口分布数据可视化」——六类源流考据、郡望堂号、历史名人、全国／省级／地区级分布呈现、单文件 HTML 报告；**不做算命、改运、吉凶判断，不做族谱校对与血缘鉴定**。

**不适用范围（不在范围，转其他事项）**：

- 族谱编纂与家谱校对 → 属专门谱牒工作
- 基因溯源与血缘鉴定 → 属科学检测机构
- 名人谥号、名号考释 → 非姓氏查询范畴
- 算命、改运、运势判断 → 本技能只呈现文化，不作任何预测
- 户籍人口精确统计与身份核验 → 转公安户政等有权机关

**场景路由表**：

| 用户诉求 | 走向 | 关键判据 |
|---|---|---|
| 查某姓起源与分布 | surname_query → pop_calc → report_render | 是否在前 100／前 20 库 |
| 只看全国排名 | surname_query --list N | assets/surname_rank.json |
| 看某省情况 | pop_calc --province X | 省级为第一大姓（官方）或估算 |
| 看某市情况 | place_scan --surname X --city Y | AMAP_KEY 是否可用（侧面证据） |
| 求运势判断 | 拒绝并说明边界 | 「红线声明」第 1 条 |

**English triggers**: surname origin, Chinese family name, surname distribution, Hundred Family Surnames, ancestral origin tracing, surname population atlas, Chinese genealogy culture, surname lookup.

## 红线声明

1. **不得**输出算命、改运、吉凶、旺衰等预测性表述；本技能只做文化溯源与数据呈现。
2. **不得**用估算值冒充官方口径；省级估算必须带【估算值】并给出方法。
3. **不得**把地区级姓氏地名密度换算为人口数字；该方法只作侧面证据，须显式声明。
4. **不得**编造未收录姓氏的具体源流与名人；**禁止**为凑内容臆造【待核】以外的数据。
5. **不得**在报告中暴露用户身份与精确住址；用户提供的个人信息仅用于本任务。
6. **不得**生成伪装成真实文献与实景的 AI 配图；族谱、古籍、拓片、实景一律用真实素材并标注来源。

## 执行步骤（编号）

1. 边界判定：先判诉求是「文化溯源」还是「求运势判断」，后者按「红线声明」回到文化定位。
2. 识别姓氏：从输入提取姓氏（含复姓，先按复姓表整体匹配）。
3. 基础查询：跑 `scripts/surname_query.py` 取排名、人口、源流、郡望、堂号、名人；未收录按失败模式表 F1 兜底。
4. 三级测算：跑 `scripts/pop_calc.py` 出全国／省级口径，估算值带【估算值】。
5. 地名扫描：需地区级时跑 `scripts/place_scan.py`，缺失 Key 按 F3 降级。
6. 渲染报告：跑 `scripts/report_render.py` 装配底稿并产出单文件 HTML，跑 html_check 要求 FAIL=0。
7. 密度核算：逐章核算不少于 300 中文字，不足按 F5 补足后重跑。
8. 交付自检：跑 `python3 scripts/qf_surname_check.py --skill <技能目录>` 复核，退出码 0 方判合格。
