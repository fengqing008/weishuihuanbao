# 翻译失败模式清单（baoyu-translate / references）

配套 SKILL.md 的「失败模式」章节，按环节归集处置路径。

## 一、配置环节

| 情形 | 现象 | 处置 |
|---|---|---|
| 三级路径均无 EXTEND.md | 参数取不到，术语缺失 | 按 BLOCKING 要求先跑首次配置；用户拒答时回退默认配置并标注 |
| EXTEND.md 字段写错 | 解析失败 | 按 references/config/extend-schema.md 修正字段名后重试 |
| 用户中途改目标语言 | 已译块作废 | 停止当前流程，确认新参数后从 Translate 环节重跑，不拼接旧块 |

## 二、运行环境环节

| 情形 | 现象 | 处置 |
|---|---|---|
| 本机无 bun | 脚本无法启动 | 用 `npx -y bun <script>` 拉起 |
| npx 也不可用 | 脚本无法启动 | 降级为纯提示词翻译流程，不依赖脚本分块 |
| 输出目录不可写 | 写盘抛异常 | 切换到 workspace 可写目录后重试；不可用则只输出译文正文 |

## 三、输入环节

| 情形 | 现象 | 处置 |
|---|---|---|
| 源文件编码异常 | 读入乱码 | 统一转 UTF-8 后重试；无法判定原编码时索要另存版本 |
| 输入是 URL 且抓取失败 | 拿不到正文 | 转 web-scraper 或 scrapling-official 重试；仍失败索要正文粘贴 |
| 输入为扫描件 PDF | 无文字层 | 转 textin-xparse 先做 OCR，再进翻译环节 |
| 输入含图片文字 | 图文语言不一致 | 输出图片待本地化候选清单，转 image-text-edit，兜底在交付说明提示 |

## 四、分块环节

| 情形 | 现象 | 处置 |
|---|---|---|
| 超长文本未分块 | 尾部段落丢失 | 按 chunk_threshold 自动分块后重试 |
| 分块脚本异常 | 无分块产物 | 按标题手动切分，逐块翻译并回拼 |
| 指代跨块错位 | 译文前后不一致 | 回退到带重叠段的分块策略，或随块传入上文衔接段后重跑 |
| 回拼顺序错乱 | 段落次序与原文不符 | 按源文顺序号重排后重跑回拼 |

## 五、术语环节

| 情形 | 现象 | 处置 |
|---|---|---|
| 术语表格式错误 | 解析抛异常，术语未生效 | 用 `scripts/glossary_check.py` 预校验，按报错行回退修正 |
| 同一源词两个译法 | 全文术语不统一 | 以优先级高的条目为准，冲突项单列通知，重跑全文替换 |
| 源词与译词完全相同 | 该条实为未翻译 | 逐条核对，确认是专有名词后保留并标注 |
| BOM 或全角分隔符 | 解析错位 | 清洗为 UTF-8 无 BOM 与半角分隔符后重试 |

## 六、交付环节

| 情形 | 现象 | 处置 |
|---|---|---|
| refined 模式跳过审查 | 交付物只有粗译 | 回退补齐 Review 与 Polish，重跑终稿 |
| 交付稿与分块稿不一致 | 终稿漏改某块 | 以终稿为唯一交付件重新核对块级一致性 |
| 用户要求保留原格式 | Markdown 结构被打乱 | 回退重译该段，保持标题、列表与链接结构不变 |

## 七、兜底与续跑

1. 分块任务中断：以已完成的块文件为断点，续跑时只处理未完成块，避免整篇重译。
2. 术语表不可用：先完成翻译，交付时列出生词候选，供用户回填术语表后重跑替换。
3. URL 抓取与 OCR 均不可用：向用户索要正文文本，交付正文译文并标注未做图文本地化。
