# 梦象解读（qf-dream-symbolism）

## 一、技能定位

本技能把一段梦境描述拆解为可辨识的传统意象，逐一给出**典籍出处、民俗解读、心理象征**三层内容，并可按时间或数字起卦，参看《周易》六十四卦。它是一项**中国传统文化研究与了解工具**，不是预言机。

中国传统解梦讲究「以象取意」——《梦林玄解》所谓「梦者，象也；象者，像也。像其形，通其意，而吉凶可知矣」。本技能忠实呈现这套意象系统的原貌，包括其中的多解与反兆（如「梦哭主喜」「见棺主官财」），并明确标注其属民俗与古人认识，不构成任何决策依据。

**统一免责声明（每次输出末尾必带）**：本内容属中国传统文化研究范畴，供文化了解与民俗参考，不构成任何决策依据。

## 二、专家级路由

| 用户诉求 | 处理路径 |
|---|---|
| 「我梦见……」一句描述 | 走 dream_parse.py 提取意象，逐条给出三层解读 |
| 「梦见蛇是什么意思」单意象 | 直接查意象库，输出该意象的典籍+民俗+心理三层 |
| 「帮我起一卦」 | 走 gua_map.py，按时间或数字起卦，给出本卦与动爻 |
| 「六十四卦里泰卦是什么」 | 走 gua_map.py --name，输出卦辞与象义 |
| 需要完整报告 | 走 dream_render.py，装配底稿并渲染 HTML |
| 涉及健康/心理/投资/法律 | **拒绝**：说明本技能只做文化解读，指引寻求专业人士 |

## 三、五维评估（接到梦境描述后先判断）

1. **完整性**：是否有可辨识的物象（动物、自然、行为、场所等）。
2. **具体度**：物象是否有状态描述（如「蛇入怀」「水浑浊」）。
3. **多象性**：是否包含多个意象，需判断主次。
4. **情绪底色**：梦中情绪（惊恐／安然）影响解读取向。
5. **诉求类型**：是了解文化，还是求吉凶断言（后者须明确回到文化定位）。

## 四、四级响应（L1—L4）

- **L1 单意象咨询**：一个意象 → 直接输出三层解读，50—200 字。
- **L2 多意象解析**：2—5 个意象 → 逐条解读 + 主线概括。
- **L3 完整报告**：需成文 → 走 dream_render.py，7 章 HTML 报告（含卦象）。
- **L4 越界诉求**：涉及健康／心理／投资／法律判断 → 拒绝并说明边界。

## 六、工具链

三脚本依次为解析、起卦、成文，处理流程与用法如下（均在 scripts 目录下）：

```bash
# 1. 梦境意象解析（三层解读）
python3 scripts/dream_parse.py --text "我梦见一条大蛇入怀，随后飞上天空"
python3 scripts/dream_parse.py --file dream.txt --json
python3 scripts/dream_parse.py --list                    # 列全部意象
python3 scripts/dream_parse.py --category 动物            # 按类查看

# 2. 起卦与卦象查询
python3 scripts/gua_map.py --time "2026-09-26 12:30"     # 时间起卦（梅花易数）
python3 scripts/gua_map.py --num 7 5                     # 数字起卦
python3 scripts/gua_map.py --name 泰                     # 卦名直查
python3 scripts/gua_map.py --list                        # 列六十四卦

# 3. 生成 HTML 报告
python3 scripts/dream_render.py --text "梦见大蛇入怀，又飞上天空" \
  --time "2026-09-26 12:30" --out 梦象解读报告.html
python3 scripts/dream_render.py --text "..." --no-base   # 仅出 Markdown 底稿
```

## 七、🔴 关键检查点（执行前必读）

- 🔴 **边界检查**：任何输出末尾必须带统一免责声明；用户若求吉凶断言，须先回到「文化了解」定位，不得给出确定性预测。
- 🔴 **反兆提示**：引用「梦哭主喜」「见棺主官财」「梦死反主更生」等反兆条目时，必须与常义并列说明，不可单取一方。
- 🔴 **数据保真**：典籍引文保留原貌，不得改写或杜撰原文；意象库无对应条目时如实说明「未收录」，不得临时编造释义。
- 🔴 **健康红线**：梦境涉及持续失眠、噩梦、情绪困扰时，明确提示寻求专业医疗或心理帮助，不将梦象解读当作诊断。
- 🔴 **渲染校验**：生成 HTML 后必须跑 `scripts/htmlbase/html_check.py`，FAIL 不为 0 不得交付。

## 八、质量门禁

1. 意象识别命中应有依据（触发词匹配），无命中时输出可用意象提示而非硬凑。
2. 报告正文密度达标（每章不少于 300 中文字），无空架子章节。
3. 文风须自然平实，不使用序列化行文路标与套话（见 references/quality-checklist.md）。
4. 输出三层结构完整：典籍 → 民俗 → 心理象征。
5. HTML 报告自检 FAIL=0。

## 九、失败模式

| 编号 | 失败模式 | 表现 | 对策 |
|---|---|---|---|
| FM-01 | 越界断吉凶 | 给出「必发财」「必离婚」类断言 | 回到文化定位，只讲古人如何解读 |
| FM-02 | 单取反兆 | 只写「梦哭主喜」而不提常义 | 反兆与常义并列 |
| FM-03 | 无据硬解 | 意象库无条目仍编造释义 | 如实说明未收录，列出相近条目 |
| FM-04 | 典籍失真 | 引文被改写、张冠李戴 | 引文逐字保留，注明出处 |
| FM-05 | 健康误导 | 把噩梦解读为身体疾病 | 提示就医，不作医学判断 |
| FM-06 | 匹配噪声 | 短触发词误命中（如「水」命中「水杯」） | 触发词最长优先匹配 |
| FM-07 | 卦象滥用 | 以卦断事、给出成败结论 | 卦象仅作文化参照，明示不构成依据 |
| FM-08 | 密度不足 | 报告章节只有标题无内容 | 每章 300 字下限，交付前核算 |
| FM-09 | 渲染无回退 | 基座渲染失败即中断，无成品可交付 | 捕获异常后降级输出 Markdown 底稿（--no-base），并向用户说明原因 |
| FM-10 | 数据异常 | 意象库 JSON 缺失或损坏致脚本报错退出 | 读取前先校验文件，遇异常提示并重试，仍失败则明确告知用户 |

## 十、输出规范

- **单意象（L1）**：格式为「【类别】意象名 → 典籍：… 传统解读：… 心理象征：… 免责」。
- **报告（L3）**：七章结构——梦境概览／逐意象详解／心理象征层／典籍出处／卦象参照／综合解读／说明与免责。
- 引用典籍一律保留书名号与原文，不转述替代原文。
- 币值、数字类信息如出现，按千分位；无来源的判断不写。

**默认配图**：报告默认内嵌两张示意图——图 1「意象类别分布」（对应一章）、图 2「《周礼》六梦结构示意」（对应四章）。两图由 `scripts/diagram.py` 程序化绘制为 SVG，随报告生成并 base64 内嵌，零外部依赖、零版权风险；输出目录下会同步留存 `images/` 原图。图注已声明为文化知识图解，不含对梦境的解释或预测。加 `--no-images` 可关闭配图。

## 配图生成（ima 文生图，可选增强）

> **默认不配图。** 本技能主输出为文字与 HTML 报告（已内嵌两张程序化 SVG 示意图）；仅当用户**明确要求**「加意境配图／生成插图／给报告配图」时，才按下列闭环执行；用户未提出即维持现状，不主动出图。

**风格 id**：本技能固定用 `ink-watercolor`（水墨国风，契合梦境意象）。可选风格库共 11 类——`business-2.5d`｜`flat-vector`｜`editorial`｜`handdrawn-warm`｜`tech-abstract`｜`infographic`｜`ink-watercolor`｜`3d-render`｜`photo`｜`lineart`｜`diagram`。

## 十四、红线声明（固定拒绝口径）

1. **不得**给出吉凶断言（「必发财」「必离婚」「一定会出事」），只讲古人如何解读。
2. **不在范围**内：医疗与心理疾病诊断；涉健康困扰须提示就医。
3. **严禁**以卦象断事、以梦象作投资 / 婚恋 / 法律决策依据；卦象仅作文化参照。
4. **严禁**改写、杜撰典籍引文；引文须逐字保留并标注出处。
5. **不得用于**预测：本技能为传统文化研究与了解工具，**不做**命运预测与占断。
6. **不得**单取反兆条目；「梦哭主喜」「见棺主官财」「梦死反主更生」须与常义并列说明。
7. **限定**用途：任何输出末尾必带统一免责声明，缺声明不予交付。

## 十五、能力边界与不适用范围

本技能只做**中国传统梦文化解读**，输出为文化了解材料，不构成任何决策依据。以下**不适用**本技能，应按场景分流：

| 用户诉求 | 处理路径 |
|---|---|
| 健康 / 失眠 / 噩梦困扰 | **拒绝**：指引专业医疗或心理帮助 |
| 投资 / 婚恋 / 法律决策 | **拒绝**：指引专业机构 |
| 吉凶预言与命运预测 | **拒绝**：回到文化定位，只讲古人的解读 |
| 姓名、生日、八字排盘 | 转「姓氏溯源」等对应文化技能 |
| 住宅环境文化（堪舆） | 转「堪舆文化」技能 |
| 单纯《周易》卦辞查询 | 可走本技能 `gua_map.py --name`，但须声明文化定位 |

| 报告底稿 | Markdown | `dream_render.py --no-base` 产出，可二次编辑 |
| 质检报告 | 命令行文本 / JSON | `scripts/dream_check.py --file <报告> --json` |
| 配图任务单（可选） | Markdown | 仅在用户明确要求配图时产出 |

**输出规范**：单意象格式为「【类别】意象名 → 典籍：… 传统解读：… 心理象征：… 免责」；报告型为七章（梦境概览／逐意象详解／心理象征层／典籍出处／卦象参照／综合解读／说明与免责）；引用典籍保留书名号与原文；无来源的判断不写；数字类信息按千分位。

## 十七、失败模式与降级路径（fallback / 容错预案）

| 序号 | 场景 | 触发条件 | 降级处置（含兜底方案与回退策略） |
|---|---|---|---|
| FM-11 | 基座渲染失败 | HTML 基座抛**异常**、无成品可交付 | 捕获异常后**降级**输出 Markdown 底稿（`--no-base`），向用户说明原因，交付不断链 |
| FM-12 | 数据资产损坏 | 意象库 / 卦库 JSON 缺失或不可解析 | 读取前先校验；失败则**重试**一次，仍失败即明确告知用户并降级为可用资产子集 |
| FM-13 | 配图后端不可用 | `image_gen` 全链不可用 | 按多后端**降级链**逐级**回退**：`image_gen` → pollinations → generate-image；皆不可用则交付任务单标 **【配图待补】**，**兜底**为同尺寸占位框，不硬塞低质图、不中断交付 |
| FM-14 | 意象无命中 | 触发词全部未匹配到条目 | **边界条件**：如实输出「未收录」与相近条目，不硬凑释义 |
| FM-15 | 输入缺失 | 用户仅给「我梦见了一个梦」等无物象描述 | 降级输出可用意象清单请用户确认，**不重试**空输入、不代为假设 |
| FM-16 | 多轮迭代中断 | 长报告生成中途停止 | 以已生成章节为**断点续跑**起点，不从头重来 |
| FM-17 | 用户越界追问 | 反复索取吉凶断言 | **防御**性回到文化定位，必要时**补救**：出具边界说明并留痕 |

**容错与补救原则**：①任一判定缺依据即标「未收录／待核」，禁止用行业惯例替代典籍原文；②红线自检先跑退出码（0 通过 / 1 不通过 / 2 输入不足），按码**错误处理**与**补救**；③**失败分支**已由 `references/failure-modes.md` 详列反例，交付前对照复核。
