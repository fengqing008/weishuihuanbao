# 污水厂环保合规与督察整改实务

污水处理厂是环保监管的常设对象：进出水在线监测联网、排污许可载明限值、污泥与药剂纳入固废与危化品管理、环保税按排污当量计征。任何一个环节失守，后果从责令改正、罚款直至行政拘留与刑事责任。本技能把运营期环保合规拆成可勾选的义务清单，把督察检查问题拆成可销号的整改链条，把环保税拆成可核算的当量账，并给出陈述申辩与举证的成文骨架。

## 一、专家级路由（使用者层级）

| 层级 | 使用者 | 核心诉求 | 主产出 | 响应档 |
|---|---|---|---|---|
| A 现场运行值班长 | 厂长、中控值班长 | 这次检查查出什么、多久要改完 | 问题清单 + 整改台账行 | L1–L2 |
| B 环保专员 / EHS | 环保员、安全环保主管 | 整改方案怎么写、报告怎么销号、台账是否齐 | 整改方案 + 整改报告 + 佐证包 | L2–L3 |
| C 项目管理者 | 副总、运营总监 | 会不会被罚、罚多少、如何申辩减损 | 风险评估 + 陈述申辩书 + 迎检预案 | L3–L4 |
| D 集团合规 / 外部律师 | 集团法务、环保顾问 | 处罚可否撤销、数据是否涉刑、历史遗留如何清理 | 法律意见 + 听证意见 + 涉刑风险报告 | L4 |

判准原则：先定位使用者层级，再定响应档。层级判错，一份迎检自查会被写成技术问答，一份陈述申辩会被写成整改报告。

## 二、适用与不适用（技能边界）

适用：运营期环保合规自查清单编制、环保督察与执法检查问题整改方案与整改报告、排污许可执行报告（季报、年报）填报、危险废物鉴别与转移联单及贮存台账、环保税测算与纳税主体变更陈述、在线监测数据异常说明、行政处罚陈述申辩与听证意见、长江经济带生态环境警示片问题整改专项材料。

不适用，改走对应技能：
- 化验检测方法与质控 → `sewage-lab-assistant`；
- 运行日报周报与运营月报编制 → `wastewater-ops-report`；
- 排污许可申报表首次填报与许可量核算 → 排污许可证申领及填报助手；
- 环保设施三同时报告（预评价、验收评价） → 安全三同时报告编制；
- 工艺提标改造设计 → `wastewater-optimization`。

红线：本技能只做合规判断与成文，不做违法事实的隐匿与修饰；涉篡改监测数据、偷排、伪造台账的情形一律标注【待核：涉嫌违法，停止代办】并转入法律救济通道，不得输出"如何规避监管"的内容。

## 三、五维评估（任何任务先跑）

1. **义务对象**：本次针对哪一项义务——环评手续、排污许可、竣工验收、危废、在线监测、环保税、应急预案。对象错，依据与时限全错。
2. **依据层级**：法律（《环境保护法》《水污染防治法》《固体废物污染环境防治法》《环境保护税法》）、行政法规（《排污许可管理条例》《危险废物经营许可证管理办法》）、部门规章与标准（HJ 978-2018、HJ 212、GB 18597、GB 18918）、地方标准（如湖北、陕西地方限值）。地方标准严于国家标准的，从严执行。
3. **处置阶段**：处于事前自查、检查中配合、收到文书、整改实施、整改报告报送、销号验收、处罚救济哪一环。阶段不同，产出物不同。
4. **证据完整性**：是否具备环评批复、排污许可证正副本、验收意见、转移联单、危废台账、在线比对报告、维修与药剂投加记录。证据缺口即合规缺口。
5. **风险等级**：是否已被立案、是否涉及超标倍数、是否涉及数据造假（对应行政拘留与刑事）、是否涉及环保税欠缴滞纳金、是否涉及警示片公开曝光。风险等级决定是否升级到 L4 并联法务。

五维结论用一张表输出四项：义务对象、依据条文、处置阶段、风险等级，再定响应档。

## 四、四级响应（L1–L4）

| 档位 | 触发情形 | 动作 | 产出 |
|---|---|---|---|
| L1 | 问依据条文、问时限、问清单条目 | 直接答复并援引法律与标准全称条款 | 问答 + 依据出处 |
| L2 | 单个问题整改、单份台账、单次数据异常 | 走对应模板或脚本 | 整改台账行、整改方案、数据说明 |
| L3 | 一次检查多问题、季度执行报告、危废全流程、环保税更正 | 八步全流程 | 台账 + 方案 + 报告 + 佐证包 |
| L4 | 行政处罚、听证、警示片曝光、涉数据造假、涉刑、历史遗留主体清退 | 八步全流程 + 法务并联 + 风险处置 | 陈述申辩书 + 听证意见 + 风险报告 |

L4 触发词：行政处罚告知书、听证告知、长江经济带警示片、数据造假、移送公安、生态环境损害赔偿、纳税主体变更争议、复议与诉讼。

## 五、核心全流程（八步）

### Step 1 锁定义务对象与依据条文

写明厂名、所属主体、问题类别（水、气、固废、许可、税）、触发文件名称与文号。逐条列出适用法律条文与标准编号。判断是否属地方标准更严情形。此步产出"义务—依据"对照行，作为后续全部材料的骨架。依据检索模板见 `references/compliance-obligations.md`。

### Step 2 问题清单化与分级

把检查记录、责令改正通知、自查发现逐条转为问题清单，字段为：序号、问题描述、涉及点位、依据条款、问题等级、整改责任部门、责任岗位、整改时限、销号佐证要求。等级判定按整改时限分档：立行立改（3 日）、限期整改（15 日）、专项整治（30 日）、系统治理（60 日）。生成工具见 `scripts/rectify_ledger.py`，模板见 `references/rectification-templates.md`。

### Step 3 现场取证与证据固定

- 影像：整改前问题部位照片、视频，含时间水印。
- 记录：检查文书原件扫描、在线监测历史数据导出、药剂投加与设备维修记录。
- 台账：危废入库出库台账、转移联单、贮存间温湿度与防渗检查记录。
- 缺口：证据缺失的条目单列，标注【待核：缺×××证据，须补充】。数据异常举证要点见 `references/case-library.md`。

### Step 4 编制整改方案

整改方案骨架七段：问题概述、原因分析、整改目标、整改措施（技术措施 + 管理措施）、责任分工与时限、资金安排、跟踪与验收。技术措施写到可执行粒度（更换哪台设备、搭设多大仓库、新建几平方米贮存间、加装何种防渗层）；管理措施落到制度与岗位。逐条对齐 Step 2 清单，保证一条问题对一条措施。模板与范例见 `references/rectification-templates.md`。

### Step 5 组织实施与过程留痕

按方案节点推进并留存过程证据：采购合同与到货验收单、施工照片、制度签发页、培训签到表、台账启用记录。过程留痕是销号验收的凭据，无过程证据的整改不予销号。

### Step 6 编制整改报告

整改报告骨架七段：问题来源与整改背景、整改组织与责任、整改措施落实情况（逐条对账）、整改成效（含监测数据与现场照片）、举一反三与长效机制、附件清单、落款与日期。整改报告与整改方案、销号佐证构成一套"三件套"，缺一不可。模板见 `references/rectification-templates.md`。

### Step 7 销号申请与验收

提交销号申请，附整改报告、佐证包、承诺书。接受主管部门现场核查。核查发现整改不彻底的，退回整改并重置时限，重新走 Step 4 至 Step 6。销号台账与状态跟踪用 `scripts/rectify_ledger.py --status`。

### Step 8 归档与长效机制

建立环保合规档案：一问题一档（问题文件、方案、报告、佐证、销号文件）。同步更新排污许可执行台账、危废台账、环保税申报底稿。将本次问题反向映射到合规义务清单，补上制度缺口，形成下一周期自查要点。

## 七、脚本工具与命令

```bash
# 生成整改台账与销号清单（问题清单 CSV → 台账 CSV + Markdown 销号表）
python3 scripts/rectify_ledger.py --in 问题清单.csv --out 整改台账.csv --md 销号清单.md

# 按责任部门汇总与逾期预警
python3 scripts/rectify_ledger.py --in 问题清单.csv --out 整改台账.csv --today 2026-09-20

# 更新销号状态（closed 关闭 / verifying 验收中）
python3 scripts/rectify_ledger.py --in 整改台账.csv --out 整改台账_更新.csv --set "1=closed,3=verifying"

# 环保税测算（按污染物排放量与当量值计征，含达标免税与减排减征判定）
python3 scripts/env_tax_calc.py --plant 城区厂 --period 2026Q2 --tax-rate 1.4 \
    --cod 1200 --nh3n 180 --tp 25 --tn 260 --std 一级A

# 从废水排放量与水污染物浓度测算当量数与应纳税额（浓度 mg/L × 水量 m³）
python3 scripts/env_tax_calc.py --plant 城区厂 --period 2026Q2 --tax-rate 1.4 \
    --volume 900000 --conc "COD=18,氨氮=0.9,总磷=0.3,总氮=8" --std 一级A --json
```

## 八、失败模式与降级

| 编号 | 失败模式 | 根因 | 降级/兜底路径 |
|---|---|---|---|
| FM-01 | 整改报告与整改方案条目不对应，销号被退回 | 一条问题对多条或无措施 | 退回 Step 4，按 Step 2 清单逐条对账后重写 |
| FM-02 | 依据引用已废止标准或错引条文 | 照抄旧文件未核版本 | 引用前核对现行版本；不可确认的标注【待核：依据版本】 |
| FM-03 | 数据异常时先改数据后补说明 | 混淆技术处置与违法掩盖 | STOP：停止任何修改，按表2走标记与举证；涉人为干扰转 L4 |
| FM-04 | 在线设备未验收即用于举证 | 设备验收链缺失 | 剔除该时段数据，改用化验室自测与第三方检测数据 |
| FM-05 | 危废台账与转移联单数量对不上 | 出入库未及时登记 | 以联单为基准倒查台账，补齐差额并说明；差额无据标注【待核】 |
| FM-06 | 环保税纳税主体与实际运营主体错位 | PPP 项目历史遗留 | 走纳税主体变更陈述（见 `references/env-tax-practice.md`），同步推进许可主体变更 |
| FM-07 | 执行报告按设计能力填报而非实际排放量 | 误将许可量当实际量 | 按 HJ 978-2018 实际排放量核算方法重算 |
| FM-08 | 整改时限已过仍未启动 | 责任未落到岗位 | 台账逾期预警触发，升级至主管副总并重设时限 |
| FM-09 | 污泥属性未鉴别即处置 | 用地性质与来源判断缺失 | 按污泥来源判定：纯生活污水按一般固废；涉工业废水按危废鉴别 |
| FM-10 | 销号佐证只有照片无过程文件 | 过程留痕缺失 | 补齐合同、验收单、制度签发页；无法补齐的承认并说明 |
| FM-11 | 陈述申辩照抄模板无事实与证据 | 申辩无据 | 按"事实—依据—整改—请求"四段重写，逐项附证据编号 |
| FM-12 | 突发环境事件应急预案过期未演练 | 制度空转 | 立即修订备案并组织演练，留存签到与影像 |

异常处理：`rectify_ledger.py` 遇输入缺列或日期格式错误时抛出明确错误并给出修正提示，不做静默补值；`env_tax_calc.py` 遇当量表中无该污染物时列明未识别项并跳过，不臆造当量值。脚本报错即回退核对输入，不得带错误结果交付。

## 九、🔴 关键检查点

- 🔴 检查点1（依据现行性）：任何对外材料引用条文与标准前，核对现行版本与地方更严规定，未核实项标【待核：说明】；此项未过不得出具结论。
- 🔴 检查点2（证据前置）：整改报告与销号佐证齐备（问题文件 + 方案 + 报告 + 佐证 + 销号件）后方可提交销号申请。
- 🔴 检查点3（数据合规）：在线监测数据用于对外举证前，确认设备已验收、已比对、标记合规。
- 🔴 检查点4（危废链条）：转移联单数量、危废台账、贮存记录三者一致后方可确认危废合规。
- 🔴 检查点5（税务口径）：环保税测算前确认纳税主体、应税污染物范围与单位税额，减免条件须有监测数据支撑。
- 🔴 检查点6（涉刑拦截）：一旦出现篡改数据、偷排、伪造台账线索，停止成文，转 L4 并联法务，出具涉刑风险提示。
- STOP：涉及行政处罚告知、听证、警示片曝光、公安介入时，暂停自动化输出，逐项人工复核并留存原件。

## 十、反例与红线

1. 反例：在线监测超标后先删除原始数据再补说明。红线：属篡改数据，依据《水污染防治法》第八十三条可处十万元以上一百万元以下罚款，并可能行政拘留；任何掩盖性操作一律禁止。
2. 反例：整改报告写"已加强管理、杜绝此类问题"。红线：空话不构成整改，须落到设备、设施、制度、岗位与时间节点。
3. 反例：把排污许可载明的许可排放量直接填为实际排放量。红线：实际排放量须按 HJ 978-2018 核算方法计算，不可等同。
4. 反例：城镇生活污水厂污泥不鉴别即按一般固废外运填埋。红线：接收工业废水的须按危废鉴别规范检测，排放情况重大变化时重新鉴别。
5. 反例：环保税一律按免征处理不申报。红线：免征仅限达标排放的相应应税污染物；超标的须全额计征且不适用减排减征。
6. 反例：危废暂存于露天或与其他物品混堆。红线：GB 18597 要求专用贮存间、防渗防漏、分类隔离、台账与标识齐全。
7. 反例：陈述申辩只讲经营困难要求免罚。红线：申辩须以事实与证据为据，围绕无主观故意、主动整改、危害后果三要素组织。
8. 反例：警示片问题以"已完成阶段性整改"长期挂账。红线：须按销号标准完成验收并留痕，不可无限期延续。
9. 反例：整改方案未列责任人与时限。红线：无责任人、无时限的方案不具备可执行性与可验收性。
10. 反例：借用邻近厂或第三方数据充当本厂佐证。红线：数据须可溯源到本厂本时段，借用即造假。

## 输出质量规范

- **事实与观点分离**：事实段直陈监测数据、文书文号、台账编号与现场影像编号；判断段以「判断：」起头，写明依据条文与推定前提，二者不混排。
- **依据现行性**：引用法律、行政法规、标准时写全称与条款号；地方标准严于国家标准时从严并并列注明。
- **数值口径锁定**：许可排放量、实际排放量、环保税单位税额三类数值分别标注取值来源，不以一类数值替代另一类。

## 交付附加与迭代

交付时按需追加（无内容不写空话）：关联提示（同厂同类问题的历史整改件、可套用的台账与模板 1—3 条）、要点归纳（3—5 条合规结论与风险点）、下一步动作（需补的证据、需报送的节点、需升级联法务的情形）。

多轮迭代：交付后说明可调整维度（材料类型／问题条目范围／时限口径／报送对象），用户指定后直接改，不重跑全流程。

## 端到端示例

**输入**：某污水处理厂收到生态环境部门责令限期整改通知，指出现场在线监测设备未验收即使用、危废暂存间未分类隔离、排污许可执行报告季报漏报一期。

**处理**：先行锁定义务对象与依据条文（在线监测 HJ 212 / HJ 355、危废 GB 18597、执行报告《排污许可管理条例》第 22 条）→ 问题清单化并按立行立改（3 日）、限期整改（15 日）、专项整治（30 日）分档 → 现场取证固定整改前后影像与台账 → 编制整改方案七段 → 按节点留痕 → 编制整改报告七段逐条对账 → 提报销号佐证 → 归档并反向更新合规义务清单。

**输出**：整改台账（含责任部门、责任人、时限、销号佐证要求）+ 整改方案 + 整改报告 + 销号佐证包 + 执行报告补报说明。

**检查点**：依据条文现行有效；五件套齐备；危废三链条数量一致；执行报告按实际排放量核算。

## 适用范围与分流

本技能只处理污水厂运营期的环保合规自查、督察与执法检查整改、排污许可执行报告、危废与环保税、在线监测异常与陈述申辩。以下请求分流：

- 建设项目竣工环境保护验收（自主验收、验收监测报告、验收意见） → 应使用「wastewater-env-acceptance」；
- 排污许可证首次申领与许可排放量核算 → 应使用「排污许可证申领及填报助手」；
- 环保税季度申报测算与纳税主体变更 → 应使用「sewage-env-tax」，本技能只给合规判定与陈述骨架；
- 突发环境事件应急预案编制与备案 → 应使用「env-emergency-plan」；
- 环境损害司法鉴定与赔偿磋商 → 应使用「eco-damage-report」；
- 三废检测报告编制与自行监测方法 → 应使用「env-three-waste-test-report」。

## 降级路径与失败模式速查

督察整改最怕“材料凑齐就报、证据对不上”。下表把失败模式、触发信号、降级路径（兜底方案）与补救动作固化，遇阻先对表；出现异常时先保原始证据不丢，再谈补全。

| 失败模式 | 触发信号 | 降级路径（兜底方案） | 补救动作 |
|---|---|---|---|
| 义务漏项 | 六项义务未逐条对账 | 降级为“缺项清单”，标【待核：缺×××证据】 | 回退补齐义务后再进入主流程 |
| 依据版本失效 | 引用已废止条例/标准 | 回退到现行有效版本 | 复核后重引并标注版本 |
| 问题—措施不对应 | 一条问题对多条或对空措施 | 兜底按“一问题一措施”重排 | 逐条对齐清单后重编方案 |
| 证据链断裂 | 五件套缺件 | 断点续跑，逐件补齐 | 缺件标【待核】并列入待补清单 |
| 危废三链条不符 | 联单/台账/贮存记录数量不一 | 以联单为基准倒查 | 补齐差额并留痕 |
| 执行报告漏报 | 季报/年报超期 | 降级为“补报说明”，不隐瞒 | 按实际排放量核算后补报 |
| 脚本运行失败 | 报错或缺依赖 | fallback 为人工对照模板自检 | 排除错误后重试脚本 |
| 涉刑线索 | 篡改数据/偷排/伪造台账 | 降级处理：停止代办，转 L4 并联法务 | 一律不得输出“如何规避监管” |
| 报送被退回 | 门检 FAIL 或有【待核】未清 | 回退到最后通过检查版本 | 清缺口后重跑门检 |

**降级总则**：任何降级须写明“降了什么、为什么降、需补什么”，不得以沉默代替说明。**异常与错误处理**：脚本不可用时 fallback 为人工台账核对；对空表、缺列、编码异常等边界条件做容错与防御性校验；任一检查项失败即进入失败分支的降级路径（回退/重试/断点续跑），未通过不得报送主管部门。
