# 手绘线稿插图引擎（qf-lineart）

## 一、专家定位与路由

本技能是一个**插图引擎**，只负责把主题词渲染成手绘线稿插图，并给出落位规划；不负责版面本身。

路由判断：

| 用户诉求 | 处理方式 |
|---|---|
| 要一张手绘插图 / 线稿配图 | 直接走本技能，`--motif` 单张出图 |
| 要给一篇文章配 2–3 张图 | 走批量模式（关键词选题 + 落位规划） |
| 要比较不同笔触 / 配色 | 走 `--compare-styles` 与 `--sheet` |
| 要一本书 / 一篇推文 / 一套幻灯片整体配图 | 本技能出图，由对应技能（排版、推文、PPT）负责落版 |
| 只要真实照片、不要手绘 | 不在本技能范围 |

## 二、适用边界

**适用**：文章与书刊配图、公众号推文插图、PPT 与汇报材料插图、方案与报告配图、课件的示意插图、需要统一手绘风格的一套图。

**不适用**：写实照片与摄影素材、复杂人物与场景插画、需要精确工程制图的图示（走制图类技能）、图片编辑与修图、AI 文生图类整图创作。

## 三、五维评估

接到配图需求，先评估五维，定档后再出图。

1. **主题匹配度**：文字里的高频意象能否落到 16 母题之一；命中为零时按通用母题补位。
2. **风格一致性**：同一批图必须同笔触、同配色；跨篇换色会破坏整册观感。
3. **载体适配**：跨栏大图走 1500×820，栏内浮图走 760×980，比例错配会导致版面挤压。
4. **底纹需求**：入网页或幻灯片且底色非白时铺暖纸底；出版内页保持透明底，由版面提供底色。
5. **可复现性**：交付需可复现时固定 seed，同一 seed 出图逐像素一致。

## 四、四级响应 L1–L4

| 档 | 触发条件 | 动作 |
|---|---|---|
| **L1 直出** | 单一母题、单一风格 | 一条命令出图，不做评估 |
| **L2 选型** | 主题明确但风格未定 | 出 2–3 个候选（不同笔触或配色）供挑选 |
| **L3 成套** | 一篇文章 / 一节内容配 2–3 张 | 关键词选题 + 同风格同配色 + 落位规划 |
| **L4 成建制** | 一本书 / 一整套材料配图 | 全册统一配色笔触 + 逐篇清单 + 总览拼版 + 质检 |

## 五、工作流与步骤（六步）

1. **定核心框架**：取标题与正文，先提主旨、结构骨架与核心意象，再据此定画面（`scripts/content_composer.py`）。
2. **定风格**：按载体定笔触与配色（见第六、七节速查）。
3. **定尺寸**：wide 1500×820 / inline 760×980。
4. **出图**：单张走 `--motif`；成套走批量模式。
5. **落位**：按 role 字段交给版式技能（wide 跨栏、inline 栏内浮图、inline-end 靠后浮图）。
6. **质检**：过第九节门禁，拼总览图目视复核。

以上六步为默认流程；同一套的图务必在步骤 2 一次性锁定风格，跨篇章改风格会让全套返工。

```bash
# 单张
python3 scripts/lineart_cli.py --motif lamp --style brush --palette sepia -o lamp.png

# 5 种笔触对比
python3 scripts/lineart_cli.py --motif cloud --compare-styles --palette ochre -o styles.png

# 16 母题总览拼版
python3 scripts/lineart_cli.py --sheet sheet.png --palette sepia --style fountain

# 按文章批量配图（关键词选题 + 落位规划）
python3 scripts/lineart_cli.py --manifest book.json --per-article 3 \
    --outdir images/auto --palette sepia --style pencil -o auto_images.json
```

## 六、引擎规格速查

**五档笔触**（手感差异由复笔遍数、抖动系数、线宽系数、颗粒、晕染共同决定）

| 笔触 | 复笔 | 抖动 | 线宽 | 颗粒 | 适用 |
|---|---|---|---|---|---|
| `fountain` 钢笔 | 2 遍 | 1.00× | 1.00× | 轻 | 规矩克制，通用首选 |
| `pencil` 铅笔 | 3 遍 | 1.25× | 0.85× | 重 | 松弛、纸感强 |
| `brush` 毛笔 | 2 遍 | 1.35× | 1.50× | 中 | 提按变化、最有笔意 |
| `marker` 马克笔 | 1 遍 | 0.55× | 1.90× | 极轻 | 粗壮醒目、扁平 |
| `charcoal` 炭笔 | 3 遍 | 1.90× | 1.70× | 最重 | 朦胧、氛围感 |

**参数**：`--roughness` 粗糙度 0–3（0 近直尺，1 常规，2 以上恣意）；`--bowing` 弯曲度；`--grain` 颗粒强度；`--seed` 种子；`--paper` 铺暖纸底；`--no-shade` 关闭体量排线。

**压感与出锋（v2.4.0）**：五档笔触的压感强度（`press`）与出锋幅度（`over`）分档设定——毛笔 1.00 / 炭笔 0.85 / 铅笔 0.74 / 钢笔 0.58 / 马克笔 0.00。压感让线条走「起笔轻、行笔重、收笔出锋」，并叠一层行笔速度带来的低频起伏；出锋只在开放路径生效，闭合轮廓（圆、方框）不出锋。跨度小于 44px 的短线自动近似等宽，避免被压断。

## 七之二、场景母题的用法（内容驱动）

场景母题解决的是"图与文对不上"的问题：象征符号（叶、云、月）好看但空，具体物件（台阶、图纸、池体、天平）才有信息量。

- **命中优先**：选题时场景母题权重 ×1.5，能命中就优先用场景。
- **一人一景**：场景里的人物用 `person()` 简笔人影绘制，可摆 stand / sit / point / raise 四种姿势。
- **可组合**：需要表达"多人场景"时，在同一画面上组合多个人影与物件（如三级台阶上三个人影）。
- **可扩展**：新增场景只需写 `s_xxx(d, W, H, pen, ink)` 并注册进 `DRAW`，自动继承全部笔触、配色与质感能力。

```python
# 场景与象征母题混选（场景优先）
python3 scripts/lineart_cli.py --motif checklist --style pencil --palette sepia -o q.png
python3 scripts/lineart_cli.py --list-motifs   # 32 个母题
```

## 七之三、两条出图通道（AI 主、程序化兜底）

| 通道 | 工具 | 用在 |
|---|---|---|
| **AI 生图通道**（主） | `scripts/prompt_builder.py` 出提示词 + 外部/平台绘图后端出图 | 成书与成套交付的主通道：场景更丰富、更贴合文章内容 |
| **程序化引擎**（兜底） | `scripts/lineart_cli.py` | AI 出图缺位、失败，或需要逐像素复现时补位 |

AI 通道的提示词范式引进自公众号配图经验，三条要点：**落到具体物件**（台阶、图纸、池体、天平比抽象渐变耐看）、**结尾必附负面约束**（否则出现文字与标识）、**留白要留够**。提示词末尾一律附「不得出现任何文字、字母、数字、logo、水印。」

```bash
python3 scripts/prompt_builder.py --manifest book.json --per-article 2 -o prompts.json
python3 scripts/prompt_builder.py --text "竣工验收这半年" -o one.json
python3 scripts/prompt_builder.py --list-prompts
```

主通道出图的统一底色口径：**米白纸实底**——透明底在深色界面或深色底纹上会呈黑底观感，故一律铺实底；程序化兜底同样默认铺实底（`paper=True`），确需透明底时才显式加 `--transparent`。详见 `references/ai-channel.md`。

## 七之四、文意提取通道（v2.2.0，配图融入文章的正解）

母题选题（`pick_motifs`）从固定画面库里挑，画面与具体文章之间隔着"主题相似"一层。要让配图**从文章里长出来**，走文意提取通道——这也是《读者》四十年的做法：先读文稿，再从文中选中心点（见 `references/reader-illustration-tradition.md`）。

四步：

```bash
# 1) 提素材：正文 → 画面素材底稿（物象/场景段/基调/锚点候选）
python3 scripts/text_brief.py --manifest book.json --out brief_materials.json

# 2) 提核心框架 + 构思画面：正文 → 核心框架卡 + 画面任务单（v2.3.0 新增，
#    自动完成原先"读文写任务单"那一步）
python3 scripts/content_composer.py --manifest book.json --outdir briefs --palette sepia --style pencil
#    单篇用法：python3 scripts/content_composer.py --file src_52.md -o brief.json --frame-out core_frame.md

# 3) 复核任务单：对照核心框架卡逐条核对六条红线

# 4) 渲染提示词：任务单 → 标准提示词（每篇 wide / inline 两条）
python3 scripts/prompt_builder.py --brief briefs/art_brief_auto.json -o prompts.json
```

核心框架四件：**一句话主旨**（论点句，短且含判断词）、**结构骨架**（各节标题与各节核心句）、**核心意象**（去噪后的高频词）、**画面落点**（wide 与 inline 两条）。画面由框架分派而来：论点句进主旨、叙事句进 wide、物象句进 inline；物象分事务词与静物两类，特写只取静物。动作按画面语言转写（如"整理成"→"把散开的纸页理齐、叠成一沓"），氛围按基调补光，画面描述不照抄原文句子，原文原句留在 `evidence` 里备核。

任务单六条红线（逐条自检）：**有出处**（subject 必须能在本文找到对应语句或物件）、**非图解**（禁用"上台阶+箭头=晋升"式看图识字）、**两图不重**、**可入画**、**无字**、**克制**（留白不少于三成）。

任务单每条带 `anchor`（`kn:关键词`），交落版技能按"图跟文走"插入——见读者排印坊「配图联动」。字段定义、示范与反例见 `references/art-brief-guide.md`。

## 七之五、压感与体量排线（v2.4.0）

线稿的手绘感由两件事撑起：笔的提按与面的体量。v2.4.0 补齐这两处。

- **压感走笔**：线条沿路径变宽，起笔轻、行笔重、收笔出锋，并叠低频起伏（模拟行笔速度变化）；收笔处墨色略淡。跨度小于 44px 的短线自动近似等宽，避免压断。
- **体量排线**：`Pen.shade()` 给一个面铺浅斜排线，母题内部按需调用（处理池水体、档案柜柜体已接入）。排线本身也走手绘笔，带抖动、压感与浓淡变化，不再是一条条等宽机械线。
- **开关**：`--no-shade` 关闭体量排线；`--transparent` 输出透明底。两者都与 `--seed` 兼容，同种子逐像素复现。

```bash
# 开启排线（默认）
python3 scripts/lineart_cli.py --motif plant --style brush --palette sepia -o plant.png

# 关闭排线（只要纯轮廓线）
python3 scripts/lineart_cli.py --motif plant --style brush --palette sepia --no-shade -o plant_plain.png
```

原理与参数见 `references/line-pressure-and-shading.md`。

## 八、联动调用

其他技能接入本引擎的接口：

- **接口形态**：`scripts/lineart_cli.py`（命令行）与 `scripts/lineart_engine.py`（库，函数 `render` / `pick_motifs` / `plan_roles`）。
- **批量契约**：输入稿件清单 JSON（含 `articles[]`，每项有 `order`/`title`/`column`/`body`），输出配图清单 JSON（`{order: [{file, motif, role}]}`）。
- **落位契约**：`role` 取 wide / inline / inline-end，由落版技能消费。
- **风格契约**：同批图固定 `--palette` 与 `--style`；跨技能联动时由主控技能统一传入，避免各出各色。

```python
# 库调用示例
import sys; sys.path.insert(0, "scripts")
import lineart_engine as E
E.render("moon", out="moon.png", style="brush", palette="ochre", size=(760, 980))
motifs = E.pick_motifs("长夜里的灯与远方", n=3, seed=2026)
```

已对接与可对接：书刊排版类技能（成套配图 + 落位）、公众号推文类技能（头图与文内插图）、演示文稿类技能（分节插图）、报告与方案类技能（章节插图）。

## 九、质量门禁 🔴

| 门 | 判据 | 不过即打回 |
|---|---|---|
| 🔴 G1 可辨 | 输出图与母题语义一致，主题可无提示认出 | 图形崩坏或语义不符 |
| 🔴 G2 一致性 | 同批图笔触与配色完全一致 | 混用笔触或色板 |
| 🔴 G3 比例 | 跨栏 1500×820、栏内 760×980，不变形 | 比例错配致版面挤压 |
| 🔴 G4 干净度 | 无孤立杂线、无意外色块、无越界元素 | 出现污渍状残留 |
| 🔴 G5 底色 | 出版内页透明底；网页/幻灯片按背景决定是否铺纸底 | 透明底贴深色底导致线条消失 |
| 🔴 G6 可复现 | 交付版固定 seed，重跑逐像素一致 | 同参数出图不一致 |
| 🔴 G7 排线 | 体量排线不出形状、不盖主轮廓、不成污渍块 | 排线越界或画面发脏 |

## 十、失败模式

| 编号 | 现象 | 根因 | 处置 |
|---|---|---|---|
| FM-01 | 圆形偏心、轮廓散架 | 复线逐点独立随机，形状被抖散 | 复线改「整条线整体偏移 + 逐点微扰」两层 |
| FM-02 | 短元素（星点、书页线）糊成一团 | 抖动幅度对小尺寸元素过大 | 路径跨度小于 40px 时抖动自动收敛 |
| FM-03 | 出现污渍状淡色块 | 叠加了低透明度大圆做强调 | 关闭 accent 强调层，画面只留墨线 |
| FM-04 | 同批图风格不统一 | 逐张改参数，未锁定风格 | 同批强制同一 palette 与 style |
| FM-05 | 出图不可复现 | 未固定 seed | 交付版固定 seed 并记录 |
| FM-06 | 深色底上线条看不见 | 透明底直接贴在深色背景 | 铺暖纸底或改浅底承载 |
| FM-07 | 关键词命中为零，选题随意 | 文本无母题关键词 | 按 fallback 母题补位并人工确认 |
| FM-08 | 栏内浮图占高过大挤掉正文 | 尺寸取成跨栏比例 | 按 role 取 760×980 |
| FM-09 | 中文标签渲染成方块 | 角标字体缺中文字形 | 显式加载 CJK 字体，缺失时退化为英文标签 |
| FM-10 | 场景画出来认不出 | 人物过于简略、物件语义不明（如把跑鞋画成半圆、把交接画成悬浮物） | 场景中的关键物件只画“一眼能认出”的写法；改完必须拼总览图目视复核，逐个判定可辨性 |
| FM-11 | 抽象符号与内容脱节 | 只用象征母题（叶／云／月）表达具体主题，图与文无关联 | 场景母题权重 ×1.5 优先命中；象征母题仅作补位 |
| FM-12 | 核心框架提取跑偏 | 论点句与叙事句未分派、要点混入文档大标题、跨词 n-gram 入榜 | 按 `references/content-composer.md` 第六节的 FC-01 至 FC-06 逐条处置 |
| FM-13 | 排线越出形状或压住主轮廓 | shade 形状点贴轮廓、间距过密 | 形状点相对轮廓内缩 4–5px；间距≥15px、透明度≤50；出图后放大看边界 |
| FM-14 | 压感过强致短线断裂 | press 施加于超短路径 | 跨度＜44px 自动收敛压感；仍偏弱时降低 `--roughness` |

记录格式：新增失败模式时写清现象、根因、处置与验证四段；同类故障在出图流程中复现时，先查本表与第九节门禁是否已覆盖，避免重复踩坑；跨批复现的错误回写到本节，形成可复用的教训。

## 十一、反例黑名单

1. 不把母题当写实插画用（灯是意象不是灯具说明书）。
2. 不给同一批图混搭钢笔与炭笔。
3. 不在出版内页铺满底色纸纹（会与版面纸色打架）。
4. 不用线稿替代工程图、示意图与数据图表。
5. 不省质检直接交付（G1–G6 逐项过）。
6. 不擅自改母题语义去迎合关键词。
7. 不把越界元素（线条出画）当作「手绘感」放行。
