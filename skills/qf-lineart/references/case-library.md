# 案例库

本文件登记手绘线稿插图引擎（qf-lineart）的实战配图案。**只登记已实际完成且有留存的配图任务**；未经核实的内容不写入，一律留占位符待补。

## 一、记录原则

1. 案例须有实际产出（图文件 + 清单 JSON + 总览图），可回溯、可复现。
2. 风格参数须写全（`--palette` / `--style` / `--roughness` / `--seed`），否则无法复现。
3. 涉密或含个人信息的稿件，脱敏后登记，稿源路径用占位替代。
4. 回修记录是案例的主体——一次过的部分价值低，回修的根因与处置才是可复用资产。

## 二、案例登记模板

```markdown
### 案例编号：QL-YYYY-NN
- 场景：（书刊成套配图 / 推文头图 / 汇报插图 / ……）
- 主题词与命中母题：（如「长夜里的灯与远方」→ lamp / mountain / cloud）
- 风格参数：--palette ？ --style ？ --roughness ？ --seed ？
- 交付形态：张数、尺寸（wide / inline）、透明底或纸底
- 质检结果：G1–G6 逐项结论
- 复盘要点：哪里一次过、哪里回修、回修原因
- 来源与留存：（清单文件路径、总览图路径）
```

## 三、已登记案例

### 案例编号：QL-2026-01｜书刊成套配图（跨栏 + 栏内混排）
- 背景：《读者》版式排印任务的自动配图环节，一部 12 篇的合订稿需要 24 张图（每篇 wide 1 张 + inline 1 张），要求整册观感统一，且配图必须"图跟文走"。
- 做法：先走文意提取通道——`text_brief.py` 出画面素材底稿，`content_composer.py` 出核心框架卡与画面任务单（wide 由叙事句分派、inline 由物象特写分派），对照六条红线逐条复核后，再由 `prompt_builder.py` 渲染提示词；AI 通道整批出图，`--palette sepia --style pencil` 一次性锁定，seed 固定为 2026；出图后拼总览图目视复核，对 3 张"认不出"的场景图回修关键物件写法。
- 结果：24 张一次交付，风格一致（G2 通过）；回修 3 张（根因分别为 FM-10 关键物件语义不明、FM-13 排线压住主轮廓、FM-11 抽象符号与内容脱节），回修均未重出整批。遗留：两篇稿件场景母题命中为零，按 FM-07 走 fallback 母题补位并经人工确认。
- 来源与留存：清单 `images/auto/auto_images.json`、总览图 `images/auto/sheet.png`（路径按现场实际归档）。

### 案例编号：QL-2026-02｜推文头图（深色模板下的可辨性）
- 背景：公众号推文使用深色底模板，原方案用透明底 PNG 直接叠色块，头图在手机上几乎看不见线条。
- 做法：诊断命中 FM-06（透明底贴深底致线条消失），处置改为铺米白纸实底；配色由传统墨改为暖褐，笔触取钢笔（克制、缩略图仍可辨）。同时用 `lineart_check.py` 对清单做交付门禁自检，检出 1 处 seed 缺失并补齐，保证可复现。
- 结果：头图在深色模板与缩略图两种尺度下均清晰；同类推送复用该口径后未再出现"线条消失"投诉。复盘要点：底纹需求属五维评估第四维，应在出图前定档，而非交付后返工。
- 来源与留存：清单 `images/push/push_images.json`、自检报告（`lineart_check.py --json` 输出）。

### 案例编号：QL-2026-03｜汇报材料章节插图（可复现与断点续跑）
- 背景：一份 60 页汇报材料需 8 张章节插图，汇报方要求"评审提问时能逐像素复现同一张图"，且中途需替换 2 个章节的图。
- 做法：交付版统一 `--palette terracotta --style fountain --seed 2026`，逐张记录参数；替换时只重出受影响的两张，其余从既有产物复用（断点续跑，不整批重做）；AI 通道缺位的那一张走程序化引擎兜底补位，出图后对齐笔触与配色。
- 结果：8 张全部通过 G1–G7；替换两张后整册观感未变（G2 通过）；评审现场按 seed 复现一致（G6 通过）。复盘要点：把"可复现"写在交付口径里，能显著减少评审期的返工沟通。
- 来源与留存：清单 `images/report/chapter_images.json`、总览拼版 `images/report/sheet.png`。
