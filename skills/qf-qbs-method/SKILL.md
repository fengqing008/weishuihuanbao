## 〇、专家级路由（v1.0.0）

**专家定位**：把"从问题出发、借经典书沉淀出可调用技能"的完整链路固化为一条五阶段流水线，服务手上有个真问题、想用经过时间检验的知识来解的用户。

**五维评估**：
- 适用场景：①用户给问题，要求荐书并最终转成技能 ②用户问"某个问题该读哪本经典书"并希望落地成工具 ③用户已选定书，缺合规取书路径与技能化衔接 ④把已有书籍技能接入问题解决链路 ⑤QBS 全流程复现
- 能力边界：不推荐也不协助获取盗版（Z-Library 等影子图书馆）；不做无授权内容的转换；不接纯荐书问答与纯格式转换；不替用户做医疗、法律等需资质主体的决断
- 依赖资产：内核 book-to-skill（`skills/book-to-skill/`）+ 本技能 scripts 三脚本 + references 专家件八份
- 交付质量：问题陈述卡 + 荐书评分表 + 取书路径说明 + 生成的技能 + 解题报告 + QBS 台账；全流程留痕、双轨归档
- 性能表现：单次全流程五阶段，含 4 个人工确认点（Step 0/1/2/4 起始处）

**四级响应（L1-L4）**：
- L1 轻量问答（QBS 是什么、经典书怎么选、版权怎么办）→ 直接作答，指向对应专家件
- L2 标准链路 → 按 Steps 0-5 跑通单本书
- L3 复杂任务 → 多问题并行、多书比选、已有技能复用，叠加质量门
- L4 专家任务 → 全流程 + 定制荐书标准 + 技能合并 + 注册入库

**黄金窗口**：单问题收敛至 1—2 本核心经典书；单本书 3—15 万字；生成的技能主 SKILL.md ≤4,000 tokens

# QBS 法 · 从问题到技能

## Phase 0｜启动前校验（未过不进五阶段）

| 检查项 | 通过标准 | 未过动作 |
|---|---|---|
| 问题可表述 | 一个具体真问题，含场景与约束 | 先收敛问题 |
| 问题可试答 | 问题属于方法可应对的范围 | 超范围时明示 |
| 取书路径 | 经典书来源合法可获取 | 换合法路径 |
| 内核可用 | book-to-skill 内核可调用 | 降级为人工蒸馏 |
| 产出目标 | 技能名与解题目标明确 | 明确目标 |

🔴 检查点：任一检查项未过，先补齐再启动；不得跳过荐书环节直接蒸馏。

## 定位声明

把"问题 → 经典书 → 技能 → 解题"这条链路固化成一个可反复执行的编排技能：先锁定真问题，再按可检验的经典标准荐书，随后给出合法取书路径，调用内核 `book-to-skill` 把它蒸馏为技能，最后用该技能回答最初的问题并留痕归档。

产出的是"一个能持续回答同类问题的小工具"，不是一份书单，也不是一篇读书笔记。

## 触发条件

- 用户描述了一个具体困惑或待解决的问题，并希望"用经典书的方法"来解
- 用户点名要 QBS 法、问书成技、经典书转技能、从问题到技能
- 用户已有一本书但尚未接入"问题—技能"链路，要求补全整个流程
- 用户要求"先荐书、再转成技能、再用它答题"的完整链路

## 与内核 book-to-skill 的分工

两个技能互补，触发场景不同，不可互相替代：

| | 本技能（QBS 法） | 内核 book-to-skill |
|:--|:--|:--|
| 输入 | 一个**问题** | 一个**书籍文件/文件夹** |
| 起手 | 荐书 + 取书 | 文本提取 |
| 覆盖 | Steps 0-5 全链路 | Steps 0-9 书→技能 |
| 关系 | 在 Step 3 调用内核 | 被本技能调用 |

用户手上已有书、只要求转技能时，直接走 book-to-skill；用户给的是问题、还没书时，走本技能。衔接参数与路径约定见 `references/book-to-skill-bridge.md`。

## 分步工作流（Steps 0-5）

执行顺序：

1. Step 0 问题锁定 → 产出问题陈述卡，过人工确认点；
2. Step 1 荐书 → 产出荐书评分表，过人工确认点；
3. Step 2 合规取书 → 产出取书路径说明，过人工确认点；
4. Step 3 转技能 → 调用内核产出技能目录，过转换门；
5. Step 4 调用解题 → 产出解题报告，过解题门；
6. Step 5 留痕入库 → 产出台账与归档记录，过归档门。

每个阶段有产出物、有确认点；任一阶段产出未齐不得进入下一阶段。

### Step 0 — 问题锁定

把用户的模糊诉求收敛成一张"问题陈述卡"：领域、要解的核心问题、已知条件与约束、期望产出形态、判断成功的标准。用 `scripts/qbs_pipeline.py init` 建台账并写入 Step 0 结论。

**🔴 检查点（人工确认）**：向用户复述问题陈述卡，确认无误后再荐书。问题不清晰时先追问，不得带猜往下走。

### Step 1 — 荐书（按经典筛选标准）

按 `references/classic-book-criteria.md` 的四维标准（时间检验、权威性、跨代验证、问题匹配度）提出 3—5 本候选，用 `scripts/book_recommender.py` 生成结构化评分表并排序：

```bash
python3 scripts/book_recommender.py --problem "如何做高产出管理" \
  --candidates candidates.csv --out recommend.md
```

脚本校验"首版年份是否满足 30 年以上"并计算加权分（判据见评分表字段说明）。候选表用 `book_recommender.py --template` 生成 CSV 骨架；年份填写口径（原著 vs 译本）见 `references/classic-book-criteria.md`。

**🔴 检查点（人工确认）**：用户选定 1—2 本核心书后进入取书。

### Step 2 — 合规取书

用 `scripts/source_guide.py` 为选定书目生成合法获取路径（正版电子书平台、公共图书馆借阅、公版书库、纸质购买），并给出可获取性评估：

```bash
python3 scripts/source_guide.py --book "The Art of War" --author "Sun Tzu" --first-pub-year 1910 --out source.md
```

版权状态判定：优先用作者卒年（`--death-year`）判公版；无卒年时，首版距今 >100 年的历史作品（`--first-pub-year`）按"极可能已进入公有领域"处理。版权边界与各来源判别见 `references/legal-book-sources.md`。**影子图书馆（Z-Library 等）不在推荐之列**，用户主动要求时说明风险并给出替代路径。

**🔴 检查点（人工确认）**：确认取书方式（含无法取得全文时的降级方案）后进入转换。

### Step 3 — 转技能（调用内核 book-to-skill）

按 `references/book-to-skill-bridge.md` 的契约调用内核，把书籍蒸馏为技能：文本提取 → 内容类型确认 → 成本预估 → 章节映射 → 技能命名 → 建目录 → 生成章节与 glossary/patterns/cheatsheet → 生成主 SKILL.md → 安全扫描。

```bash
BT=skills/book-to-skill
python3 "$BT/scripts/"extract.py <书籍文件> --mode text --install-missing ask
```

生成的技能落到 `skills/<skill_name>/`，可经 `ima_skill_create` 注册。完整参数与降级路径见 `references/book-to-skill-bridge.md`。

**🔴 检查点（人工确认）**：内核产出通过 `references/quality-checklist.md` 的转换门后进入解题。

### Step 4 — 调用解题

加载生成的技能，回到 Step 0 的问题陈述卡作答：每条结论标注它来自书中哪个框架/原则（可回溯），无法由该书覆盖的部分显式说明。用 `scripts/qbs_pipeline.py check` 校验"问题—书—技能—答案"四环是否闭合。

**🔴 检查点（人工确认）**：用户认可答案或提出补充问题（补充问题回到 Step 4 循环，不重跑 Step 1—3）。

### Step 5 — 留痕入库

汇总本次全链条产物：问题陈述卡、荐书评分表、取书路径、生成的技能、解题报告、QBS 台账。技能包与报告按 `references/output-template.md` 归档，台账用 `python3 scripts/qbs_pipeline.py status` 导出。

## 输出规范

| 产出物 | 载体 | 关键字段 |
|:--|:--|:--|
| 问题陈述卡 | 台账 JSON + Markdown | 领域/核心问题/约束/成功标准 |
| 荐书评分表 | Markdown + CSV | 书名/首版年/权威性/匹配度/加权分/排序 |
| 取书路径说明 | Markdown | 来源类型/可得性/版权状态/降级方案 |
| 生成的技能 | 技能目录 | SKILL.md + chapters/ + glossary/patterns/cheatsheet |
| 解题报告 | Markdown | 结论/溯源框架/覆盖边界/遗留问题 |
| QBS 台账 | JSON | 五阶段进度/产出路径/时间戳 |

## 依赖与降级

依赖 Python3 标准库（三个脚本零第三方依赖）；内核 book-to-skill 需 PDF/EPUB 等解析包，缺失时按其提示处理。取书环节无全文时降级为"高质量二手材料"（权威书评、作者公开讲义、再版序言），并在报告中标注降级事实。内核不可用时，Step 3 中断并保留 Step 0—2 产出，待内核恢复后续跑。

## 边界与反模式

- 不推荐、不引导、不协助获取盗版或影子图书馆内容；用户坚持时说明法律与质量双重风险，并给出合法替代。
- 不做无授权内容的转换；输入属未授权材料时在 Step 2 停止。
- 不把"荐书"当成终点——本技能的完成线是"技能被成功调用并回答原问题"。
- 常见错误：问题未澄清就荐书；用畅销新书替代经典；跳过取书合法性核验；Step 3 生成的技能未做安全扫描就发布；解题结论未标注溯源框架。

## 实战范例

**范例一（标准链路）**：用户提"我想提升团队产出，但管理学书太多不知读哪本" → Step 0 锁定"如何提升管理产出率" → Step 1 荐《卓有成效的管理者》《高产出管理》等，评分表排序 → 用户选《高产出管理》 → Step 2 给正版电子书与图书馆路径 → Step 3 调用内核生成 `grove-hpo-method` 技能 → Step 4 用该技能输出提升方案并标注 OKR、管理杠杆等框架来源 → Step 5 归档台账。

**范例二（多问题并行）**：用户一次抛出"如何带好团队""如何做减法决策"两问 → 分别建两张问题陈述卡 → 荐书阶段合并比选（两问可共用《卓有成效的管理者》）→ 选 2 本 → 转出 2 个技能 → 分别解题 → 台账记录两组链路。完整演绎收录于 `references/case-library.md`。

## 输出质量规范

- **来源分级与缺口标注**：书籍信息标注版本与出版年（P0 公版原文｜P1 权威版本与译注｜P2 二手解读）；取书路径不通时明示，不以替代文本充作原书。
- **事实与观点分离（区分事实与判断）**：原书框架与结论属事实段（并注章节）；据此对用户问题的应答属判断段，以「判断：」起头并说明推理链条。
- **风险与免责提示**：经典书方法论反映其时代条件，用于当代决策时须校正前提；涉及法律、财务、医疗问题时须转专业渠道。

## 约束

不得编造书籍内容、章节与作者观点；蒸馏产物中的每条框架须可回溯到原书位置。取书须走合法渠道（公版书开放源或用户自备文件），不提供侵权获取路径。

## 交付附加与迭代

交付时按需追加：变更提示（书目版本差异）、要点归纳（3—5 条，如最贴合问题的框架）、下一步动作（可执行项，如补充书目、按技能试答）。

多轮迭代：交付后说明可调整维度（书目／蒸馏深度／问题边界），指定后直接改。

## 交付自检表

| 检查项 | 标准 | 不达标动作 |
|---|---|---|
| 问题收敛 | 具体、可试答 | 再收敛 |
| 选书有据 | 符合经典书筛选标准 | 重选 |
| 路径合法 | 公版或用户自备 | 换路径 |
| 条目可溯 | 框架有原书位置 | 回补 |
| 留痕完整 | 五阶段过程有记录 | 补记录 |
