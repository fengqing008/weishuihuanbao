# 失败模式与处置（failure-modes）

## 一、工程类

**F1 外链残留**
现象：断网或内网打开时样式丢失、图标变方框。
根因：从在线模板复制骨架，带入了 CDN 样式表与图标字体。
处置：内嵌样式，图标改用字符或内联 SVG。
预防：构建后第一时间跑 `html_check.py`，EXTERNAL_RES 为零容忍项。

**F2 体积失控**
现象：单文件超过 2MB，移动端打开卡顿。
根因：内嵌多张未压缩的大图，base64 使体积再涨约 37%。
处置：长边裁到 900px 以内并转码，或改用内联 SVG。
预防：图片入库前先看字节数，超 80KB 不直接内嵌。

**F3 标签不配对**
现象：页面局部错位、表格撑破容器。
根因：手工删改标签时漏闭合。
处置：定位 html_check.py 报出的未闭合标签并补齐。
预防：改动后重跑自检，不凭目测确认。

**F4 主题变量名不一致**
现象：换配色后部分元素仍保持旧色。
根因：页面写了 `--accent2`，配色块生成的是 `--accent-2`。
处置：统一变量名，以 `palettes.py css` 的输出为准。
预防：变量只从工具生成，不手写。

## 二、内容类

**F5 数据无来源**
现象：读者追问来源时无法答，可信度打折。
根因：正文直接写数字，来源留在作者脑子里。
处置：关键数据补角标，末尾补来源区块。
预防：数据文件里每条数值与来源成对录入。

**F6 缺口被掩盖**
现象：读者把估算值当确认值使用。
根因：缺口用"暂无数据"一句带过，未标影响。
处置：改用缺口徽标，并在缺口区块写影响与补充渠道。
预防：凡测算值一律标明"测算"与依据。

**F7 观点伪装成事实**
现象：对外发布后被指带主观倾向。
根因：判断性表述与数据叙述混排在同一段。
处置：观点移入观点块，与事实叙述分开。
预防：写完通读一遍，凡"我们认为/业内普遍"类内容进观点块。

**F8 深底配色打印**
现象：纸质稿大面积灰黑，正文与底色糊在一起。
根因：屏幕观感优先，未考虑灰度还原。
处置：换浅色主题。
预防：纸质分发的任务在选色阶段就限定浅色主题。

## 三、校验类

**F9 拿 HTML 源文件送文本校验**
现象：出现"38 处数字未千分位""缺一级标题序号"等告警。
根因：校验器按文本解析，把 CSS 十六进制色值与标签结构当正文。
处置：先用 `--text-out` 抽正文，再送文本校验。
预防：把"结构自检 → 抽正文 → 文本校验"固化为固定三步。

**F10 无渲染环境的验证缺口**
现象：交互逻辑只有代码层校验，未做浏览器实测。
根因：沙箱无无头浏览器。
处置：用结构自检替代（变量完整性、JS 语法、标签配对），并在交付说明中披露该限制，提醒在本地浏览器点按一遍。
预防：把"点一遍配色切换与打印预览"写进人工复核项。

**F11 目录锚点失效**
现象：点目录无反应或跳错位置。
根因：章节 id 与目录 href 不一致，或 id 重复。
处置：核对 id 与 href 一一对应。
预防：目录由构建器按 sections 自动生成，不手写。

## 四、流程类

**F12 单一来源直接下结论**
现象：关键结论被一条来源带偏。
根因：缺少交叉验证环节。
处置：补第二来源；补不上则标注单一来源。
预防：数据文件里凡 P2 及以下来源，均标级别并在结论处复核。

**F13 版本迭代后旧件仍在外流**
现象：同一成果两个版本同时在传。
根因：更新版入库后未处理旧条目。
处置：隐藏旧条目，交付说明写明当前有效版本。
预防：归档步骤固定"新件入库 + 旧件隐藏"两步。
