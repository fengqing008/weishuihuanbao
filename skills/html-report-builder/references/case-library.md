# 案例库与取材指引（case-library）

## 一、登记规则

本案例库只登记真实交付过的成果，字段留空即标注【待填】，禁止编造项目名、数字与结论。登记一条案例需填全：场景、响应级别、配色、骨架、自检结果、遇到的问题、可复用做法。

## 四、取材指引

需要具体视觉做法时，从既有技能copy思路（不改对方文件）：

- 单文件工程骨架与配色切换：取本技能 `scripts/build_report.py` 生成的页面为基线。
- 社交卡片成组（3:4／21:9）：走 guizang-social-card-skill。
- 杂志化长文版式（双栏、页眉页脚镜像、目次页）：走读者排印坊。
- 正式公文格式（GB/T 9704、标题挂大纲、一键目录）：走 docx-gw-format / contract-format。
- 图表与图引擎（架构图、关系图、思维导图、Mermaid）：走 baoyu-diagram / graphviz / mindmap / pretty-mermaid。
- 信息图与看板（KPI、时间线、漏斗、对比）：走 infographic / infocard。
- HTML 幻灯片：走 frontend-slides。
- 手绘线稿配图：走 qf-lineart。

## 五、常见取材误区

- 把 infographic 的看板当成果页用：看板适合汇报现场，成果页需要来源区块与缺口区块。
- 把 PPT 转出的 HTML 直接当交付件：体积大、结构乱、离线状态下字体与图表易缺失。
- 引用别家技能的配色值却不复校对比度：对方配色为其页面场景调过，换场景需重跑门禁。
