# 结构骨架与章节写法（structure-templates）

## 一、骨架选择

| 判断 | 取用骨架 |
|---|---|
| 交付对象是领导，看完要拍板 | 骨架 B · 汇报页 |
| 对外研究、尽调、投资分析，需回溯证据 | 骨架 C · 研究报告页 |
| 说明书、方案、培训材料、成果归档 | 骨架 A · 通用成果页 |
| 多篇合辑或成书 | 多页装配（见 output-spec 第五节） |

## 二、骨架 A · 通用成果页

适用 L2 级。章节配置：

1. 页头：标题 + 副标题 + 交付对象 + 成文日期
2. 目录（区块 ≥4 时挂载）
3. 结论与核心发现（一句话结论 + 核心发现清单）
4. 主题章节（按内容分 2—6 节）
5. 参考来源
6. 信息缺口与风险（有缺口时挂载）
7. 页脚：数据来源行 + 落款 + 成文日期

数据文件写法：

```json
{
  "title": "某市污水厂运行情况说明",
  "subtitle": "2026 年上半年运行数据与达标情况",
  "audience": "住建局",
  "date": "2026-09-21",
  "theme": "forest",
  "conclusion": "上半年处理量与达标率均达合同约定，电耗高于设计值 6%。",
  "items": ["处理量完成年度计划的 51.3%", "出水达标率 100%", "吨水电耗同比上升 6.2%"],
  "sections": [{"title": "一、运行概况", "html": "<p>...</p>"}],
  "sources": [{"label": "厂区在线监测月报", "level": "P0", "note": "2026 年 1—6 月"}],
  "gaps": [{"item": "缺 6 月污泥外运台账", "impact": "污泥处置成本无法核算到月", "channel": "运营部台账"}],
  "footer": {"unit": "某水务项目公司", "author": "小邦", "note": "厂区在线监测月报（P0）、化验室周报（P0）"}
}
```

## 三、骨架 B · 汇报页

适用 L1 级与需要当场拍板的场合。章节配置：

1. 页头
2. 结论与请求事项（三行以内说完，置顶）
3. 依据与现状（数据带角标）
4. 风险与备选方案（每个方案写代价）
5. 待决策事项清单
6. 页脚

写法要点：结论区不超过一屏；请求事项单独成行并写明期望动作与时限；备选方案不写"优秀/良好"之类的评价词，只写代价与前提。

## 四、骨架 C · 研究报告页

适用 L3 级。章节配置：

1. 页头
2. 目录
3. 执行摘要（核心发现 ≤5 条，每条带来源角标）
4. 数据仪表盘（指标 / 数值 / 同比 / 来源 / 时间）
5. 分维度详述（每维度一节）
6. 观点与争议（各观点标立场与证据强度）
7. 信息缺口与风险
8. 参考来源（全量清单）

写法要点：数据仪表盘用表格而非花哨图形，保证可复制、可打印；观点与争议区块顶部加一句声明"本区块为观点性信息，非事实"；每个维度末尾给一句本维度结论。

## 五、章节写法通则

- 每节首段给结论，再展开依据；不把结论压到节末。
- 表格只用于对比与清单；叙述性内容用段落，不塞进表格。
- 长段落超过 300 字拆段；单条要点不超过 4 行。
- 数字统一千分位并标单位与年份；未核实数据用缺口徽标。
- 标题不超过 25 字；重复出现的机构名首次给全称并定义简称。
- 章节内避免并列结构硬凑对称小标题：事实叙述用连贯段，并列项用分条。

## 六、构建命令

```bash
python3 "$S/scripts/build_report.py" --init --out spec.json
python3 "$S/scripts/build_report.py" --data spec.json --out 成果页.html --theme forest --check
```

生成后按 `references/quality-checklist.md` 逐项过一遍即可交付。
