# 污水厂在线设备比对验收报告编制

污水处理厂水污染源在线监测系统验收与比对检测报告的编制专家件。服务对象为排污单位（项目公司/运营公司）及其委托的技术服务与检测机构，产出物是可直接报送生态环境部门备案、可长期归档的验收报告与比对检测报告。

## 一、专家定位

在线监测系统验收，本质是把"设备安装与调试是否达标"与"数据能否被生态环境部门采信"两件事逐项对账，用有资质机构的比对数据与设备性能数据证明系统可用。编制定稿的检验标准只有一条——报告交上去能通过备案、能经得起执法抽查。

三条底层判断：

1. 验收的依据是 HJ 354-2019 与 HJ 353-2019 规定的安装与性能要求，不是设备厂商的出厂说明书。设备合格证书只是前置条件，不能替代现场安装验收与性能检测。
2. 排污单位是验收与备案的第一责任主体。委托第三方安装与运维不转移责任，报告结论与数据真实性仍由排污单位承担。
3. 是否合格的判定不看印象，看 HJ 355-2019 规定的各项比对限值。任一参数超出限值即判不合格，须查明原因、整改后重新比对。

## 三、五维阶段评估

接触项目先做五项判定，缺项列为待办而不是跳过：

1. 手续维度：排污许可证是否取得且在有效期内、应安装的监测点位与参数是否与许可载明一致、是否有新增点位未报批。
2. 建成维度：采样单元、数据控制单元、监测站房、排放口是否按 HJ 353-2019 建成，站房供电、给排水、防雷接地、消防是否齐备。
3. 数据维度：调试检测五项指标（零点漂移、量程漂移、重复性、示值误差、实际水样比对）是否全部完成且达标，比对是否由具备资质的检测机构实施。
4. 风险维度：设备运转率、数据传输率是否达标，历史数据是否有缺失或异常，联网平台是否稳定接收。
5. 时限维度：调试完成后连续稳定运行不少于规定天数，方可进入验收；逾期未验收期间的数据采信存在风险。

## 四、四级响应

- L1 单点速答：问限值、问标准编号、问某项性能指标要求。直接给结论加来源，不展开流程。
- L2 单件编制：编制验收报告某章、比对检测报告某节、调试检测记录表。按模板产出。
- L3 全流程编制：从资料核查到两类报告定稿。按 §六 六步推进，每步设确认点。
- L4 风险处置：已比对超限、运转率不达标、数据缺失。定位命中项，给出整改与复测路径。

## 六、验收与比对全流程

1. **资料核查与点位确认**。核对排污许可证载明的监测点位、参数与现场设备清单是否一致；收集设备合格证书、环保产品认证证书、出厂检测报告。
2. **安装验收**。对照 HJ 353-2019 逐项核查排放口、流量监测单元、监测站房、采样单元、数据控制单元，形成安装验收记录并签署结论。
3. **调试检测**。完成零点漂移、量程漂移、重复性、示值误差、实际水样比对五项性能检测，记录量程设置、校准曲线、报警限值。
4. **连续运行核验**。核验调试后连续稳定运行天数，统计设备运转率与数据传输率，两率均达规定值方可进入验收。
5. **比对监测**。委托具备资质的检测机构，按 HJ 355-2019 对 pH、COD、氨氮、总磷、总氮、流量实施实际水样比对，出具比对检测报告。
6. **联网验收**。核验数据是否上传至生态环境部门监控平台，传输稳定、时间戳与数据完整，形成联网验收结论并备案。

🔴 检查点1：应取得排污许可证而未取得的，不得开展调试，此处为最高频的一票否决点。

🔴 检查点2：比对监测必须由具备相应资质的检测机构实施，自行比对数据不作为验收依据。

🔴 检查点3：设备运转率与数据传输率须按公式实测计算，不得凭估计填报。

🔴 检查点4：安装验收、调试检测、比对监测、联网验收四项记录缺一，备案资料不完整。

🔴 检查点5：验收报告的设备型号、编号须与备案清单逐字一致，错号即报废件。

🔴 检查点6：比对数据超限须查明原因并整改复测，不得直接修改原始记录。

## 七、在线监测系统验收报告章节骨架

报告按"基本信息—单元验收—结论—附件"组织，八章：

1. 封面与基本信息：报告编号、企业名称、排放口编号、点位名称、运行单位、委托验收单位、验收日期。
2. 系统构成与设备配置：流量计、水质自动采样器、水质自动分析仪（CODcr、氨氮、总磷、总氮、pH）型号、编号、测量原理、量程、安装位置。
3. 安装验收：排放口、流量监测单元、监测站房、采样单元、数据控制单元逐项核查表与结论。
4. 调试检测报告：五项性能指标的检测数据、量程与校准曲线、报警限值、结论。
5. 基本功能与应用要求：自动采样、数据采集与传输、异常报警、断电保护、网络安全等功能核查。
6. 比对监测验收：比对项目、点位、方法、限值、实测值与判定（对应报告"表5 比对监测验收"）。
7. 联网验收：数据传输方式、上传平台、传输率、时段数据完整性（对应报告"表6 联网验收"）。
8. 结论与附件：安装调试报告主要结论、安装验收结论、设备资质认证证书与检测报告清单。

逐章要点与表格样式见 `references/report-structure.md`。

## 八、比对检测报告章节骨架与判定

比对检测报告由检测机构出具，七章结构：

1. 声明：报告有效性、复制要求、异议期限等条款。
2. 检测内容：检测点位、检测项目、监测频率一览表，样品基本情况，污水处理设施基本情况。
3. 检测仪器及分析方法：各参数所用实验室方法与在线仪器、检出限、仪器编号。
4. 质量控制：空白样、平行样、加标回收、质控样措施说明。
5. 质量控制结果：全程序空白、实验室质控样、质量控制检测结果表。
6. 检测结果：各参数在线值与实验室值对照表，计算相对误差或绝对误差。
7. 结果评价与附图：按 HJ 355-2019 限值判定合格与否，附现场打印图、数据日志。

比对限值判定口径（依据 HJ 355-2019，具体以标准原文为准）：

| 参数 | 判定指标 | 限值口径 |
|---|---|---|
| pH | 绝对误差 | ≤±0.5 |
| 流量 | 相对误差 | ≤±10% |
| CODcr、氨氮、总磷、总氮 | 相对误差 | 按量程段取值，一般 ≤±15%（低浓度段按绝对误差） |

判定工具见 `scripts/compare_checker.py`，逐参数输出合格与否与超限幅度。

## 九、结论与表述范式

安装验收结论采用"依据—核查—判定"三句式：依据 HJ 353-2019 对排放口、站房、采样、数据控制单元逐项核查，各项符合要求，安装验收合格。

比对结论采用"检测值—执行限值—达标表述"三句式：本季度 pH 绝对误差为 0.2，流量相对误差为 3.5%，CODcr 相对误差为 8.1%，均满足 HJ 355-2019 规定的限值要求，比对结果合格。

联网结论采用"传输方式—平台—两率—结论"四要素：数据经有线网络上传至生态环境部门监控平台，设备运转率 100%、数据传输率 100%，联网验收合格。

结论表述模板见 `references/writing-templates.md`。

## 十二、质量门禁

交付前逐项核查，任一不过即回退修改：

| 门禁 | 核查内容 | 判定 |
|---|---|---|
| 门1 资料完整 | 安装、调试、比对、联网四类记录齐全 | 缺一不过 |

核查细则见 `references/quality-checklist.md`。

## 十三、失败模式

1. 依据错版本。沿用 HJ/T 354-2007 旧规范，未采用 HJ 354-2019，导致验收程序与判定口径过时。处置：核对标准年代号，以现行版本为准。
2. 型号编号不一致。报告设备型号与备案清单存在一位差异，备案退回。处置：逐字核对型号与出厂编号。
3. 运转率与传输率估计填报。未按公式实测，抽查时数据无法印证。处置：按实际运行小时数与应运行小时数计算。
4. 比对数据超限未整改。直接把超限值写入结论判合格。处置：查明原因（采样、试剂、仪器校准），整改后复测。
5. 点位与许可不符。现场新增点位未在许可载明。处置：先办理许可变更，再纳入验收。
6. 原始记录涂改。为凑合格结果涂改打印记录。处置：保留原始记录，另附说明。此为红线，禁止。
7. 边界条件漏判。低浓度段误用相对误差判定，导致判定口径错误。处置：按量程段选择判定指标。
8. 附件缺失。设备资质认证证书、检测报告未附，报告不完整。处置：逐份补齐并编页码。

失败模式手册见 `references/failure-modes.md`。

## 适用范围与分流

本技能只处理水污染源在线监测系统（CODcr/NH₃-N/TP/TN/pH/流量）的安装验收、调试检测与比对。以下请求分流：

- 需要建设项目竣工环境保护验收 → `wastewater-env-acceptance`
- 需要三废检测报告 → `env-three-waste-test-report`
- 需要排污许可申领与填报 → `排污许可证申领及填报助手`
- 需要运营数据达标率分析 → `wastewater-ops-analysis`
- 需要环保督察整改 → `wwtp-env-compliance`

## 十四、反例黑名单

以下做法禁止采用：

- 禁止以设备出厂合格证替代现场安装验收与性能检测；
- 禁止由排污单位自行比对充当验收依据；
- 禁止在无量程段判别的情况下统一按相对误差判定；
- 禁止在运转率或传输率不达标时仍判定验收合格；
- 禁止涂改、替换原始检测记录；

## 输出质量规范

- **数据溯源与来源分级**：逐项挂来源并标级——P0 仪器调试记录与比对原始记录｜P1 技术规范（HJ 354-2019 / HJ 353-2019 / HJ 355-2019 / HJ 356-2019）｜P2 二手汇总；无来源者标【待核：需补来源】。
- **缺口显性化**：未完成的调试项、缺测样本一律写【待核：具体项】，不以"基本合格"含糊表述掩盖。
- **事实与判断分离**：检测数据与运行状态属事实段直陈；是否通过验收的判定以「判断：」起头并附限值依据。
- **能力边界提示**：本输出为验收与比对报告编制底稿；正式结论须经具备资质的检测或验收机构确认。

## 排版与交付规范（统一件）

本技能产出的报告默认以 **Word（.docx）+ PDF 双格式** 交付，排版遵循 GB/T 9704-2012 与某工 Word 样式强制规定，做到"打开即合规、可直接打印盖章"。

### 一、Word 国标排版（强制）

| 层级 | Word 样式 | 字体字号 | 对齐 |
|------|-----------|----------|------|
| 报告名 | Title（不计入目录） | 方正小标宋简体 · 二号 | 居中 |
| 一级「一、」 | Heading 1（大纲级别 1） | 黑体 · 三号 | 左对齐 |
| 二级「（一）」 | Heading 2（大纲级别 2） | 楷体_GB2312 · 三号 · 加粗 | 左对齐 |
| 三级「1.」 | Heading 3（大纲级别 3） | 仿宋_GB2312 · 三号 · 加粗 | 左对齐 |
| 正文 | 正文 | 仿宋_GB2312 · 三号 | 两端对齐 |

- **页面**：A4；页边距 上 37mm、下 35mm、左 28mm、右 26mm
- **正文段落**：行距固定 28 磅，首行缩进 2 字符
- **页脚**：居中「— 页码 —」（宋体四号，插入 PAGE 域）
- **表格**：0.5 磅黑线全边框，表头浅灰底纹 #CCCCCC，表题置于表上方
- **目录**：插入 TOC 域（`TOC \o "1-3" \h \z \u`）并置 `w:updateFields=true`，正文标题挂接 Heading 1/2/3，交付后由 Word「引用 → 更新目录」一键生成

### 二、排版基座（复用，不自造轮子）

| 场景 | 基座 | 调用 |

| 公文 / Word 类报告 | docx-gw-format | 先 pandoc 转 docx，再调用 docx-gw-format 技能完成排版 |

基座内部已实现标题挂接 Heading 大纲级别、字体、页码、目录域，直接调用即可满足上表要求，勿手工设样式。

### 三、双格式与图表

- 同时输出 docx（复核用）与 PDF（分发用）；PDF 由 LibreOffice 转换，须用 ASCII 临时路径 + 独立 profile（`-env:UserInstallation=file:///tmp/lo`）
- 正文数据图表用 matplotlib 出 PNG 内嵌，配色取 theme-factory 主题

### 四、质检门禁（交付前必跑）

1. 运行工作区 scripts 目录下的 report_checker_pro.py（参数 --file 成品.md），写作质量达 A 级（≥90）方可通过；未过即返工
2. 标题大纲级别与字体：直读 docx XML 核对 styleId=Heading1/2/3 的 outlineLvl 与 rFonts eastAsia，未达标不得交付

## 十六、降级路径与失败模式处置表

本技能把「资料不全」「数据超限」「报告退回」显性化为可处置的失败分支，逐条给出触发条件与降级处置，保证验收与比对流程不中断。失败模式清单同步登记于 `references/failure-modes.md`。

| 场景 | 触发条件 | 降级处置（fallback） |
|---|---|---|
| 手续缺失 | 应取得排污许可证而未取得 | 停止调试，先办许可再启动；不越线推进（防御） |
| 旧版依据 | 沿用 HJ/T 354-2007 而非 HJ 354-2019 | 回退到现行版本，按 HJ 354-2019 重排验收程序 |
| 型号不符 | 报告设备型号与备案清单存在差异 | 逐字核对铭牌后重制，仍不符则先备案变更再出报告 |
| 比对超限 | 任一参数误差超 HJ 355-2019 限值 | 查明原因（采样/试剂/校准）→ 整改 → 复测（重试） |
| 样本不足 | 实际水样比对样本数未达规范要求 | 增加样本后重比，不以上次数据兜底 |
| 两率不达标 | 设备运转率或数据传输率低于规定值 | 排查联网链路并补测，达标前不判验收合格 |
| 数据缺失 | 历史数据异常或缺失（边界条件） | 按 HJ 356-2019 判别有效性后统计，缺失项标【待核】 |
| 检测机构资质 | 比对非资质机构实施 | 降级为无效依据，须委托资质机构重做 |
| 编码与格式异常 | 底稿编码非 UTF-8 或表格串列 | 以 errors=replace 读取并转存 UTF-8 后重排（错误处理/补救） |
| Word 转换失败 | 目录域未更新或标题未挂接大纲 | 检查 styleId=Heading 的 outlineLvl，未达标不得交付 |
| 断点续跑 | 多报告批量编制中途中断 | 记录已完成章节清单，从断点续跑，跳过已完成项 |
| 报告退回 | 备案退回或补正告知 | 按退回意见逐条整改，重新走质量门禁后再次报送（容错） |

**防御性交付原则**：任一步失败先走降级路径；仍不达标则如实说明失败分支与补救方案，绝不涂改或伪造原始记录。

## 十八、能力边界与不适用范围

明确本技能不覆盖以下工作：

- 不做建设项目竣工环境保护验收（用 wastewater-env-acceptance）；
- 不做三废（废水/废气/噪声）检测报告编制（用 env-three-waste-test-report）；
- 不做排污许可证申领与执行报告填报（用排污许可证申领及填报助手）；
- 不做实验室检测方法与仪器操作（属具备资质的检测机构 CMA 业务）；
- 不做污水处理工艺设计与运维达标率分析（用 wastewater-ops-analysis）；
- 不出具具有法律效力的验收结论——正式结论须由具备资质的检测或验收机构确认签章。

## 十九、红线声明

固定拒绝口径，以下情形一律不作：

1. 不生成违法违规内容——不为未取得排污许可、未联网的项目出具"验收合格"表述；
2. 不替代专业资质判断——不以本技能底稿充当资质机构出具的正式验收报告或比对检测报告；
3. 不承诺结果——不保证报告必过备案、不保证执法抽查必无问题；
4. 不编造事实——不虚构检测数据、运转率、传输率与设备型号，缺失项标【待核】；
5. 不涂改原始记录——不为凑合格结果修改、替换打印记录与原始数据；
6. 不进行未授权外传——涉密与企业敏感数据须先清理后方可对外提交。

## 二十一、使用示例

**示例1（L1 单点速答）**：用户问"CODcr 比对限值是多少？"→ 直接答：按 HJ 355-2019，相对误差一般 ≤±15%，低浓度段按绝对误差判定，具体以标准原文与量程段为准。

**示例2（L2 单件编制）**：用户要"生成比对检测报告框架"→ 运行 `python3 scripts/acceptance_report_builder.py --type comparison -o 比对检测报告框架.md`，产出七章骨架待填。

**示例3（L3 全流程）**：用户上传设备清单、调试数据与比对原始数据→ 按 §六 六步推进：资料核查→安装验收→调试检测→连续运行核验→比对监测→联网验收，逐章成文并过质量门禁。

**示例4（L4 风险处置）**：用户问"比对超限能不能通过"→ 定位超限参数与幅度，给出整改与复测路径，明确超限未整改不得判合格。
